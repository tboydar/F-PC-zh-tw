CHAPTER 2.   THE F-PC KERNEL

 

 

 

 

 

There has not been a generally accepted definition of what is the Forth kernel, as people are still fighting over the more fundamental question on what is Forth.  A practical definition of Forth kernel is the collection of words which are written in machine code, from which a complete, operating Forth can be built in high level without more low level code words.  F83 collected all word definitions leading to Forth text interpreter and colon word compiler in a file KERNEL86.BLK.  This is also a good practical definition of a Forth kernel. 

 

F-PC, with all the enhancements over F83, has a much bigger kernel.  The code needed to build a minimal kernel system is split into four files: KERNEL1.SEQ to KERNEL4.SEQ, with a few other utility files.  Many high level words are also recoded in assembly code to improve its speed.  The above definitions of a Forth kernel are not suitable to F-PC.  What we call the F-PC Kernel is the word set which manipulates data in memory and on the stacks; and the data/control structures in colon definitions.  Words to implement the text interpreter, compiler, and files are separated to form chapters of their own.  In this chapter, we are thus restricting ourselves to the lowest layer of Forth words in the second half of KERNEL1.SEQ file.  With only very rare exceptions, they are all code words and are excellent examples of assembly programming in F-PC.

 

Most of the code words are identical to those defined in F83.  Changes are made when performance can be improved or when the segmented architecture in F-PC dictates modification.  A major improvement is that the assembly code is written in the prefix style, which is very close to the Intel MASM syntax.  It is quite different from the postfix style used in F83 and most other Forth systems.  The entire F-PC is written in the prefix style to encourage users to adopt it in future programming efforts.

 

 

2.1.    THE STACK WORDS

 

 

F-PC, as all other Forth systems, uses two stacks: the return stack for passing subroutine return addresses and the data stack for passing data or parameters between words or subroutines.  In F-PC both stacks are located in the data segment, because the SS segment register contains the same segment address as the CS and DS registers.  The regular stack pointer SP in the 8088/86 is used as the pointer for the data stack, and the BP register is used to point to the top of the return stack.  Consequently, the assembler instructions PUSH and POP are used to move data between CPU registers and the data stack.  To get data to/from the return stack, F-PC uses two methods: the BP relative mode and PUSH/POP after swapping BP with SP.  Either has its advantages and disadvantage.

 

In the stack words, input data are popped into registers AX, BX, CX, and DX.  If there are output data, the first item is left in AX and 1PUSH is invoked instead of NEXT.  The second item can be left in DX and the code word is terminated by 2PUSH, which first pushes DX and then AX on the data stack before executing NEXT.  If more than two items are generated or they are in registers other than DX and AX, they can be pushed on to the data stack by explicit PUSH instructions.

 

Since AX and DX can be pushed using 1PUSH and 2PUSH, code words are often defined so that output data are left in them at the end of a code word.  The BX register is very useful in moving data in and out of the memory.  Addresses are generally popped into the BX register and the BX relative MOV instruction can be used to read or write the memory in the code/data segment.  8088/86 processors use the CX register to store counts for various repeated instructions and LOOP instructions.  Counts are popped into CX.

 

NEXT in F-PC leaves the code field address of the word currently being executed in the AX register.  The body or parameter field of a word is 3 bytes from this code field address.  If you need this information, you can pick it up in the AX register.  However, most code words do not need this information and the AX register can be used freely.  Other free registers are BX, CX, DX, and DI.  The registers SI, BP, SP, and all four segment registers CS, DS, SS, and ES contain vital system information, and must be saved and restored before NEXT if they are modified.

 

All the definitions of stack words are listed in this section.  They are good examples to learn how either stack is addressed and how data are moved among the stacks, memory and the CPU registers.

 

DROP        Discard the top element of the data stack.

 

CODE DROP   ( n -- )

    ADD SP, # 2       

    NEXT           

    END-CODE

 

DUP     Duplicate the top element of the data stack.

 

CODE DUP    ( n -- n n )

    POP AX         

    PUSH AX

    1PUSH          

    END-CODE

 

SWAP    Exchange the top two elements on the data stack.

 

CODE SWAP   ( n1 n2 -- n2 n1 )

    POP DX         

    POP AX

    2PUSH          

    END-CODE

 

OVER        Push a copy of the second stack item.

CODE OVER   ( n1 n2 -- n1 n2 n1 )

    XCHG RP, SP

    MOV AX, 2 [RP]

    XCHG RP, SP

    1PUSH          

    END-CODE

 

PLUCK   Copy the third stack item to the top.

 

CODE PLUCK ( n1 n2 n3 -- n1 n2 n3 n1 )

    MOV DI, SP

    PUSH 4 [DI]

    NEXT

    END-CODE

 

TUCK        Tuck the first stack item under the second one. 

 

CODE TUCK   ( n1 n2 -- n2 n1 n2 )

    POP AX         

    POP DX

    PUSH AX        

    2PUSH          

    END-CODE

 

NIP     Discard the second stack item.

 

CODE NIP    ( n1 n2 -- n2 )

    POP AX         

    ADD SP, # 2

    1PUSH          

    END-CODE

 

ROT     Rotate the top three stack items, bringing the third to the top.

 

CODE ROT    ( n1 n2 n3 -- n2 n3 n1 )

    POP DX         

    POP BX         

    POP AX

    PUSH BX        

    2PUSH          

    END-CODE

 

-ROT        The inverse of ROT.  Rotate the top stack item to third place.

 

CODE -ROT   ( n1 n2 n3 --- n3 n1 n2 )

    POP BX         

    POP AX         

    POP DX

    PUSH BX        

    2PUSH          

    END-CODE

 

FLIP        Exchange the high and low bytes of the 16 bit integer on the top of data stack.

 

CODE FLIP   ( n1 -- n2 )

    POP AX         

    XCHG AL, AH

    1PUSH          

    END-CODE

 

SPLIT   Splits n1 into two byte values: n2 low, and n3 high.

 

CODE SPLIT  ( n1 -- n2 n3 )

    POP BX

    SUB AX, AX

    MOV AL, BL

    PUSH AX

    MOV AL, BH

    1PUSH

    END-CODE

 

JOIN        Join two bytes into one word.

 

CODE    JOIN    ( low-byte high-byte -- n )

    POP DX

    POP AX

    MOV AH, DL

    1PUSH

    END-CODE

 

?DUP        Duplicate the top of the stack only if it is non-zero.  This is most often used before IF so that you don't have to discard the 0 flag in the false clause.

 

CODE ?DUP   ( n1 -- n1 n1 | 0 )

    POP AX         

    CMP AX, # 0

    0<> IF

        PUSH AX

    THEN

    1PUSH                       \ 33 cycles

    END-CODE

 

?DROP       If the first stack item is zero, discard the top two items; otherwise no change.

 

CODE ?DROP ( n false -- | n true -- n true )

    POP AX

    OR AX, AX

    0= IF   INC SP

        INC SP

    THEN

    1PUSH

    END-CODE

 

R>      Pop an item off of the return stack and push it onto the data stack.  As the return stack contains addresses of words which are yet to be executed, it is dangerous to mess it up.  All words operating on the return stack are dangerous and can cause the system to crash.  This is why all other languages and operating systems must hide the return stack from the user.  Forth does not take away from you this privilege.  It also expects you to use this privilege wisely. 

 

CODE R> ( -- n )

    PUSH 0 [RP] 

    ADD RP, # 2

    END-CODE

 

R>DROP  Drop an item from the return stack.

 

CODE R>DROP ( -- )

    ADD RP, # 2

    NEXT

    END-CODE

 

DUP>R   Push a copy of the top item on the data stack to the return stack.

 

CODE DUP>R      ( n -- n )

    XCHG SP, RP         \ Faster than moving things through a register.

    PUSH 0 [RP]

    XCHG SP, RP

    NEXT                \ 29 cycles

    END-CODE

 

>R      Pop the top the data stack and push it on the return stack.  It is generally used to save the top item on the data stack temporarily.  This item must be restored to the data stack by R>.  >R and R> must be used as a pair.  If they do not occur as a pair in a colon definition, you can expect potential problems.  Used effectively, they are powerful tools to change and manipulate execution sequences.

 

CODE >R ( n -- )

    SUB RP, # 2

    POP 0 [RP]

    NEXT                        \ 26 cycles

    END-CODE

 

R@      Push a copy of top item on the return stack to the data stack.  The state of the return stack is not disturbed.  It is very convenient to push a number on the return stack and use R@ to get many copies of this number in a colon definition.  However, you have to remove it before exiting the colon definition.  Otherwise, the system will certainly crash because the F-PC system would interpret this number as a return address.

 

CODE R@ ( -- n )

    PUSH 0 [RP]

    END-CODE

 

2R>     Pop two items off the return stack and push them on the data stack.  This word is required in F-PC because F-PC saves the return address as an ES:IP register pair.  To move return addresses from or to the return stack, you should move the register pair.

 

CODE 2R>    ( -- d )

    PUSH 2 [RP]

    PUSH 0 [RP]

    ADD RP, # 4

    NEXT                        \ 50 cycles

    END-CODE

 

2>R     Pop two integers off the data stack and push them on the return stack.  It is used to move an ES:IP register pair from the data stack to the return stack.  Used for this purpose, the ES register should be on the top of the data stack.

 

CODE 2>R    ( d -- )

    SUB RP, # 4

    POP 0 [RP]

    POP 2 [RP]

    NEXT                        \ 52 cycles

    END-CODE

 

2R@     Replicate the top two items on the return stack to the data stack.  Similar to 2R> except the return stack is not disturbed.

 

CODE 2R@    ( -- d )

    PUSH 2 [RP]

    PUSH 0 [RP]

    NEXT

    END-CODE

 

PICK        Reach into the data stack and grab an element, copying it to the top of the stack.  For example, if the stack has 1 2 3, then 0 PICK returns 3, 1 PICK returns 2, and 2 PICK returns 1.

 

CODE PICK   ( nm ... n2 n1 k -- nm ... n2 n1 nk )

    POP DI         

    SHL DI, # 1    

    ADD DI, SP

    PUSH 0 [DI]

    NEXT

    END-CODE

 

RPICK   Reach into the return stack and grab the n1'th item, copying it to the top of the data stack. 

 

CODE RPICK  ( n1 -- n2 )

    POP DI         

    SHL DI, # 1    

    PUSH 0 [RP+DI]

    NEXT

    END-CODE

 

ROLL        Similar to PICK, except that the chosen item is moved (copied and then deleted) rather than copied.  1 ROLL is SWAP, 2 ROLL is ROT, etc.  ROLL can be useful, but it is slow, and so should be avoided.  It is hard to define in code.

 

: ROLL  ( n1 n2 .. nk n -- nk n1 n2 .. nk-1 )

    >R R@ PICK

    SP@ DUP 2+

    R> 1+ 2* CMOVE>

    DROP ;

 

2ROT        Rotate the top three double numbers, bringing the deepest pair to the top.

 

: 2ROT      ( a b c d e f -- c d e f a b )

    5 ROLL          \ This is where ROLL is handy

    5 ROLL

    ;

 

SP@     Push the address of the top item (prior to the push) on the data stack.

 

CODE SP@    ( -- addr )

    MOV AX, SP     

    1PUSH          

    END-CODE

 

SP!     Set the data stack pointer to the specified value.  It is only used to initialize the data stack by ABORT, and not meant to be used by user.

 

CODE SP!    ( addr -- )

    POP SP         

    NEXT           

    END-CODE

 

RP@     Push the address of the top item on the return stack to the data stack.  In F-PC, the RP or BP register is used as the return stack pointer, keeping track of the ES:IP pairs of words which are yet to be executed.

 

CODE RP@    ( -- addr )

    PUSH RP

    NEXT

    END-CODE

 

RP!     Set the return stack pointer to the specified address.  This is used by the system to initialize the return stack.  It is not meant to be used by the user.

 

CODE RP!    ( addr -- )

    POP RP         

    NEXT           

    END-CODE

 

 

2.2.      ARITHMETIC AND LOGIC WORDS

 

 

F-PC is a 16 bit Forth implementation.  All numbers and addresses, if not otherwise specified, are assumed to be 16 bit integers.  32 bit double numbers are allowed, but the double integer operations are all based upon 16 bit operations.  They are discussed in the section on double integers.  This word set is almost identical to that in F83, except that more words are coded in assembly to increase the speed of F-PC.

 

8088/86 processors have a fairly strong arithmetic and logic instruction set for 16 bit integers.  These operations use numbers stored in registers.  To build Forth operations from these machine instructions, integers must be popped off the data stack and put into appropriate registers.  Operations are then performed in the registers.  The final results are then pushed back onto the data stack.  The efficiency of the virtual Forth machine is degraded because of the data shuffling between the stack and the CPU registers.  F-PC runs much faster than F83 because more words are coded in assembly and more data are kept in CPU registers longer.  The overhead in data shuffling is considerably reduced.

 

Arithmetic and logic operations can be classified according to the number of input and output items.  A Unary Operator takes one integer as input and generates one integer as output.  It includes operators like ABS, NEGATE, NOT, 1+, 2+, 1-, 2*, 2/, U2/, etc.  Binary Operators are most prevalent, with two input integers and one output integer.  AND, OR, XOR, +, -, *, and / belong to this group.  Other operators may involve more than two inputs and one output.  Many of these complex operators are defined in F-PC, over and above those required by Forth-83 Standards.  Most of them are defined as code words in F-PC to optimize the system performance.

 

AND     Return the bitwise AND of n1 and n2 on the data stack.

 

CODE AND    ( n1 n2 -- n3 )

    POP BX

    POP AX 

    AND AX, BX

    1PUSH   

    END-CODE

 

OR      Return the bitwise OR of n1 and n2 on the stack.

 

CODE OR ( n1 n2 -- n3 )

    POP BX

    POP AX   

    OR AX, BX

    1PUSH

    END-CODE

 

XOR     Return the bitwise Exclusive OR of n1 and n2 on the stack.

 

CODE XOR    ( n1 n2 -- n3 )

    POP BX

    POP AX

    XOR AX, BX

    1PUSH

    END-CODE

 

NOT     Do an one's complement of the top item on the data stack.  Equivalent to -1 XOR.  It is a bitwise logic complement operation.  If the flag were 0=false or -1=true, then NOT could be used to complement the flag.  But in Forth, the flag is 0=false and (not 0)=true.  So in a general case, 0 NOT is -1 (=true); but 3 is true, and 3 NOT is -4, which is still true.  To complement a flag, use the comparison word 0=.

 

CODE NOT    ( n -- n' )

    POP AX

    NOT AX

    PUSH 

    END-CODE

 

Many small integers are used very often in Forth and they deserve separate word definitions instead of being compiled as literals which take more space in colon definitions.  TRUE is a number with all 16 bits set and FALSE is one with all bit cleared.  They are useful constants to make logical intentions clearer in the source code.   0 through 3 have previously been defined as constants.  However, F-PC is very efficient in its literal structure.  A literal is about three times faster than a constant.  Since this discovery, 0 through 3 are no longer included as constants.

 

-1 CONSTANT TRUE

 0 CONSTANT FALSE

 

+       Add the top two numbers on the stack and return the sum.

 

CODE +      ( n1 n2 -- sum )

    POP BX

    POP AX

    ADD AX, BX

    1PUSH

    END-CODE

 

NEGATE  Turn a number into its negative.  A two's complement operation.

 

CODE NEGATE ( n -- n' )

    POP AX

    NEG AX

    1PUSH

    END-CODE

 

-       Subtract n2 from n1 and leave the difference on the stack.

 

CODE -  ( n1 n2 -- n1-n2 )

    POP BX

    POP AX

    SUB AX, BX

    1PUSH

    END-CODE

 

ABS     Return the absolute value of the 16 bit integer on the stack.

 

CODE ABS    ( n -- u )

    POP AX

    OR AX, AX

    0< IF

        NEG AX

    THEN

    1PUSH

    END-CODE

 

UM*     Unsigned Mixed Multiply.  Multiply top two unsigned items on the data stack and return an unsigned double integer product.

 

CODE UM*    ( u1 u2 -- ud )

    POP AX          \ Get u1

    POP BX          \ Get u2

    MUL BX          \ u1*u2

    XCHG DX, AX         \ Re-ordering parts

    2PUSH           \ Push double integer product

    END-CODE

 

*       Multiply top two signed integers on the data stack and return a 16 bit signed integer product.

 

CODE *      ( n1 n2 -- n3 )

    POP AX

    POP BX

    MUL BX          \ n1*n2

    1PUSH               \ Save only the LS 16 bits of the product

    END-CODE

 

U*D         Synonym for UM* .

 

: U*D       ( u1 u2 -- ud )

    UM*   ;

 

UM/MOD  Unsigned Mixed Modulo.  This is the division primitive in Forth.  All other division operations are derived from it.  It takes an unsigned double integer ud, and divides it by an unsigned integer u1.  It leaves an unsigned remainder and an unsigned quotient on the stack.

 

CODE UM/MOD ( ud u1 -- Remainder Quotient )

    POP BX          \ u1

    POP DX          \ MS of ud

    POP AX          \ LS of ud

    CMP DX, BX

    U>=                 \ Test for overflow

    IF              \ If overflow

        MOV AX, # -1        \ return two -1's

        MOV DX, AX

        2PUSH

    THEN

    DIV BX          \ Unsigned divide

    2PUSH               \ Push rem and quot

    END-CODE

 

*D          Multiply two signed integers and leave a signed double integer product.

 

CODE *D     ( n1 n2 -- d )

    POP CX

    POP AX

    IMUL CX         \ Unsigned multiplication

    PUSH AX

    PUSH DX

    NEXT

    END-CODE

 

M/MOD   Divide a signed double integer by a signed integer, leaving a single integer quotient and a single integer remainder.  Division is floored towards minus infinity.

 

: M/MOD ( d n -- rem quot )

    ?DUP                \ Return d if n=0

    IF  DUP>R  2DUP XOR >R      \ Save n and sign

        >R DABS R@ ABS 

        UM/MOD      \ Do unsigned multiply

        SWAP R> ?NEGATE \ restore sign of remainder

        SWAP R> 0<      \ Handle negative quotient

        IF  NEGATE OVER \ Negate quotient

            IF      1- R@ ROT -

                SWAP  \ Correct remainder and floor it towards -infinity

            THEN

        THEN    R>DROP

    THEN  ;

 

MU/MOD  Divide an unsigned double integer by an unsigned integer, leaving a double integer quotient and a single integer remainder. 

 

: MU/MOD    ( ud u -- rem dquot )

    >R  0  R@           \ Make MS of d a double

    UM/MOD              \ Divide it by n   

    R>  SWAP >R         \ Save MS of quotient

    UM/MOD  R>          \ Divide LS of d and return MS of quotient

    ;

 

/       Divide second item on stack by the top item.  Return the quotient only.  Division is floored towards minus infinity.

 

CODE /  ( numerator denominator -- quotient )

    POP BX

    POP AX

    CWD             \ Extend numerator

    MOV CX, BX 

        XOR CX, DX          \ Test sign of quotient

    0>= IF                          \ For positive quotient  

        IDIV BX     \  do signed divide.

        1PUSH

    THEN

    IDIV BX             \ For negative quotient

    OR DX, DX

    0<> IF

        DEC AX      \ Floor it towards -infinity

    THEN

    1PUSH

    END-CODE

 

/MOD        Divide the top item by the second item like /.  Return the quotient on top with the remainder under it.  The division is floored.  Quotient and remainder have the same sign as the numerator.

 

CODE /MOD   ( num denom -- rem quot )

    POP BX

    POP AX

    CWD

    MOV CX, BX

    XOR CX, DX

    0>= IF              \ Same treatment for quotient as in /

        IDIV BX

        2PUSH

    THEN

    IDIV BX

    OR DX, DX

    0<> IF

        ADD DX, BX      \ Floor the remainder

        DEC AX      \ Floor the quotient

    THEN

    2PUSH

    END-CODE

 

MOD     Similar to /MOD, but return only the remainder.

 

: MOD       ( n1 n2 -- rem )

    /MOD  DROP  ;

 

*/MOD  Multiply n1 with n2 and divide the product by n3.  Return both the quotient and the remainder.  The intermediate product is a double integer to preserve the precision.  This is a very important operation to do scaling; i.e., n1 is multiplied by the ratio of n2/n3.  It allows high precision scaling without using floating point representation.

 

CODE */MOD  ( n1 n2 n3 -- rem quot )

    POP BX

    POP AX

    POP CX

    IMUL CX         \ n1*n2

    MOV CX, BX

    XOR CX, DX

    0>= IF              \ Positive quotient

        IDIV BX     \ (n1*n2)/n3

        2PUSH

    THEN

    IDIV BX             \ Negative quotient

    OR DX, DX

    0<> I

        ADD DX, BX      \ Floor remainder

        DEC AX      \ Floor quotient

    THEN

    2PUSH               \ Push rem and quot

    END-CODE

 

*/        Multiply n1 by the ratio of  n2/n3.  The intermediate result is kept to full accuracy of 32 bits.  Notice that this is not the same as * followed by /.  It is a particularly useful operator, as it allows you to do accurate arithmetic on fractional quantities.  See Leo Brodie's "Starting Forth" for more examples.

 

: */        ( n1 n2 n3 -- n1*n2/n3 )

    */MOD

     NIP  ;             \ Discard remainder

 

2*      Double the number on the data stack.  Doing an arithmetic left shift is much faster than doing a multiplication by 2.

 

CODE 2* ( n -- 2*n )

    POP AX

    SHL AX, # 1

    PUSH

    ND-CODE

 

2/      Shift the number on the stack right one bit.  Equivalent to division by 2.

 

CODE 2/     ( n -- n/2 )

    POP AX

    SAR AX, # 1         \ Arithmetic right shift

    1PUSH           \ Sign is preserved

    END-CODE

 

U2/     16 bit logical right shift.

 

CODE U2/    ( u -- u/2 )

    POP AX

    SHR AX, # 1         \ Logic right shift

    1PUSH               \ Sign bit is cleared

    END-CODE

 

U/16        Divide top unsigned integer by 16.  This is needed in converting an address to a segment address.

 

CODE U16/   ( u -- u/16 )

    POP AX

    SHR AX, # 1

        SHR AX, # 1

    SHR AX, # 1

        SHR AX, # 1

    1PUSH

    END-CODE

 

U/8     Divide top unsigned integer by 8.

 

CODE U16/   ( u -- u/16 )

    POP AX

        SHR AX, # 1

    SHR AX, # 1

    1PUSH

    END-CODE

 

8*      Multiply the top of the stack by 8.

 

CODE 8* ( n -- 8*n )

    POP AX

    SHL AX, # 1

    SHL AX, # 1

        SHL AX, # 1

    1PUSH

    END-CODE

2.3.      MEMORY WORDS

 

 

Memory words move data from data stack to memory, from memory to stack, and from memory to memory.  In F-PC, all memory operations assume that the data are in the Code/Data Segment to maintain compatibility with F83.

 

The address for memory reference is generally popped into the BX register.  Data are then fetched or stored using the BX relative mode.  The relative offset from BX is in most cases 0.  The BX relative mode of addressing assumes the use of DS segment register.  Since in F-PC the DS register is always aligned with the CS register, all addresses thus generated are restricted to the Code Segment.

 

Memory store words are often dangerous if data is stored into the wrong places in the dictionary, outside of declared areas for variables or arrays.  Forth trusts that the user will make the best use of this capability.

 

Some Forth programmers prefer to avoid @ and ! by using VALUE's, which are discussed in Sec. 6.2.

 

@       Fetch a 16 bit value from addr.

 

CODE @  ( addr -- n )

    POP BX

    PUSH 0 [BX]

    NEXT

    END-CODE

 

!       Store a 16 bit value to addr.

   

CODE !      ( n addr -- )

    POP BX

    POP 0 [BX]

    NEXT

    END-CODE

 

C@      Fetch an 8 bit value from addr.  Fill high byte with zero.

 

CODE C@ ( addr -- char )

    POP BX

    SUB AX, AX

    MOV AL, 0 [BX]

    1PUSH

    END-CODE

 

C!      Store the least significant 8 bits of char to addr.

 

CODE C! ( char addr -- )

    POP BX

    POP AX

    MOV 0 [BX], AL

    NEXT

    END-CODE

 

CMOVE   Move a set of bytes from source-addr to dest-addr.  The number of bytes to be moved is count.  The bytes are moved from low address to high address, so overlap is possible and in fact sometimes desired.  To move a range of data, we use the interesting 8088/86 instruction REPZ MOVSB which moves a byte pointed to by DS:SI to a destination pointed to by ES:DI.  Both SI and DI are incremented while CX is decremented.  The moving continues until CX is decremented to zero.  The direction flag, ES, DS, SI, DI and CX registers must be initialized properly before the block move and restored afterwards.  SI is renamed as IP in F-PC.

 

CODE CMOVE  (  source dest count -- )

    MOV BX, IP          \ Save IP

    MOV AX, DS          \ Copy DS for setting ES

    POP CX          \ Count

    POP DI          \ Destination address

    POP IP              \ Source address, SI

    MOV DX, ES          \ Save ES

    MOV ES, AX          \ Point ES to code segment

    REPNZ           \ Repeat until count is zero

    MOVSB           \ Copy DS:SI to ES:DI

    MOV IP, BX          \ Restore IP of SI

    MOV ES, DX          \ Restore ES

    NEXT                \ Done

    END-CODE

 

CMOVE>  The same as CMOVE above except that bytes are moved in the opposite direction, i.e., from high addresses to low addresses.  SI and DI must be initialize to point to the end of the source and destination string, and the direction flag must be set so that addresses are decremented during moving.

 

CODE CMOVE> ( source dest count -- )

    MOV BX, IP          \ Save IP or SI

    MOV AX, DS          \ Copy DS

    POP CX          \ Count

    DEC CX          \ Make a small correction

    POP DI          \ Destination

    POP IP              \ Source

    ADD DI, CX          \ End of destination string

    ADD IP, CX          \ End of source string

    INC CX          \ The right count

    MOV DX, ES          \ Save ES

    MOV ES, AX          \ Point ES to code segment

    STD             \ Reverse direction of copying

    REPNZ           \ Repeat

    MOVSB           \   string move

    CLD             \ Restore move direction

    MOV IP, BX          \ Restore IP

    MOV ES, DX          \ Restore ES

    NEXT                \ All done

    END-CODE

 

PLACE   Copy n bytes of data from source-addr to dest-addr and lay it down as a counted string. 

 

CODE PLACE  ( source-addr n dest-addr -- )

    POP DI          \ Destination

    POP CX          \ Length

    MOV 0 [DI], CL      \ Copy the length byte

    INC DI          \ First byte of dest string

    CLD             \ Now do CMOVE

    MOV BX, IP

    POP IP

    MOV DX, ES

    MOV AX, DS

    MOV ES, AX

    REPNZ

    MOVSB

    MOV IP, BX

    MOV ES, DX

    NEXT

    END-CODE

 

CSET        Set the contents of a character (byte) at addr so that the bits that are 1 in b are also 1 in addr.  Equivalent to DUP C@ ROT OR SWAP C!

 

CODE CSET   ( b addr -- )

    POP BX

    POP AX

    OR 0 [BX], AL           \ Use OR to set bits

    NEXT

    END-CODE

 

CRESET  Set the contents of a character (byte) at addr so the the bits that are 1 in b are zero in addr.  Equivalent to DUP C@ ROT NOT AND SWAP C! .

 

CODE CRESET ( b addr -- )

    POP BX

    POP AX

    NOT AX          \ Clear bits by NOT AND

    AND 0 [BX], AL

    NEXT

    END-CODE

 

CTOGGLE Flip the bits in a character (byte) at addr by the value b.  Equivalent to DUP C@ ROT XOR SWAP C! .

 

CODE CTOGGLE    ( b addr -- )

    POP BX

    POP AX

    XOR 0 [BX], AL      \ Toggle bits by XOR

    NEXT

    END-CODE

 

ON      Set the contents of addr to TRUE or -1.  All 16 bits are set.  See also ON> in Sec. 6.2.

 

CODE ON ( addr -- )

    POP BX

    MOV 0 [BX], # TRUE WORD

    NEXT

    END-CODE

 

OFF     Set the contents of addr to FALSE or 0.  All 16 bits are cleared.  See also OFF> in Sec. 6.2.

 

CODE OFF    ( addr -- )

    POP BX

    MOV 0 [BX], # FALSE WORD

    NEXT  

    END-CODE

 

-1!     Same as ON.  This is to make our intention clear in storing a number -1 into the address.  ON is meant to set a flag, which should not be taken as a number -1.

 

CODE -1!    ( addr -- )

    POP BX

    MOV 0 [BX], # TRUE WORD

    NEXT

    END-CODE

 

0!      Same as OFF.  The intention is to store a zero, not to clear a flag.

 

CODE 0! ( addr -- )

    POP BX

    MOV 0 [BX], # FALSE WORD

    NEXT

    END-CODE

 

INCR        Increment the contents of addr.  Equivalent to 1 SWAP +! .  This is a very common operation missing in most Forth systems.

 

CODE INCR   ( addr -- )

    POP BX

    INC 0 [BX] WORD

    NEXT            

    END-CODE

 

DECR        The reverse of INCR.  Decrement contents in addr.

 

CODE DECR   ( addr -- )

    POP BX

    DEC 0 [BX] WORD

    NEXT

    END-CODE

 

0DECR   Decrement contents in addr  to 0 only, not below.

 

CODE 0DECR  ( addr -- )

    POP BX

    DEC 0 [BX] WORD

    0< IF   MOV 0 [BX], # 0 WORD

    THEN

    NEXT

    END-CODE

 

D+!     Add a double integer d to the double integer located at addr.  Similar to +!.

 

CODE D+!    ( d addr -- )

    POP BX

    POP AX

    POP DX

    ADD 0 [BX], DX

    ADC 2 [BX], AX

    NEXT

    END-CODE

 

+!      Add a 16 bit integer n to the 16 bit integer stored at addr.

 

CODE +! ( n addr -- )

    POP AX

    END-CODE

 

C+!     Add a byte b to a byte stored at addr.

 

CODE C+!    ( b addr -- )

2.4.   COMPARISON WORDS

 

 

Comparison words test the top item or items on the data stack and return a flag (identified as f on the stack) to be used mostly for conditional jump words like IF, UNTIL, WHILE, ?LEAVE, ABORT", etc.  The flag is either TRUE (-1) or FALSE (0).  Sometimes these flags can be used to increment or decrement a variable or address conditionally.  Using the flag to do arithmetic is permissible (F-PC does not care a bit!) but is considered bad style.  Flags should be used for logic operations, not for arithmetic operations.  Relying upon the side effects of logic flags will often lead you into trouble.

 

In Forth, the TRUE condition is represented by any integer other than 0.  The 'true TRUE' is represented by -1.  All comparison words return 'true TRUE' under the true condition, but words consuming the true flag require only a non-zero integer.  This property allows us to use = to test for equality and - to test for inequality.  Using the results of arithmetic operations as flags is powerful but sometimes very confusing.

 

Forth is best known to be an untyped language.  The reason is that data are generally pushed on the data stack and are operated upon there.  Once a piece of data is pushed on the data stack, its identity is completely lost.  It can thus be treated as an address, an integer, part of a double integer, a flag, a byte, a character, or whatever you desire it to be.  Much of the flexibility and power of Forth is derived from this unique property.  However, to write a clear and understandable Forth program, one should avoid as much as possible the confusion in mixed data types.  F-PC includes many words of identical functions but with different names to emphasize the types of data involved in the operation.  You are encouraged to use the proper words to clarify your intentions in the program.

 

F-PC provides a very rich set of comparison words, allowing you to test most situations easily and quickly.  Most comparison words belong to either the unary type or the binary type as discussed in the arithmetic words, Sec. 2.2.  There are also more complicated comparison words which do not generate flags, like WITHIN, BETWEEN, MAX and MIN.

 

In F-PC 2.25 and earlier versions, a common point of return is defined as a label YES.  This practice was adopted from F83.  It pushes a TRUE flag on the stack before doing NEXT:

 

LABEL YES

    MOV AX, # TRUE      \ Copy a true flag into AX 

    1PUSH               \ Push AX and do NEXT

    END-CODE

 

In F-PC 3.5, this common return method is abolished.  Each comparison word generates the proper flag locally, and runs much faster.

 

0=      Return true if top is zero, false otherwise.  0= is more reassuring than NOT, which does a bitwise complement to the item on top of the stack.  Here n does not have to be -1.  Any non-zero integer will cause a false flag to be returned, and only a 0 will result in a true flag.  NOT behaves like a comparison operator only for 'true TRUE' and FALSE flags.  It will not work properly as 0= if the integer is not -1 or 0.

 

CODE 0= ( n -- f )

    POP AX

    SUB AX, # 1         \ Only if n=0, a borrow will be generated

    SBB AX, AX          \ Subtract with borrow to produce the correct flag.

    1PUSH

    END-CODE

 

0<      Return true if top is negative, i.e., sign bit is on.  Otherwise return false.

 

CODE 0< ( n -- f )

    POP AX

    CWD             \ Extend sign bit into DX register.

    PUSH DX

    NEXT

    END-CODE

 

0>      Return true if top is positive.

 

CODE 0> ( n -- f )

    POP AX

    NEG AX

    OV<> IF CWD     \ Use the overflow bit to test for positive condition

        PUSH DX     \ Extend 0 to DX

        NEXT

    THEN

    SHL AX, # 1

    1PUSH

    END-CODE

 

0<>     Return true if the top is non-zero, false otherwise.

 

CODE 0<>    ( n -- f )

    POP AX

    NEG AX

    SBB AX, AX

    1PUSH

    END-CODE

 

=       Return true if the two elements on the stack are equal, false otherwise.

 

CODE =  ( n1 n2 -- f )

    POP AX

    POP CX

    SUB AX, CX

    SUB AX, # 1

    SBB AX, AX

    1PUSH

    END-CODE

 

<>      Return true if the two element are not equal, else false.

 

CODE <> ( n1 n2 -- f )

    POP AX

    POP CX

    SUB AX, CX

    NEG AX

    SBB AX, AX

    1PUSH

    END-CODE

 

?NEGATE   Negate the second element if the top is negative.

 

: ?NEGATE   ( n1 n2 -- n3 )

    0<              \ Negate n1 if n2<0

    IF    NEGATE   THEN   ;

 

U<      Compare the top two elements on the stack as unsigned integers and return true if the second is less than the first.  Be sure to use U< whenever comparing addresses, or else strange things will happen above the 32K boundary.

 

CODE U< ( u1 u2 -- f )

    POP CX

    POP AX

    SUB AX, CX

    SBB AX, AX

    1PUSH

    END-CODE

 

U>      Compare the top two unsigned integers on the stack.  True if u1 > u2.

 

CODE U> ( u1 u2 -- f )

    POP AX

    POP CX

    SUB AX, CX

    SBB AX, AX

    1PUSH

    END-CODE

 

<       Compare the top two elements on the stack as signed integers and return true if n1 < n2.

 

CODE <  ( n1 n2 -- f )

    POP AX

    POP BX

    CMP BX, AX

    >= IF   SUB AX, AX

        1PUSH

    NEXT

    MOV AX, # TRUE

    1PUSH

    END-CODE

 

>       Compare the top two elements on the stack as signed integers and return true if n1 > n2.

 

CODE >  ( n1 n2 -- f )

    POP AX

    POP BX

    CMP BX, AX

    <= IF   SUB AX, AX

        1PUSH

    NEXT

    MOV AX, # TRUE

    1PUSH

    END-CODE

   

UMIN        Return the smaller of n1 and n2, using unsigned comparison.

 

CODE UMIN   ( n1 n2 -- min )

    POP AX

    POP BX

    CMP BX, AX

    U<= IF  PUSH BX

        NEXT

    THEN

    1PUSH

    END-CODE

 

MIN     Return the smaller of n1 and n2.

 

CODE MIN    ( n1 n2 -- min )

    POP AX

    POP BX

    CMP BX, AX

    <= IF   PUSH BX

        NEXT

    THEN

    1PUSH

    END-CODE

 

MAX     Return the larger of n1 and n2.

 

CODE MAX    ( n1 n2 -- max )

    POP AX

    POP BX

    CMP BX, AX

    <= IF   1PUSH

    THEN

    PUSH BX

    NEXT

    END-CODE

 

0MAX    Return the larger of n1 or zero, treated as signed numbers.

 

CODE 0MAX   ( n1 n2 -- max )

    POP AX

    SUB BX, BX

    CMP BX, AX

    <= IF   1PUSH

    THEN

    PUSH BX

    NEXT

    END-CODE

 

UMAX    Return the UNSIGNED larger of n1 and n2.

 

CODE UMAX   ( n1 n2 -- max )

    POP AX

    POP BX

    CMP BX, AX

    U<= IF  1PUSH

    THEN

    PUSH BX

    NEXT

    END-CODE

 

BETWEEN Return true if min <= n <= max, otherwise false.

 

CODE BETWEEN    ( n min max -- f )

    XOR AX, AX

    POP BX

    POP CX

    POP DX

    <= IF   CMP DX, CX

        >= IF   DEC AX

        THEN

    THEN

    1PUSH

    END-CODE

 

WITHIN  Return true if min <= n < max, otherwise false.

 

CODE WITHIN ( n min max -- f )

    POP DI

    POP CX

    POP BX

    XOR AX, AX

    < IF    CMP BX, CX

        >= IF   DEC AX

        THEN

    THEN

    1PUSH

    END-CODE

 

 

2.5.   INPUT AND OUTPUT WORDS

 

 

Personal computers are much more fun than minicomputers and mainframes because you can do your own things with personal computers.  The IBM-PC is more fun than the Macintosh because the PC has an open bus which you can use to put in your own circuits.  For instance, the Prototype Card with decoding layout, JDR-PR2, from JDR Micro Devices, San Jose, CA (408)947-8881, about $30. 

 

To do useful things with a PC, you have to get inputs from outside into the PC and also send signals from the PC to the outside world.  Since the 8088/86 has a separate I/O path, we define a Forth interface to it.  Use P@ and P! to read or write directly to the 8086 16 bit ports.  Use PC@ and PC! to read or write to the 8088 8 bit ports.

 

PC@     Fetch a byte from an input port whose port number is on the data stack.  The port number is first popped into the DX register which is used to address the I/O ports.  Data is fetched into the AL register and then pushed on the data stack.

 

CODE PC@    ( port# -- b )

    POP DX          \ Read port# into DX.

    IN AL, DX           \ Fetch a byte.

    SUB AH, AH          \ Clear higher byte in AX.

    PUSH AX         \ Push results on the stack.

    NEXT                \ Faster than 1PUSH.

    END-CODE

 

P@      Fetch a 16 bit integer from an input port.  The 8086/80286 has a 16 bit I/O bus and you can get 16 bit data from a port if the device connected to this port also supports a 16 bit data path.  It is actually easier to get 16 bits of data than 8 bits because you don't have to mask the upper 8 bits.

 

CODE P@ ( port# -- n )

    POP DX

    IN AX, DX

    PUSH AX

    NEXT

    END-CODE

 

PC!     Store a byte into an 8 bit output port.

 

CODE PC!    ( b port# -- )

    POP DX

    POP AX

    OUT DX, AL

    NEXT

    END-CODE

 

P!      Store a 16 bit integer into a 16 bit output port.

 

CODE P! ( n port# -- )

    POP DX

    POP AX

    OUT DX, AX

    NEXT

    END-CODE

 

In the above Forth I/O words, port addresses are passed through the DX register.  The F-PC assembler also supports the 8080 style input-output instructions.  If the port address is known and fixed at the assembly time, the explicit port number can be used to direct I/O function to a specific port.  The I/O instructions can be coded as follows:

 

    IN AL, # port

    OUT # port AL

 

In this case the port number is restricted to one byte.  These I/O instructions cannot access ports whose port numbers are higher than 255.  However, these fixed port I/O instructions are faster, even without the overhead to set the DX register.

 

 

2.6.   DOUBLE INTEGER WORDS

 

 

F-PC is a 16 bit Forth implementation, because the width of data stored on the stacks is 16 bits and most of the arithmetic and logic operations assume that the data are 16 bits in width.  However, a large set of words is included in F-PC to deal with 32 bit data.  The double integer extension word set in the Forth-83 Standard is fully supported.

 

A double integer occupies a 4 byte of space in memory.  The order of significance is Byte2, Byte3, Byte0 and Byte1, where Byte0 is the least significant part of the double integer and Byte3 is the most significant.  This strange arrangement is caused by the requirement that when a double integer is on the stack, the most significant 16 bit half must be on the top of the stack and is more easily accessible.  The ordering of bytes in a 16 bit integer is due to the Intel convention: the least significant byte precedes the most significant byte in memory.  The byte ordering of a double integer is the same on the data stack as in the memory.

 

If you pop a double integer on the top of data stack, you will get the most significant 16 bits first.  If you fetch a 16 bit integer from the address of a double integer, you will get the most significant 16 bit also.  The least significant 16 bits are stored at address+2.

 

The 8088/8086 lends itself easily to do double integer operations if you put the address in the BX register.  The most significant 16 bits can be accessed by 0 [BX] and the least significant part by 2 [BX].  The technique becomes obvious if you examine the following code definitions.

 

2@      Fetch a 32 bit value from addr.

 

CODE 2@ ( addr -- d )

    POP BX          \ Pop address

    PUSH 2 [BX]             \ PUSH LS 16 bits

    PUSH 0 [BX]         \ PUSH MS 16 bits

    NEXT               

    END-CODE

 

2!      Store a 32 bit value at addr.

 

CODE 2! ( d addr -- )

    POP BX          \ Pop address

    POP 0 [BX]          \ Store MS 16 bits

    POP 2 [BX]          \ Store LS 16 bits

    NEXT                \ Done

    END-CODE

 

2DROP   Discard the top two elements of the stack.

 

CODE 2DROP  ( d -- )

    ADD SP, # 4

    NEXT

    END-CODE

 

3DROP   Discard the top three elements of the stack.

 

CODE 3DROP  ( n d -- )

    ADD SP, # 6

    NEXT

    END-CODE

 

2DUP        Duplicate the top two elements of the stack.

 

CODE 2DUP   ( d -- d d )

    MOV DI, SP

    PUSH 2 [DI]

    PUSH 0 [DI]

    END-CODE

 

3DUP        Duplicate the top three elements of the stack.

 

CODE 3DUP   ( a b c -- a b c a b c )

    MOV DI, SP

    PUSH 4 [DI]

    PUSH 2 [DI]

    PUSH 0 [DI]

    END-CODE

 

4DUP        Duplicate the top 4 elements of the stack.

 

: 4DUP      ( a b c d -- a b c d a b c d )

    2OVER 2OVER

    ;

 

2SWAP   Swap the top two pairs of double integers on the stack.  You can use this operator to swap two 32 bit integers and preserve their meaning as double integers.

 

CODE 2SWAP  ( d1 d2 -- d2 d1 )

    POP CX          \ Pop them all

    POP BX

    POP AX

    POP DX

    PUSH BX         \ Push in the right order

    PUSH CX

    2PUSH

    END-CODE

 

 

2OVER   Copy the second pair of double integers over the top pair.  Behaves like OVER for 32 bit integers.

 

CODE 2OVER  ( d1 d2 -- d1 d2 d1 )

    MOV DI, SP

    PUSH 6 [DI]

    PUSH 4 [DI]

    NEXT                \ 50 cycles

    END-CODE

 

2ROT        Rotate top three double integers.  It is done in high level because we do not have enough registers to store 6 items.  It is also used very rarely.

 

: 2ROT      ( a b c d e f -- c d e f a b )

    5 ROLL              \ Get a

    5 ROLL              \ Get b

    ;

 

D+      Add the two double integers on the stack and return the results as a double integer.

 

CODE D+ ( d1 d2 -- dsum )

    POP AX          \ Get d2

    POP DX

    POP BX          \ Get d1

    POP CX

    ADD DX, CX          \ Add LS parts

    ADC AX, BX          \ Add MS parts with carry.

    2PUSH               \ Push sum.

    END-CODE

 

DNEGATE Same as NEGATE except for double integers.

 

CODE DNEGATE    ( d1 -- -d1 )

LABEL DNEG1             \ Shareable code with DABS 

    POP AX          \ Get d1

    POP DX

    NEG AX

    NEG DX

    SBB AX, # 0         \ Adjust borrow

    2PUSH               \ Push results

    END-CODE

 

S>D     Take a single integer and make it a double integer by extending the sign bit to the upper half.

 

CODE S>D    ( n -- d )

    POP AX

    CWD             \ Just the right instruction to extend the sign of n.

    XCHG DX, AX         \ Adjust the register order

    2PUSH

    END-CODE

 

DABS        Return the absolute value of the 32 bit integer on the stack.

 

CODE DABS   ( d -- |d| )

    POP AX

    OR AX, AX

    0>= IF  1PUSH

    THEN

    POP DX

    NEG AX

    NEG DX

    SBB AX, # 0

    2PUSH

    END-CODE

 

D2*     32 bit left shift.

 

CODE D2*    ( d -- d*2 )

    POP AX          \ Get MS part

    POP DX          \ Get LS part

    SHL DX, # 1         \ Shift LS part left

    RCL AX, # 1         \ Rotate left with carry

    2PUSH               \ Push results

    END-CODE

 

D2/     32 bit arithmetic right shift.  Equivalent to divide by 2.

 

CODE D2/    ( d -- d/2 )

    POP AX

    POP DX

    SAR AX, # 1         \ Arithmetic shift right

    RCR DX, # 1         \ Rotate right with carry

    2PUSH

    END-CODE

 

D-      Subtract the two double integers.

 

: D-    ( d1 d2 -- d3 )

    DNEGATE         \ -d2

    D+   ;              \ d1-d2

 

?DNEGATE    Negate the double integer if the top is negative.

 

: ?DNEGATE  ( d1 n -- d2 ) 

    0<              \ n<0 ?

    IF   DNEGATE   THEN   ;

 

D0=     Compare the top double integer to zero.  True if d=0.

 

: D0=       ( d -- f )

    OR              \ Every bit must be 0.

    0= ;

 

D=      Compare the top two double integers.  True if d1=d2

 

: D=        ( d1 d2 -- f )

    D-              \ Compare 

    D0=  ;              \ Return the flag

 

DU<         Perform unsigned comparison of two double integers.  It is built upon the single integer unsigned compare U<.

 

CODE DU<    ( ud1 ud2 -- f )

    POP DX

    POP BX

    POP CX

    POP AX

    SUB AX, BX

    SBB CX, DX

    SBB AX, AX

    1PUSH

    END-CODE

 

D<          Compare the top two double integers.  True if d1<d2.

 

: D<        ( d1 d2 -- f )

    2 PICK OVER =       \ If MS parts are equal,

    IF      DU<         \ use DU< to compare.

    ELSE  NIP ROT DROP <    \ Otherwise compare MS parts.

    THEN  ;

 

D>          Compare the top two double integers.  True if d1>d2.

 

: D>        ( d1 d2 -- f ) 

    2SWAP

    D<   ;

 

DMIN        Return the lesser of the top two double integers.

 

: DMIN      ( d1 d2 -- d3 )

    4DUP D>             \ If d1>d2,

    IF  2SWAP  THEN         \ Move the unwanted double integer to top of stack,

    2DROP ;         \   and discard it.

 

DMAX        Return the greater of the the top two double integers.

 

: DMAX  ( d1 d2 -- d3 )

    4DUP D<             \ If d1<d2,

    IF  2SWAP  THEN         \   move d1 to top,

    2DROP ;         \   and discard the lesser.

 

 

2.7.   THE STRUCTURE WORDS

 

 

In a colon definition, Forth words are compiled as a list of  addresses which point to executable code.  In F-PC, the list of addresses is stored in the List Segment, and the addresses are Code Field Addresses.  The Code Field Addresses are offset addresses in the Code Segment, which contains executable machine code and various other data structures.  When a colon definition is executed, the colon inner interpreter goes through this list of cfa's and executes the code contained in the code fields.  Since the code field contains executable code, F-PC is thus based on the 'Direct Threaded Code.'  F-PC is much faster than its predecessor F83 which is based on the 'Indirect Threaded Code.'  In indirectly threaded code, an address compiled in a colon definition points to a code field which contains the address of executable code.  F-PC gets rid of this level of indirection and the performance is greatly improved.

 

There are other data structures in a colon definition.  The most common data besides code addresses are integer literals.  A literal structure contains the code address of (LIT) and a 16 bit integer, compiled in-line with the addresses.  When (LIT) is executed, it pulls the integer out of the next address, pushes it on the data stack, and continues executing the next word following the integer.  Other data structures based on integer literals are double integer literal, ASCII code literal, and address literal.

 

Another useful class of literals is string literals, which allow strings of characters to be compiled in-line with the execution addresses.  The run-time behavior of string literals depends upon the string literal word compiled before the string.  The string literal will be discussed much later.

 

Forth is a structured language and it allows the user to build control structures inside colon definitions and code definitions.  Control structures are characterized by the property that each structure has one entry point and one exit point.  F-PC provides a powerful word set for building selection structures (IF-ELSE-THEN), finite loops (DO-LOOP), indefinite loops (BEGIN-UNTIL and BEGIN-WHILE-REPEAT), infinite loops (BEGIN-AGAIN), and case structures.

 

Building literals and control structures requires specialized tools which are generally called compiler directives or assembler directives.  The directives are Forth words which are immediately executed inside colon or code definitions.  They compile special words and the necessary data or addresses so that the desired control path can be accomplished at run-time.  It requires very lengthy discussions to fully explain these directives because one would have to comprehend the significance of words whose run-time behavior differs from their compile-time behavior.  The difficulty multiplies here in the kernel because the kernel is built by the metacompiler, which has to build an object image which is executable in a target environment, not in the host environment while the object image is being compiled.

 

Keeping these difficulties in mind, you will understand that it is impossible to fully explain all the intricacies in this part of the F-PC kernel.  You don't have to read this section too seriously.  Scan through it first and move to other parts which are more interesting.  When you finish the metacompiler, come back and re-visit this section.  It will then begin to make sense, I assure you.

 

T: defines a metacompiler directive, which compiles a data or control structure in the target image during metacompilation.  The set of metacompiler directives are very similar to the set of compiler directives used for normal Forth programming, as discussed in Chapter 4 later.  The difference is that the regular compiler directives build structures in executable code on the host computer, while the metacompiler directives build structures in the target code image intended to be executed on a target computer.

 

In Figures 4 and 5 we try to summarize different data structures and control structures used in F-PC colon definitions.  It will give you an idea of how these structures are used in colon definitions and the run-time code which executes these structures.

 

(LIT)       The run-time code for literals.  Push the following two bytes in the list of cfa's onto the data stack and moves the IP over them.  It is compiled by the word LITERAL.  (LIT) allows constants to be stored in-line with the cfa's in the list of a colon definition.  Using the special 8088 instruction LODSW ES:, (LIT) is much faster than constants which have to jump to the Code Segment to find their stored values.  It is thus more advantageous in F-PC to use literals than constants.

 

CODE (LIT)  ( -- n )

    LODSW ES:           \ Grab next word in list

    1PUSH               \ Push it on data stack

    END-CODE

 

<'>     Same as (LIT).

 

LITERAL Compile (LIT) into the target list dictionary and follow it by the integer on the top of data stack.  (LIT) and the integer form an integer literal structure in a colon definition.

 

T: LITERAL  ( n -- )

    [TARGET] (LIT)      \ Compile (LIT)

    ,-X   T;                \ Compile n

 

DLITERAL    Compile a double integer literal as two single integer literals.  The (LIT) dl (LIT) dh structure will push the double integer onto the stack at run-time.

 

T: DLITERAL ( d -- )

    [TARGET] (LIT) ,-X      \ Compile lower half of d  

    [TARGET] (LIT) ,-X   T;     \ Compile higher half of d

        [[ TRANSITION ]]

    THEN  ;

CODE DOBEGIN    ( -- )      \ Really a NOOP

    NEXT   

    END-CODE

DOAGAIN Unconditional jump to the offset address compiled in the next cell.  Compiled by AGAIN to close an infinite loop.

 

CODE DOAGAIN    ( -- )

    MOV ES: IP, 0 [IP]      \ Move the address in next

    NEXT                \   cell into IP, thus effect

    END-CODE            \   an unconditional jump.

CODE DOREPEAT   ( -- )

    MOV ES: IP, 0 [IP]      \ Load IP and jump

    NEXT

    END-CODE

 

?WHILE  Compiled by WHILE inside an indefinite loop.  Test top of stack.  If the flag is true, continue executing the following word sequence.  Otherwise, jump to the end of loop marked by DOREPEAT.

 

CODE ?WHILE ( f -- )

    POP CX

    CX0<> IF

        ADD IP, # 2     \ Continue on.

        NEXT

    THEN

    MOV ES: IP, 0 [IP]      \ Load IP and jump to the end of the loop.

    NEXT               

    END-CODE           

 

?UNTIL  Compiled by UNTIL as the end of an indefinite loop.  Test top of stack as a flag.  If it is true, exit the loop.  Otherwise jump back to BEGIN.  The code is identical to >WHILE.

 

BRANCH  Performs an unconditional branch.  Compiled by ELSE. 

 

CODE BRANCH ( -- )

    MOV ES: IP, 0 [IP]

    NEXT

    END-CODE

 

DOENDOF Identical to BRANCH.  End of a case clause.

 

?BRANCH Performs a conditional branch.  If the top of the data stack is true, take the branch.  If not, skip over the branch address which is in-line.  Same as ?WHILE.  It is compiled by IF.

 

NEXT|       End of a FOR...NEXT loop.  This loop structure was used by Chuck Moore for NC4000 Forth engine, in which NEXT| is a machine instruction.

 

CODE NEXT| ( n1 --- )      \ Primitive form of NEXT (as in FOR - NEXT loops)

    SUB 0 [RP], # 1 WORD        \ Decrement top of return stack.

    U>= IF              \ If not negative yet, branch back to address after FOR.

        MOV IP, ES: 0 [IP]

        NEXT

    THEN

    ADD RP, # 2         \ End of loop.  Discard count on the return stack.

    ADD IP, # 2         \ Continue.

    NEXT    END-CODE

(LOOP)  The run-time procedure for LOOP.  Branch back to the beginning of the loop if there are more iterations to do.  Otherwise it exits.  The loop counter is incremented.

 

CODE (LOOP) ( -- )

    INC 0 [RP] WORD     \ Increment index

    OV<> IF         \ If not yet overflowed,

        MOV ES: IP, 0 [IP]  \   loop back.

        NEXT

    THEN

    ADD RP, # 6         \ Overflow, terminate the loop.

    ADD IP, # 2

    END-CODE

 

(+LOOP) Increment the loop counter by the value on the stack and decide whether or not to loop again.  Due to the weirdness of the 8088, you have to stand on your head to determine the conditions under which you loop or exit.

 

CODE (+LOOP)    ( n -- )

    AX POP          \ Get increment n

    ADD 0 [RP], AX      \ Add it to the index

    OV<> IF         \ If not yet overflowed,

        MOV ES: IP, 0 [IP]  \   loop back.

        NEXT

    THEN

    ADD RP, # 6         \ Overflow, terminate the loop.

    ADD IP, # 2

    END-CODE

 

(DO)        The run-time code compiled by DO.  Push an in-line address onto the return stack along with values needed by (LOOP).  This DO-LOOP mechanism was included in the Forth-83 Standard, attributed to Bob Smith.  Three items are pushed on the return stack: the exit address which was compiled right after (DO), the loop limit lim with its most significant bit set, and a loop index which is ind-lim+8000H.  The index is incremented by (LOOP).  The overflow flag will indicate that the index has crossed the boundary of limit and limit-1.  The overflow condition causes the loop to be terminated.  This loop mechanism is faster than the old way where the unmodified limit and index are pushed on the return stack.

 

This DO-LOOP structure does have the peculiarity that if ind=lim, the loop is executed 65536 times, which produces a momentary pause for an empty loop, or a longer pause if a slow set of instructions is in the loop.  The exit address is compiled after (DO) by DO and resolved by LOOP.  It is pushed on the return stack under index and limit so that LEAVE will be able to exit the loop immediately, without having to continue executing till LOOP before exiting.  This DO-LOOP structure was adopted in F83 and carried over into F-PC.

 

HEX                 \ Hard to say 8000H in decimal

CODE (DO)   ( lim ind -- )

    POP DX          \ Get index ind

    POP BX          \ Get limit lim

    XCHG RP, SP         \ Prepare to push things on the return stack.

    LODSW ES:           \ Get the exit address after LOOP.

    PUSH AX         \ Push the address on the return stack.

    ADD BX, # $8000     \ Offset limit by $8000

    PUSH BX         \ Push modified limit

    SUB DX, BX          \ Take the difference of limit and index

    PUSH DX         \ Push it on the return stack.

    XCHG RP, SP         \ Restore data stack and return stack pointers

    NEXT

    END-CODE

(?DO)       The run-time code compiled by ?DO.  The difference between ?DO and DO is that ?DO will not perform any iteration if the initial index is equal to the final limit.

 

CODE (?DO)  ( lim ind -- )

    POP DX          \ Get index

    POP BX          \ Get limit

    CMP BX, DX          \ limit=index?

    0= IF

        MOV ES: IP, 0 [IP]  \ Yes.  Exit immediately.

        NEXT

    THEN

    XCHG RP, SP         \ Lifted from (DO).

    LODSW ES:

    PUSH AX

    ADD BX, # $8000

    PUSH BX

    SUB DX, BX

    PUSH DX

    XCHG RP, SP

    NEXT

    END-CODE

 

(OF)        Run-time code used inside a CASE structure.  It is compiled by OF.

 

CODE (OF)   ( n1 n2 -- n1 )  ( or )  ( n1 n1 -- )

    MOV DI, SP          \ Test against the input number.  DI  relative is faster than

        MOV ES: IP, 0 [IP]

        NEXT

    THEN

    ADD SP, # 2         \ Numbers are equal, execute the OF clause.

    ADD IP, # 2

    NEXT

    END-CODE
