CHAPTER 4.   INTERPRETER AND COMPILER

 

 

 

 

 

KERNEL3.SEQ is the most interesting part of the F-PC system, containing all the words which build up the text interpreter and many compilers for various types of Forth words in F-PC.  In a sense, these words form the Forth operating system which allows the user to enter commands for execution and also compile source code to extend the Forth system.

 

Many of these words are built from words that were defined in KERNEL1.SEQ.  Furthermore, you will find that many of the compiler directive words are the same as those defined under the metacompiler in KERNEL1.SEQ.  However, the compiler directives defined here are those which we normally use in a target system like F-PC.  The ones in KERNEL1.SEQ are used to build the target system.  Word names are the same but the functions are quite different.  Since the compiler words defined in this file are the ones you will use in F-PC, they deserve more attention as you start learning the internal structures of F-PC.  After you fully understand the whats, whys and hows here, you can go back and take a closer look at the target compiler words which build a target core image, not words executable in F-PC.

 

 

4.1.   THE DICTIONARY WORDS

 

 

>TYPE   Type a string in a multitasking system.  The string is copied from common memory to PAD, which is private to a task, and sent out to the console device from there.  Each task must manage its own input and output processes.

 

: >TYPE ( addr len -- )

    TUCK                \ Hide a copy of len under addr

    PAD SWAP CMOVE      \ Copy string to PAD

    PAD SWAP TYPE       \ Type from PAD

    ;

 

.(      Type the following string on the terminal.  This is useful in printing messages from a file while the file is being interpreted or compiled.

 

: .(        ( -- ) 

    ASCII )             \ The string terminator

    PARSE >TYPE         \ Parse out string and type it

    ; IMMEDIATE         \ Must be executed, not compiled.

 

(       The Forth comment command.  The following input stream up to and including  ) is ignored.

 

: (     ( -- )

    ASCII )             \ Scan till )

    PARSE

    2DROP           \ Ignore the string

    ; IMMEDIATE

 

TRAVERSE    Run through a name field in the specified direction.  Terminate when we detect a byte whose most significant bit is set.  The name field in a header is delimited by characters with the most significant bit set.  If the direction is 1, scan forward; if it is -1, scan backward.  It allows us to move from the link field before the name field to the code pointer field after the name field and vice versa.

 

CODE TRAVERSE       ( addr direction -- addr' )

    POP CX          \ Direction flag

    POP BX          \ Address of first character

    ADD BX, CX          \ Incr/decr address

    PUSH ES         \ Save ES

    MOV ES, YSEG        \ ES needed for Head Segment

    BEGIN               \ Scan the name field

        MOV ES: AL, 0 [BX]  \ Get next character

        AND AL, # 128       \ Bit 7 cleared?

    0= WHILE            \ Yes.

        ADD BX, CX      \ Continue with next character

    REPEAT          \ No.  End of name field

    POP ES          \ Restore ES

    PUSH BX         \ Return new address

    NEXT                \ Done

    END-CODE

 

DONE?   Return a true flag if the input stream is exhausted or if the number n on the data stack does not match that in STATE.  This is used to turn off the compiler and return to the text interpreter.  It is recoded in assembly for speed. 

 

CODE DONE?  ( n -- f )      \ STATE @ <>   END? @ OR   END? OFF   .

    POP AX          \ n

    CMP AX, STATE       \ n <> STATE ?

    0<> IF

        MOV END? # 0 WORD   \ Clear END?

        MOV AX, # -1        \ Leave true in AX

        1PUSH

    THEN

    PUSH END?           \ Push flag

    MOV END? # 0 WORD

    NEXT

    END-CODE

 

CNHASH  Code to Name Hash.  Given a code field address, get a pointer into the name  hash table in YSEG.  Since heads are separated from code in F-PC, it is difficult to find the head of a word from its code field address.  The name hash table in the Head Segment limits the ranges of heads to be searched for a given code field address.  The table has 64 entries of 4 bytes each.  Each entry has a high address and a low address, which delimits the memory range in the Head Space to be searched.  The Code Segment is divided into 64 blocks of 1024 bytes.  Each block of code has a name hash table entry pointing to an area in the head space where the heads of words in the corresponding block are to be found.  The relationship among the code dictionary, the head dictionary, and the name hash table is shown in Figure 6.

 

HEX

: CNHASH    ( cfa -- yaddr )

    0FE00 AND           \ Code Segment is divided into 64 blocks of 1024 bytes each

    FLIP ;              \ (n/1024)*4, offset into the hash table

: CNSRCH    ( cfa ya maxya -- nfa flag )

    SWAP 2+ 2+          \ From ya to nfa of first head

    BEGIN 2DUP          \ Compare nfa to the limit maxya

    U> WHILE ( cfa mxy nfa )    \ If still in range, search.

        DUP YC@ 31 AND \ Get the length of name field

        + 1+ DUP Y@     \ Fetch cfa in code pointer field

        3 PICK =        \ Compare code field addresses

        IF -ROT 2DROP   \ Found.

            1- -1 TRAVERSE  \ Move back and recover nfa

            FALSE EXIT \ Add flag and quit

        THEN

          6 +               \ Not matched. Continue with the

    REPEAT   2DROP      \   next name field

    TRUE ;          \ Failed.  Push a true flag.

 

CNSRCH was re-coded in assembly to improve searching speed.  The new code definition is as follows:

 

CODE CNSRCH ( cfa ya maxya -- nfa f )

    pop dx              \ maxya

    pop bx              \ ya

    add bx, # 4         \ Move to name field

    pop di              \ cfa

    mov ds, yseg            \ Align DS to Head Segment

HERE    cmp dx, bx          \ Ya is still less than maxya?

    U> IF   mov ax, 0 [bx]  \ Yes.

        and ax, # 31        \ Skip over the name field

        add bx, ax

        inc bx          \ Move to code pointer field

        mov ax, 0 [bx]      \ Get cfa

        cmp ax, di      \ If they match, then we found it

        0= if

            sub bx, # 2     \ 1 before last char in name

            begin   mov al, 0 [bx]  \ Test high bit

                and al, # 128   \ Loop till high set

            0= while   dec bx   \ Backup one char

            repeat

            push bx     \ Push nfa of found name

            mov ax, cs      \ Restore DS

            mov ds, ax

            mov ax, # false     \ Push false flag.  Success.

            1push

        then

        add bx, # 6     \ Step to nfa of next header

        JMP ROT     \ Jump to  HERE above to           

                    \   repeat the search

    THEN

    mov ax, cs          \ Search failed

    mov ds, ax          \ Restore DS

    mov ax, # true          \ Push flag

    push ax

    1push               \   and return

    end-code

4.2.   INTERPRETER WORDS

 

 

HASH        Given a string address and a pointer to a vocabulary thread table, return the actual thread.  Use the first two characters and the count of the string to determine which thread.  The hashing algorithm is 2*(char2 + 2*char1) + count.  This special algorithm gives the best distribution of words in the FORTH vocabulary among the 64 threads.  The function of HASH is incorporated into the code word OVER.SWAP.HASH.@(FIND).  It is not used by F-PC, but preserved for F83 compatibility.

 

CODE HASH   ( str-addr voc-ptr -- thread )

    POP CX          \ Vocabulary pfa

    POP BX          \ String address

    MOV AX, 1 [BX]      \ First and second characters

    SHL AL, # 1         \ 2*char1

    ADD AL, AH          \ Add second character

    SHL AL, # 1         \ 2* again

    ADD AL, 0 [BX]      \ Add count

    AND AX, # #THREADS 1-   \ Only 64 thread

    SHL AX, # 1         \ Offset address

    ADD AX, CX          \ Address of selected thread

    1PUSH               \   in vocabulary thread table

    END-CODE

 

 

(FIND)  Search the dictionary based on the pointer to a vocabulary thread table and a string.  If it finds the string in a thread, return the code field address of the word.  If the word is an immediate word the flag returned is a 1.  If it is non-immediate the flag returned is a -1.  If the name is not found, the string address is returned along with a flag of zero.  Note that links point to links, and lfa's are absolute addresses in the Head Segment.

 

CODE (FIND) ( here lfa -- cfa flag | here false )

    POP BX                  \ Link field address

    OR BX, BX          

    0= IF                       \ If it is 0, exit with

        SUB AX, AX              \   a false flag.

        1PUSH

    THEN

    POP CX                  \ HERE has the string

    PUSH ES

    MOV ES, YSEG                \ ES must point to Head Segment.

    MOV DI, CX         

    BEGIN

        MOV ES: AX, 2 [BX]          \ First cell in name field

        XOR AX, 0 [DI]          \ Compare to 1st cell in string

        AND AX, # ( 63 ) $7F3F      \ Mask off irrelevant bits

        0= IF                   \ A match!

            MOV DX, BX          \ Save link field address

            ADD BX, # 2         \ Point BX to name field

            BEGIN               \ Scan through name

                INC BX          \ Next char in name

                INC DI          \ Next char in string

                MOV ES: AL, 0 [BX]

                XOR AL, 0 [DI]      \ Match?

            0<> UNTIL           \ Exit if characters not same

            AND AL, # 127           \ Mask off delimiting bit

            0= IF

                MOV ES: CX, 1 [BX]  \ Pick up cfa

                MOV BX, DX      \ Link field address

                MOV ES: AL, 2 [BX]  \ Count byte in name

                AND AL, # 64        \ Test for immediacy

                0<> IF

                    MOV AX, # 1 \ 1 for immediate word

                ELSE

                    MOV AX, # -1    \ -1 for normal word

                THEN

                POP ES      \ Restore ES

                PUSH CX     \ Cfa just found

                1PUSH           \ Push flag

            THEN        \ Fail to match last char

            MOV BX, DX  \ Restore link field address

            MOV DI, CX  \ Restore HERE pointer

        THEN            \ Fail to match 1st cell

        MOV ES: BX, 0 [BX]  \ Get next link in thread

        OR BX, BX       \ Exit loop at end of thread

    0= UNTIL            \ Not end.  Compare next name.

    POP ES          \ Restore ES

    PUSH CX         \ Push back HERE

    SUB AX, AX          \   with a false flag.

    1PUSH

    END-CODE

 

FIND        Run through the vocabulary stack searching for the name whose address is supplied on the stack.  If the name is found, return the code field address of the name and a non-zero flag. The flag is -1 if the word is non-immediate and 1 if it is immediate.  If the name is not found, the string address is returned along with a false flag.

 

F-PC has being optimized to be very fast in compiling source files.  One reason is that almost all the words involved in compilation were recoded in assembly.  However, FIND is really too big to be reduced to machine code.  It was partially recoded by extracting a number of phrases for re-coding.  These phrases were given strange names to reflect their actions rather than functions.

 

CODE DROP.CONTEXT.I2*+@DUP      ( addr -- n n )

    \ Consolidate the phrase DROP CONTEXT I 2* + @ DUP in FIND.

    POP AX          \ DROP

    MOV AX, 0 [RP]      \ I

    ADD AX, 2 [RP]

    SHL AX, # 1         \ 2*

    MOV BX, # CONTEXT       \ CONTEXT

    ADD BX, AX          \ +

    PUSH 0 [BX]         \ n

    PUSH 0 [BX]         \ DUP

    NEXT

    END-CODE

 

CODE PRIOR.CHECK    ( n -- n f )    \ Consolidate DUP PRIOR @ OVER PRIOR ! = in FIND

    POP AX          \ Pop n

    PUSH AX         \ Push n

    MOV BX, PRIOR       \ PRIOR @

    MOV PRIOR AX        \ OVER PRIOR !

    CMP BX, AX          \ Now, figure out the flag.

    0<> IF             

        MOV AX, # FALSE

        1PUSH      

    THEN           

    MOV AX, # TRUE     

    1PUSH      

    END-CODE

 

CODE OVER.SWAP.HASH.@       ( str-addr voc-addr -- str-addr thread )

                    \ Consolidate OVER SWAP HASH @ (FIND) in FIND.

    POP AX          \ Vocabulary address

    POP BX          \ String address

    PUSH BX         \ Save String address

    MOV CL, 0 [BX]      \ HASH

    MOV BX, 1 [BX]      \ HASH

    SHL BL, # 1         \ HASH

    ADD BL, BH          \ HASH

    SHL BL, # 1         \ HASH

    ADD BL, CL          \ HASH

    AND BX, # #THREADS 1-   \ HASH

    SHL BX, # 1         \ HASH

    ADD BX, AX          \ HASH

    MOV BX, 0 [BX]      \ HASH

    END-CODE            \   Tail recursion

 

 

: %%FIND    ( addr  false #vocs 0 -- cfa flag | addr false )

    DO  DROP.CONTEXT.I2*+@DUP   \ Get thread in vocabulary.

                        \ Last flag 0 if end of thread.

        IF  PRIOR.CHECK     \ Update PRIOR with vocabulary

                        \   being searched now.

            IF          \ PRIOR is same as current vocabulary,

                DROP FALSE  \ Do not search this thread.

            ELSE    OVER.SWAP.HASH.@  (FIND)

                        \ Else, search this thread.

                DUP ?LEAVE  \ If TOS is true, a word was  found. 

                        \   Exit the loop.

            THEN

        THEN

    LOOP   ;

 

CODE %FIND      ( addr -- cfa flag | addr false )

    MOV DI, SP

    MOV BX, 0 [DI]

    CMP 0 [BX], # 0 BYTE

    0<> IF

        MOV PRIOR # 0 WORD \ prior off

        MOV BX, # 0

        PUSH BX                 \ false

        MOV CX, # #VOCS

        PUSH CX                 \ #vocs

        PUSH BX                 \ 0

        MOV AX, # ' %%FIND      \ Call colon word

        JMP AX

    THEN

    MOV END? # TRUE WORD

    MOV 0 [DI], # ' NOOP WORD

    MOV AX, # 1

    1PUSH

    END-CODE

 

DEFER FIND  ' %FIND IS FIND

 

DEFINED Look up the next word in the input stream.  Return true if it exists; otherwise false.  May ignore case if CAPS is ON.

 

: DEFINED   ( -- here 0 | cfa [ -1 | 1 ] )

    BL WORD             \ Parse out next word

    ?UPPERCASE          \ Change to upper case if CAPS<>0.

    ;

 

?STACK  Check for parameter stack underflow or overflow and issue appropriate error message if detected.  It is broken into smaller pieces to optimize for speed.  The critical part is coded in assembly.  The original high level definition is:

 

: (?STACK)  ( -- )

    SP@ SP0 @ OVER  U<   ABORT" Stack Underflow"

    PAD   2DUP  U<   ABORT" Stack Overflow"

    200 + U<

    IF      CR ."  Running out of CODE memory! "

    THEN    ;

 

It is broken down into a few high level definitions and re-assembled into a code definition.  It is an interested example showing you how high level words are called from a code word.

 

: STACKUNDER    ( --- )

    TRUE                \ Abort always

    ABORT" Stack Underflow" ;

 

: STACKOVER ( --- )

    TRUE

    ABORT" Stack Overflow" ;

 

: WARNOVER  ( --- )

    CR              \ Avoid crowding a line.

    ."  Running out of CODE memory! " ;

 

Now, we will assemble the above high level definitions into a code definition, which will run much faster than the original ?STACK colon definition.  The testing is done in machine code and runs very fast.  When an error condition is detected, the aborting routines can take all the time they can use because they are outside of the critical path.

 

CODE (?STACK)       ( --- )

    MOV CX, SP          \ Get current stack pointer

    MOV BX, UP

    MOV BX, SP0 [BX]        \ Get the bottom of stack

    CMP BX, CX          \ Underflow?

    U< IF               \ Yes.  Call STACKUNDER.

        MOV AX, # ' STACKUNDER

        JMP AX

    THEN

    MOV DX, DP [BX]     \ Get top of dictionary

    ADD DX, # 80            \ Allow some buffer

    CMP CX, DX          \ Overflow?

    U< IF               \ Yes.  Call STACKOVER.

        MOV AX, # ' STACKOVER

        JMP AX

    THEN

    ADD DX, # 200           \ Add some more buffer space

    CMP CX, DX          \ Near overflow?

    U< IF               \ Yes.  Send out a warning.

        MOV AX, # ' WARNOVER

        JMP AX

    THEN

    NEXT

    END-CODE

 

DEFER ?STACK    ' (?STACK) IS ?STACK

 

INTERPRET   The Text Interpreter Loop in F-PC.  If the next word is found in the dictionary, execute it; otherwise, convert it to a number and push it onto the stack.  It interprets the commands typed on the terminal or read from a file one line at a time.

 

: INTERP    ( -- )

    BEGIN               \ Process a line of commands 

        ?STACK              \ Abort if stack over- or under-flows.

        DEFINED         \ Parse out next word and search the dictionary.

        IF     EXECUTE      \ A word is found.  Execute it.

        ELSE   NUMBER       \ Otherwise, convert word to number

            DOUBLE? NOT     \ If not a double integer,

            IF  DROP  THEN  \   drop the most significant half.

        THEN  

        FALSE DONE?         \ Exit if at end-of-line.

    UNTIL   ;

 

DEFER INTERPRET ' INTERP IS INTERPRET

 

DEFER STATUS        Display current status of F-PC.  See Sec. 8.4 and STATUS.SEQ.

 

PRINT   Interpret the following words, and send output characters to the printer.

 

: PRINT     ( --- )

    PRINTING ON         \ Turn on printer

    INTERPRET           \ Execute words following

    PRINTING OFF ;      \ Turn off printer

 

 

4.3.   COMPILER TOOL WORDS

 

 

ALLOT   Allocate n bytes of space in the code dictionary.

 

: ALLOT ( n -- )        DP +!   ;   \ Add n to dictionary pointer

 

 

,       Comma.  Compile integer n to the top of the code dictionary.  Increment the dictionary pointer so that it will point to the next free cell on the top of the code dictionary.  Comma and C, are the two fundamental tools of the Forth compiler, as they are used to build new words and new data structures in the dictionary.

 

CODE ,      ( n -- )

    MOV BX, UP          \ DP is a user variable

    MOV AX, DP [BX]     \ Get dictionary pointer

    ADD DP [BX], # 2  WORD  \ Increment dictionary pointer by 2.

    MOV BX, AX

    POP CX          \ Get n

    MOV 0 [BX], CX      \ Compile it to dictionary

    NEXT

    END-CODE

 

C,      Similar to  ,  except it compiles an 8-bit value.

 

CODE C, ( b -- )

    MOV BX, UP

    MOV AX, DP [BX]     \ Get dictionary pointer

    INC DP [BX] WORD        \ Increment by 1

    MOV BX, AX

    POP CX

    MOV 0 [BX], CL      \ Compile byte to dictionary

    NEXT

    END-CODE

4.4.   LITERAL WORD COMPILERS

 

 

In a colon definition, the list part of the definition is in the List segment and contains mainly a list of execution addresses pointing to executable words in the Code segment.  However, other data types and structures are also allowed in the list.  Optional data structures include integer literals, double integer literals, string literals, and address literals.  A data structure must be preceeded by a pointer to the interpreter which converts the data stored in the list to data on the data stack or a pointer pushed on the stack.  Here we shall see the set of words which compile various data structures in a colon definition.  The low level words which interpret the data structures were discussed in Chapter 2.  Words compiling control structures will be discussed in Section 4.7.

 

LITERAL Compile a single integer on the stack to the List dictionary as a literal.

 

: LITERAL   ( n -- ) 

    COMPILE (LIT)       \ Compile literal interpreter

    X,              \   with the literal value.

    ; IMMEDIATE         \ Must act during compiling.

 

DLITERAL    Compile a double integer on the stack as a double integer literal.

 

: DLITERAL  ( d# -- )

    SWAP                \ Rearrange the order of double

    [COMPILE] LITERAL       \ Compile LS integer

    [COMPILE] LITERAL       \ Compile MS integer

    ; IMMEDIATE         \ Make it immediate

 

ASCII       Compile the next character in the input stream as an ASCII literal.

 

: ASCII     ( -- n )  

    BL WORD             \ Get next word

    1+ C@               \ Only use its first character

    STATE @             \ If compiling,

    IF [COMPILE] LITERAL THEN   \  compile ASCII literal

    ;               \ If interpreting, leave code on the stack.

    IMMEDIATE           \ Make it immediate

 

CONTROL Compile the next character in the input stream as a ASCII literal of a Control Character, i.e., between 0 and 31.

 

: CONTROL   ( -- n )  

    BL WORD             \ Get next word

    1+ C@  31 AND       \ Convert the first character to a control character

    STATE @             \ Compile or interpret it

    IF [COMPILE] LITERAL   THEN  

    ; IMMEDIATE

 

CRASH   Default routine executed by an un-initialized deferred word.

 

: CRASH ( -- )

    2R@ 2-          \ ES:IP of the current word

    @L >NAME CR .ID         \ Display its name and abort with a message.

    TRUE ABORT" <- is an Uninitialized execution vector." 

    ;

 

?MISSING    Tell user the word does not exist if flag f is true.

 

: ?MISSING  ( f -- )

    IF  'WORD COUNT TYPE    \ Display the parsed string with an error message.

        TRUE ABORT"  <- What? "     \ Used to be " <- huh?, I'm confused." 

    THEN    ;           \    Tom is learning.  Give him some time.

 

'       Return the code field address of the next word in the input stream.

 

: '     ( -- cfa )     

    DEFINED             \ Parse next word and search it in the dictionary.

    0= ?MISSING   ;     \ Return the cfa.  If not found, display error message.

 

[']     Similar to ' but used only in a colon definition while compiling.

 

: [']       ( -- )         

    '               \ Return cfa of next word.

    [COMPILE] <'> X,        \ Compile it as an address literal.

    ; IMMEDIATE         \ Make it immediate

 

[COMPILE]   Force compilation of the following immediate word in a colon definition.  It overrides the rule that an immediate word must execute in a colon definition, thereby allowing it to be compiled now as a regular Forth word and executed at run-time.

 

: [COMPILE] ( -- )         

    '               \ Find cfa of next word, even if it is immediate

    X,                  \ Force its compilation into list.

    ; IMMEDIATE         \ Itself an immediate word

 

 

4.5.   STRING LITERAL COMPILERS

 

 

F-PC uses three different types of string literals: a dot-quote string is compiled in-line with a list of cfa's in the List Space to be typed out at run-time; an x-quote string is compiled in the List Space and copied to "BUF at run-time; and a quote string is compiled to the Code Space, whose address will be returned at run-time.  Putting dot-quote strings in the List Space greatly increases the amount of memory in which user can store large amounts of text data as dot-quote strings, while conserving the code space for executable code.  However, it requires that the quoted strings be used sequentially since there is only one buffer "BUF in the Code Space to hold the string for manipulation.

 

"BUF        A string buffer to store dot-quote strings copied out of the list space.  F-PC compiles ." strings in-line with the cfa's in the word list of a colon definition.  The string is moved into the Code Space for manipulation.

 

VARIABLE  "BUF 132 ALLOT

 

XEVEN   Adjust list dictionary pointer xdp to the next even number.

 

: XEVEN ( xdp -- even-xdp )     DUP 1 AND + ;

 

XALIGN  Align the list dictionary pointer to the 16 bit cell boundary.

 

: XALIGN    ( -- )

    XHERE           \ Current XDP-SEG:XDP

    NIP 1 AND           \ If XDP is odd,

    XDP +! ;            \   increment it to make it even.

 

X>"BUF  Copy an in-line string from List Space to the "BUF buffer in the Code Space.  Leave the address of "BUF on the stack.

 

: X>"BUF    ( -- "BUF )

    2R>             \ Save the return ES:IP from the return stack.  X>"BUF will                     \   be used by (.") which interprets a dot quote string literal.

    2R@             \ Get ES:IP which points to the in-line string.

    2DUP C@L            \ Length of string

    1+ DUP XEVEN        \ Adjust string length for moving

    R> + >R         \ Increase IP to skip the string

    ?CS: "BUF ROT CMOVEL    \ Copy string to X"BUF

    2>R                 \ Restore ES:IP.

    "BUF ;

 

(")     Return the address and length of an in-line quote string, and continue execution after the string.

 

: (")       ( -- addr len )

    2R@             \ Get ES:IP pointing to the next word

    @L              \   which points to the quote string in the code segment

    COUNT           \ Return address and count

    R> 2+ >R ;          \ Increment IP past the string address.

 

(X")        X-quote string interpreter, which copies an x-quote string to the "BUF buffer in the Code Space and returns the address and count of the string in "BUF buffer.

 

: (X")              ( -- addr len )                 X>"BUF COUNT ;

 

(.")        Type an in-line dot-quote string, and continue execution after the string.  It is compiled by the string literal word ." .

 

: %(.")     ( -- )

    2R@            \ Get ES:IP pointing to in-line string.

    2DUP C@L >R         \ Save the string count

    1+ R@  TYPEL        \ Type the string directly out of the list space.

    R> 1+ XEVEN             \ Actual length of compiled string

    R> + >R ;           \ Skip over the string and continue executing next word.

 

DEFER (.")   ' %(.") IS (.")

 

,"      Compile the following quote string till a " to the code dictionary in the Code Space.  Quote-string compiler.

 

: ,"        ( --- )

    ASCII " PARSE       \ Parse the string till " .

    TUCK HERE PLACE         \ Copy string to Word Buffer

    1+ ALLOT ;          \ Allocate dictionary space

 

X,"     Compile the following x-quote string till a " to the list dictionary in the List Space.  X-quote string compiler.

 

: X,"       ( -- )

    ASCII " PARSE       \ Parse string till " .

    HERE PLACE          \ Copy string to Word Buffer

    ?CS: HERE

    DUP C@ 1+ >R        \ Source-addr and actual length

    XHERE R@ CMOVEL     \ Copy to List dictionary

    R> XEVEN XDP +! ;       \ Allocate List space

 

."      Compile the following string till a " as a dot-quote string literal.  Type out the string at run-time.

 

: ."    ( -- )

    COMPILE (.")            \ Compile dot-quote string interpreter first.

    X,"                 \ Compile the dot-quote string, complete the string literal.

    ;   IMMEDIATE       \ Compiler directive.  Must be executed, not compiled.

 

"       Compile the following string as a quote string literal. Return its address and length at run-time.

 

: "     ( -- )

    COMPILE (")         \ Compile quote-string interpreter 

    HERE X,             \ Compile string address to list

    ,"                  \ Compile string to code dictionary

    ;   IMMEDIATE       \ Must be executed

 

""      Force compilation of an x-quote string in the List Space.  At run-time, the string is copied out to "BUF in the Code Space.

 

: ""        ( -- )

    COMPILE (X")            \ Compile an x-quote string interpreter

    X,"                 \ Compile string to List Space

    ;   IMMEDIATE           \ Must be executed

 

">$     Convert the address addr and length count of a quote string created by " into the address of a counted string.  This word relies on the fact that " really creates counted strings, and converts them to address and length on execution.  The string must be either used or moved before another "" string is encountered, or it will be over-written.

 

: ">$       ( addr count -- addr-1 )    DROP 1- ;

 

 

4.6.   FORGET

 

 

FORGET is a very powerful overlay mechanism in Forth.  A portion of the dictionary can be removed and the memory space reclaimed to load other applications.  In F-PC, FORGET is much snorter because the dictionary is partitioned into code, head, and list dictionaries.  All three dictionaries are trimmed back to a given word definition.

 

VARIABLE FENCE  Contains an address below which the dictionary is protected.

 

TRIM        Change the thread pointers in a vocabulary so that they are all less than a specified value, addr.  It trims back the vocabulary to addr.

 

: TRIM      ( addr voc-addr -- )

    #THREADS 0          \ Go through all threads

    DO                  \   in a vocabulary.

        2DUP @      \ Pick up one thread

        BEGIN  

            2DUP U> NOT     \ If link address is greater than   addr,

        WHILE   Y@ \   follow to the next link address

        REPEAT      \ Continue until trimmed to addr

        NIP OVER !      \ Store the last link address into the thread entry.

        2+          \ Do the same for next thread

    LOOP   

    2DROP   ;           \ All done.  Vocabulary trimmed.

 

(FRGET) Forget part of the dictionary.  Both the code address and the header address must be specified, and may be trimmed  independently.  (FRGET) resets all of the links and releases the dictionary space.

 

: (FRGET)   ( code-addr view-addr -- )

    DUP FENCE @         \ Forget below FENCE?

    U< ABORT" Below fence"      \ Not allowed.

    OVER VOC-LINK @         \ First trim the vocabularies

    BEGIN   2DUP U<         \ Vocabulary above code-addr?

    WHILE   @           \ Yes.  Follow to next

    REPEAT          \   vocabulary.

    DUP VOC-LINK !  ( ca va ca pt )     \ Vocabulary trimmed.

    NIP             \ For the remaining vocabularies

    BEGIN   DUP             \ Trim all of them.

    WHILE   2DUP            \ Exit if at end of vocabulary link.

        #THREADS 2* - TRIM   \ Trim one vocabulary

        @               \ Continue to next vocabulary

    REPEAT

    DROP    YDP !           \ Move back the Head dictionary pointer.

    DUP 1+ @ OVER       \ cfa NEST-addr cfa --

    >BODY +             \ Code address of NEST

    (LIT) TRIM          \ cfa of TRIM, a colon definition

    DUP 1+ @ SWAP >BODY +   \ Must also be NEST

    =                   \ If code-addr is a : def

    IF      DUP >BODY @

        +XSEG XDPSEG !      \ Set back XHERE too!

        XDP OFF     \ Trim List dictionary

    THEN    DP !  ;         \ Trim Code dictionary

 

FORGET  Forget all of the code and headers defined after and including <name>.  FORGET must be used with caution; if you DEFER a word that is not forgotten, and vector it to a word that is forgotten, the first call to the original word will cause the system to crash.  Similarly, if you are using DEFERS task chaining, FORGET will not know about these chains, so they must be unlinked before using FORGET or disaster will strike.  Similarly, you have to unlink tasks before forgetting them.  List Space is recovered only if you FORGET colon definitions.

 

: FORGET  <name>    ( -- )

    BL WORD             \ Get next word

    ?UPPERCASE          \ Make sure case-insensitive

    DUP CURRENT @ HASH @    \ Get the CURRENT vocabulary

    (FIND)          \   and locate the word

    0= ?MISSING             \ Abort if word is not in the CURRENT vocabulary

    DUP >VIEW (FRGET) ;     \ Trim the CURRENT vocabulary and other overlapping

                    \   vocabularies.

 

 

4.7.   STRUCTURE COMPILERS

 

 

IF, ELSE,  THEN, DO ?DO, LOOP, +LOOP, BEGIN, UNTIL, AGAIN, REPEAT, and WHILE are compiler directives needed to properly compile classical conditional structures in F-PC.  They are immediate words and they must compile their run-time routines along with whatever addresses they need.  A modest amount of error checking is done.  If you want to rip out the error checking change the ?> and ?< words to > and < words, and all of the 2DUPs to DUPs and the 2SWAPs to SWAPs.  The rest should stay the same.  On the other hand, you can also institute more elaborate error checking like what fig-Forth had by leaving specific error numbers on the stack and checking the numbers to determine if the control structures are properly nested.

 

A global error checking mechanism is built in F-PC using !CSP and ?CSP.  When a colon definition is entered, the stack pointer is saved in the variable CSP by !CSP.  When the colon definition is completed, the contents of CSP is compared with the stack pointer.  Since the compilation of a colon definition should have no effect on the data stack, any discrepancy discovered by ?CSP could only be contributed to errors in building control structures.  This global stack check and the simple structure checking in F-PC are in most cases sufficient to catch control structure errors in a colon definition.

 

DEFER WHERE Locate source code when an error occurred.

 

?ERROR  A deferred word vectored to (?ERROR).  If a true flag is on the top of the data stack, clear the data stack and type the error message located at addr.

 

: (?ERROR)  ( addr len f -- )

    IF              \ If flag is true, reset F-PC.

        2>R             \ Save error message

        SP0 @ SP!           \ Clear the data stack

        PRINTING OFF        \ Don't let printer go wild

        2R> SPACE TYPE SPACE    \ Display the error message

        QUIT            \ Restart F-PC text interpreter

    ELSE    2DROP       \ No error.  Continue.

    THEN  ;

 

(ABORT")    The run-time code compiled by ABORT".  Use ?ERROR to type an error message, and clear the return stack.

 

: (ABORT")  ( f -- )

    ?DUP IF

        X>"BUF          \ Grab the error message

        COUNT           \ Get its count

        ROT ?ERROR          \ Abort if flag is true

    ELSE    2R@ C@L 1+ XEVEN        \ Otherwise, step over the message

        R> + >R         \ Continue executing

    THEN ;

 

ABORT"  Compile the following string as an x-quote string.  If a flag on top of the stack is true at run-time, display the string as an error message and abort; i.e., return to F-PC text interpreter.

 

: ABORT"    ( -- )

    COMPILE (ABORT")        \ Also a string literal

    X,"                 \ Compile x-quote string

    ;   IMMEDIATE       \ Compiler directive

 

ABORT   Clear the data and return stacks and QUIT.  No message is displayed.

 

: ABORT ( -- ) TRUE ABORT" "  ;

 

?CONDITION  Simple compile-time error checking.  It is usually adequate for most situations.  Like F83, F-PC institutes minimal compiler security checks.  A compiler directive starting a control structure would leave a true flag on the data stack at run-time, with other structural information underneath.  The compiler directive resolving the control structure would test this flag.  If the flag is false, the control structure is not properly constructed and the compiler would abort.

 

: ?CONDITION    ( f -- )

    NOT ABORT" Conditionals Wrong"   ;

 

>MARK   Set up a Forward Branch.

 

: >MARK ( -- addr )

    XHERE           \ Get XDPSEG:XDP

    NIP                 \ Discard XDPSEG

    0 X,   ;                \ Compile a dummy address in the list dictionary,

                    \   whose address is left on the stack.

 

>RESOLVE    Resolve a Forward Branch.

 

: >RESOLVE  ( addr -- )

    XHERE           \ Get current list address pair

    -ROT SWAP           \ xhere xdpseg addr --

    !L   ;              \ Store xhere to addr, thus resolve the forward branch.

 

<MARK   Set up a Backward Branch.

 

: <MARK ( -- addr )

    XHERE NIP ;         \ Simply leave the current address on the stack.

 

<RESOLVE    Resolve a Backward Branch.

 

: <RESOLVE  ( addr -- )

    X, ;                \ Compile the addr on stack.

 

?>MARK  Set up a Forward Branch with Error Checking.

 

: ?>MARK    ( -- f addr )

    TRUE                \ Leave a flag for error checking

    >MARK  

 

?>RESOLVE   Resolve a Forward Branch with Error Checking.

 

: ?>RESOLVE ( f addr -- )

    SWAP ?CONDITION         \ Error checking

    >RESOLVE  ;         \ Then resolve the branch

 

?<MARK  Set up for a Backward Branch with Error Checking.

 

: ?<MARK    ( -- f addr )

    TRUE                \ Leave flag

    <MARK   ;           \ Mark current address

 

?<RESOLVE   Resolve a Backward Branch with Error Checking.

 

: ?<RESOLVE ( f addr -- )

    SWAP ?CONDITION         \ Check error

    <RESOLVE  ;         \ Then resolve

 

IF      Select one of two execution pathes.  Used in the form:

        flag IF <true> ELSE <false> THEN

where the ELSE <false> clause is optional.  If flag is false, branches forward to <false> or after THEN.

 

: IF        ( f -- )

    COMPILE  ?BRANCH

    ?>MARK

    ; IMMEDIATE

 

ELSE        Unconditional jump to the word after THEN.  Used in the form:

        flag IF <true> ELSE <false> THEN

If flag is false, branches forward to <false> clause.

 

: ELSE      ( -- )

    COMPILE  BRANCH     \ Compile unconditional branch

    ?>MARK              \ Mark here

    2SWAP           \ Get the marker of IF

    ?>RESOLVE           \ Resolve its forward branch

    ; IMMEDIATE

 

THEN        Terminate a branch structure.  Used in the form:

        flag IF ... ELSE ... THEN

        flag IF ... THEN

: THEN

    COMPILE DOTHEN      \ Compile marker

    ?>RESOLVE           \ Resolve forward jump

    ; IMMEDIATE

 

DO      Initialize a loop structure with index running from index to limit-1.  Used in the form:

        DO ... LOOP

        DO ... +LOOP

 

: DO        ( limit index -- )

    COMPILE (DO)            \ Start do-loop

    ?>MARK          \ Push addr and flag

    ; IMMEDIATE

 

?DO     Same as DO except that the loop will not be executed if index = limit.

 

: ?DO       ( limit index -- )

    COMPILE (?DO) 

    ?>MARK

    ; IMMEDIATE

 

LOOP        Terminate a loop structure.  Increment loop index by one and repeat <loop-body> until loop index crosses the boundary between limit and limit-1.  Used in the form:

        DO <loop-body> LOOP

 

: LOOP      ( -- )

    COMPILE (LOOP)      \ Compile end-of-loop

    2DUP 2+             \ Duplicate address and flag

    ?<RESOLVE           \ Resolve jump from DO

    ?>RESOLVE           \ Resolve jump to DO

    ; IMMEDIATE

 

+LOOP   Terminate a loop structure.  Increment loop index by n and repeat <loop-body> until loop index crosses the boundary between limit and limit - 1.  Used in the form:

    DO <loop-body> n +LOOP

 

: +LOOP ( n -- )

    COMPILE (+LOOP)

    2DUP 2+

    ?<RESOLVE

    ?>RESOLVE    

    ; IMMEDIATE

 

LEAVE   Exit a DO-LOOP immediately.  LEAVE and ?LEAVE could be non-immediate in this system, but the Forth-83 Standard specifies an immediate LEAVE, so they both are defined as immediate words for compliance and uniformity.

 

: LEAVE             \ Exactly equivalent to (LEAVE)

    COMPILE (LEAVE)

    ; IMMEDIATE

 

?LEAVE  Immediately exit a DO-LOOP if the flag is true; else continue looping.

 

: ?LEAVE

    COMPILE (?LEAVE)

    ; IMMEDIATE

 

BEGIN   Start an infinite or indefinite loop.  Used in the form:

        BEGIN ... AGAIN

        BEGIN ... flag UNTIL

        BEGIN ... flag WHILE ... REPEAT

 

: BEGIN

    COMPILE DOBEGIN     \ Mark the beginning of loop

    ?<MARK          \ Leave address and flag on stack

    ; IMMEDIATE

 

UNTIL   Mark the end of a BEGIN ... UNTIL loop.  Terminate the loop if flag f is true.

 

: UNTIL ( f -- )

    COMPILE ?UNTIL

    ?<RESOLVE           \ Backward jump to BEGIN

    ; IMMEDIATE

 

AGAIN   Unconditional jump to just after BEGIN in an infinite loop:

        BEGIN ... AGAIN

 

: AGAIN ( -- )

    COMPILE  DOAGAIN        \ Unconditional jump

    ?<RESOLVE           \   back to BEGIN

    ; IMMEDIATE

 

WHILE   Conditional exit from a  BEGIN...REPEAT loop.  Used in the form:

        BEGIN <loop> flag WHILE <true> REPEAT

Repeat <loop> and <true> clauses while the flag is true or non-zero.  Exit loop if flag is false.

       

: WHILE ( f -- )

    COMPILE ?WHILE

    ?>MARK

    ; IMMEDIATE

 

REPEAT  Unconditional backward branch to just after BEGIN in an indefinite loop:

        BEGIN  <loop>  flag WHILE  <true>  REPEAT

 

: REPEAT    ( -- )

    2SWAP           \ Resolve backward jump first

    COMPILE DOREPEAT        \ Mark end of loop

    ?<RESOLVE           \ Backward jump to BEGIN

    ?>RESOLVE           \ Forward jump from WHILE

    ; IMMEDIATE

 

The following structure related words were suggested by Bill Muench to extend the classic Forth structures.  They give the user much flexibility in exiting a loop under various conditions and are useful in cases where the classic structures are too restrictive.

 

FORWARD Unconditional forward branch.  Use it very carefully because the words following may not get executed at all.

 

: FORWARD       ( -- )

    COMPILE BRANCH      \ Similar to IF, except using unconditional jump.

    ?>MARK

    ; IMMEDIATE

 

CONTINUE    Unconditional jump back to BEGIN to repeat a loop.

 

: CONTINUE      ( -- )

    2OVER           \ Preserve the marks left by BEGIN.

    [COMPILE] REPEAT        \ Jump back.

    ; IMMEDIATE

 

BREAK   Used as THEN with IF, in an IF...BREAK phrase to exit a word.

 

: BREAK         ( -- )

    COMPILE EXIT        \ Terminate a colon word prematurely.

    [COMPILE] THEN      \ Complete the IF...BREAK structure.

    ; IMMEDIATE

 

AFT     Cause the words between BEGIN and AFT to be executed only once in a BEGIN ...UNTIL/REPEAT loop.

 

: AFT           ( -- )

    2DROP           \ Discard address and flag left by BEGIN.

    [COMPILE] FORWARD   \ Compile a forward jump

    ?<MARK 2SWAP        \ Leave its own marks for end-loop words to resolve

    ; IMMEDIATE

 

FOR     Start a single index decrementing loop.  Used with NEXT in the following fashion:  n  FOR  ...  NEXT .  Repeating index n is pushed on the return stack.  This loop structure was recently advocated by Chuck Moore because FOR and NEXT are native machine instructions of the NC4000 Forth chip.

 

: FOR           ( n -- )

    COMPILE >R          \ Push loop index on the return stack.

    ?<MARK          \ Leave marks for NEXT to resolve.

    ; IMMEDIATE

 

NEXT        Decrement the count on the return stack.  If the count becomes negative, exit the FOR...NEXT loop and discard the count.  If the count is not negative, jump to the word after FOR.

 

: NEXT          ( -- )

    COMPILE NEXT|       \ Compile low level loop function.

    ?<RESOLVE           \ Resolve jump address to FOR.

    ; IMMEDIATE

 

 

4.8.   COLON AND OTHER COMPILERS

 

 

,VIEW   Compile the view field in a header.

 

: ,VIEW ( -- )

    LOADLINE @          \ Byte offset of current line in the file under loading

    Y, ;                \ Lay down the view field

 

"HEADER Compile the following string to make a header, and initialize the code field.  First check for duplicated name and make an entry in >NAME hash table if appropriate.  Next lay down the view field and link it to the correct thread and build the link field.  Set up LAST so that it points to the new name  field.  Copy the name to YSEG and delimit the name field bits.  Compile the code field address into the code pointer field in the YSEG.  Finally add a stopper entry to >NAME hash table in case of a large ALLOT or at the end of dictionary.  It does all of its work in the Head Space, and has no effect on Code Space whatsoever.

 

A few words are split out for optimization.  The critical path is coded in assembly.  Non-critical parts are coded in high level.

 

: NOHEADROOM    ( --- )

    TRUE ABORT" Out of HEAD memory!" ;

 

: NOLISTROOM    ( --- )

    TRUE ABORT" Out of LIST memory!" ;

 

CODE SPCHECK    ( -- f1 f2 )    \ Head and List space check

    MOV AX, YDP         \ Get head DP

    SHR AX, # 1         \ Convert to segment

    SHR AX, # 1

    SHR AX, # 1

    SHR AX, # 1

    ADD AX, # 6         \ Add 6 segments for head room

    CMP AX, ' #HEADSEGS >BODY   \ Are we out of space yet?

    >  IF                   \ If so, abort.

        MOV AX, # ' NOHEADROOM

        JMP AX

    THEN

    MOV AX, XDPSEG      \ Load List segment

    SUB AX, XSEG        \ Convert to size of list so far

    ADD AX, # 6         \ Add 6 for head room

    CMP AX, ' #LISTSEGS >BODY  \ Are we out of List space yet?

    >  IF               \ Yes.  Abort.

        MOV AX, # ' NOLISTROOM

        JMP AX

    THEN

    NEXT                \ Everything in order.

    END-CODE

 

: %ALREADY_DEF      ( a1 -- a1 )   \ Is the word at A1 already defined?

    WARNING @

    IF      DUP FIND NIP

        IF      DUP  CR  COUNT TYPE ."  isn't unique "

        THEN

    THEN    ;       ( str )

 

: "HEADER   ( str-addr -- )

    SPCHECK         \ Check Head and List Spaces

    DUP C@ 31 >         \ Name too long?

    ABORT"  Name TOO LONG, > 31 chars!"

    /ALREADY_DEF

    ALIGN

    YHERE 2- Y@             \ cfa of last word

    CNHASH          \ Head hash table entry

    HERE CNHASH  <>     \ Is it the same as the entry for current code word?

    IF  YHERE HERE CNHASH   \ No.  Update hash entry

        DUP Y@ ROT UMIN SWAP    \ Find the minimum head address

        Y!          \   store it in hash entry

    THEN

    ,VIEW               \ Lay down the view field

    YHERE OVER CURRENT @    \ Get CURRENT vocabulary

    HASH DUP @  Y,      \ Lay the link field.  Update thread in CURRENT

    YHERE LAST !        \ Remember nfa

    YHERE ?CS: ROT      \ yhere cs str --

    DUP C@  WIDTH @ MIN \ Length of name

    1+ >R               \ yhere cs str --

    YHERE YS: R@ CMOVEL \ Copy string to name field

    R> YDP +! ALIGN     \ Allocate name field

    128 SWAP YCSET      \ Delimit count byte in name

    128 YHERE 1- YCSET      \ Delimit last byte in name

    HERE Y,         \ Lay code pointer field

    YHERE HERE CNHASH 2+ Y! \ Valid stopper in next hash entry

    ;

 

,CALL   Compile a CALL to address 0.  The actual subroutine address is set later by ;USES or ;CODE.  See CREATE, VARIABLE, CONSTANT and : .  CALL pushes the parameter field address or the address of BODY on the data stack, which is quite convenient if we have to access data stored in the parameter field. 

 

: ,CALL

    232 C,              \ Assemble an 8088 machine instruction CALL, decimal 232.

    0 HERE 2+ - ,           \ Assemble a dummy address 0000

    ;

 

,JUMP   Assemble a JMP 0 instruction in the code field.  The address 0 will be patched with the address of an inner interpreter.

 

: ,JUMP

    233 C,              \ Assemble a JMP instruction, which is decimal 233.

    0 HERE 2+ - ,           \ Assemble dummy address 0

    ;

 

HEADER  Create a named header in the Head Space, but compile absolutely nothing in Code Space.  The code pointer field in the head thus created does point at HERE though.  It is a deferred word vectored to <HEADER>.

 

: <HEADER>  ( -- )

    BL WORD         \ Get next word in the input stream

    ?UPPERCASE          \ Make it upper case if so desired

    "HEADER ;           \ Build a header

 

DEFER HEADER    ' <HEADER> IS HEADER

 

CREATE  Make a header for the next word in the input stream.  The word created by CREATE returns its parameter field address on the data stack due to CALL which thinks that the F-PC data stack is its return stack.

 

: CREATE <name> ( -- )

    ,CALL           \ Assemble CALL 0

    ;USES >NEXT ,-X     \ Patch 0 to >NEXT, which does nothing.  However, CALL

                    \   pushes pfa or BODY address on data stack.

 

: "CREATE       ( str-addr -- ) \ Compile a header with the name at str-addr. 

    "HEADER             \ Build a header

    ,CALL           \ Assemble CALL 0

    ;USES >NEXT ,-X    

 

!CSP        Save current stack pointer in CSP for ?CSP to check if the stack is disturbed.

 

: !CSP          ( -- )      SP@ CSP !   ;

 

?CSP        Compare the current data stack pointer with the contents saved in CSP.  Abort if they are not equal, indicating compilation error.

 

: ?CSP      ( -- )

    SP@ CSP @ <>        \ Compare stack pointer and CSP

    ABORT" Stack Changed"       \ Abort if not equal

    ;

 

HIDE        Remove the last definition from the Header Dictionary.  In F83, HIDE smudges the last header and makes it invisible to FIND because of the smudge bit in the first byte of the name field.  This technique works but it leaves garbage headers in the dictionary.  HIDE in F-PC actually un-links the last header from the current vocabulary, resulting in a clean header dictionary.

 

: HIDE      ( -- )

    LAST @          \ Name field address of last word

    DUP N>LINK Y@       \ Find link field address of next word in the thread

    SWAP CURRENT @      \ Thread head in CURRENT

    YHASH ! ;           \ Re-link to remove last word from current vocabulary

 

REVEAL  Activate the last definition in the Header Dictionary by re-linking it to the current vocabulary.  Remove the effects of HIDE.  See HIDE for difference between F-PC and F83.

 

: REVEAL    ( -- )

    LAST @ DUP N>LINK       \ Lfa of last word

    SWAP CURRENT @      \ Thread in CURRENT vocabulary

    YHASH ! ;           \ Link last word into CURRENT vocabulary, thus reveal it.

 

;USES       Similar to the traditional ;CODE except that it is used when the run-time code or the inner interpreter has been previously defined already.  It sets the code field of current word to the contents of following cell.

 

: (;USES)   ( -- )

    2R> SWAP @L         \ Fetch contents of next cell, address of an interpreter

    LAST @ NAME>        \ Get code field address of the last word

    DUP >R 3 + -            \ Patch the address of JMP or

    R> 1+ ! ;           \   CALL in the code field

 

(;CODE) Set the code field of the current word under construction to the address of the following routine coded in assembly which is the inner interpreter of this type of word.

 

: (;CODE)   ( -- )

    2R> SWAP @L         \ Fetch contents of next word

    LAST @ NAME>        \ Get its code field address

    DUP >R

    232 ( CALL ) R@ C!          \ Assemble a CALL not JUMP

    3 + - R> 1+ !  ;            \   to the inner interpreter

 

DOES>   Specify the run-time behavior of a defining word in high level Forth.  It is similar to ;CODE but defines the inner interpreter using high level Forth word sequence, making the code easy to write and portable to other Forth systems.

 

: DOES>     ( -- )

    COMPILE (;CODE)     \ Mark the inner interpreter

    HERE X,         \   and its code field address

    232 ( CALL ) C,     \ Start the inner interpreter with CALL DODOES

    [ [FORTH] ASSEMBLER DODOES META ]  

                    \ Find the address of DODOES in ASSEMBLER vocabulary.

    LITERAL         \ Make it a literal to compile daughter words

    HERE 2+ - ,         \ Assemble the relative address

    XHERE PARAGRAPH +   \ Justify the list dictionary

    DUP XDPSEG !        \   segment pointer

    XSEG @ - ,          \ Compile the segment offset in the BODY of the daughter                        \   word so it can find its interpreter in the List Space.

    XDP OFF ; IMMEDIATE \ Clear list offset pointer ready to compile the inner

                    \   interpreter in high level.

]       The Compiler Loop.  First set Compile State.  Look up the next word in the input stream and either execute it if it is an immediate word, or compile it if it is not an immediate word.  If the word is not in the dictionary, convert it to a number, either single or double precision depending on whether or not any punctuation was present.  Continue until the input stream is exhausted or the compilation STATE is changes.

 

: (])       ( -- )

    STATE ON            \ Turn on compilation flag

    BEGIN   ?STACK      \ Check the stacks

        DEFINED DUP     \ Find the next word in input

        IF  0>              \ Immediate word?

            IF  EXECUTE     \ Yes.  Execute it.

            ELSE    X,          \ No.  Compile it.

            THEN

        ELSE DROP               \ Not a valid word.

            NUMBER          \ Convert it to a double integer

            DOUBLE?         \ Any punctuation marks?

            IF  [COMPILE] DLITERAL  \ Yes.  Compile double.

            ELSE    DROP            \ No.  Compile single.

                [COMPILE] LITERAL

            THEN

        THEN

        TRUE DONE?      \ Input exhausted?

    UNTIL   ;           \ Yes. Exit. Otherwise, compile the next word.

 

DEFER ]         ' (]) IS ]

 

MAKEDUMMY   Make a dummy colon definition using next word as its name.  It is effectively a NOOP, used by ANEW for forgetting words before recompiling a file.

 

: MAKEDUMMY ( -- )      \ MAKEDUMMY <word> <enter>

    HEADER          \ Build a header

    ,JUMP               \ Compile JMP in code field

    XHERE PARAGRAPH +   \ Absolute paragraph of new def

    DUP XDPSEG !        \ Set new XHERE segment

    XSEG @ - ,          \ Compile relative paragraph of def

    XDP OFF         \ Clear List offset

    COMPILE UNNEST      \ End it like a colon word

    ;USES  NEST ,-X     \ Install colon interpreter as its own interpreter.

 

ANEW    Define a NEW dummy definition.  If the word already exists, then forget it before making a new one.  A nice utility to allow re-compiling a file again and again for debugging purposes.  This technique, attributed to Ray Isaac at Calos, is a real neat trick.

 

: ANEW  ( -- )          \ ANEW <word> <enter>

    >IN @ >R            \ Save interpreter pointer to re-read the word name

    DEFINED NIP         \ Is if already defined?

    R@ >IN !            \ Restore >IN pointer

    IF FORGET THEN      \ Forget it if defined.

    R> >IN !            \ Make a new definition.

    MAKEDUMMY   ;

    XHERE PARAGRAPH +   \ Justify List dictionary pointers

    DUP XDPSEG !

    XSEG @ - ,

    XDP OFF

    HIDE                \ Hide the header

    ;USES   NEST ,-X        \ Install colon interpreter

 

: : ( -- )  (:) ]  ;

RUN     This is the F-PC operating system used in QUIT (see Sec. 5.3).  Interpret or compile whatever is in the Terminal Input Buffer.  Test the system variable STATE, and do the appropriate thing (interpret or compile).  If STATE is ON, compile the words in the input buffer to the dictionary; otherwise, execute them.

 

: <RUN>             ( -- )

    STATE @         \ In compiling state?

    IF  ]           \ Yes.  Compile text in TIB.

        STATE @ NOT     \ End of line.  Test again.

        IF INTERPRET THEN   \ Interpret if STATE changes.

    ELSE    INTERPRET THEN  \ Interpreting state.  Interpret text in TIB.

    ;
