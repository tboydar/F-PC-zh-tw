CHAPTER 5.   SYSTEM INITIATION

 

 

 

 

 

KERNEL4.SEQ is the last kernel file.  The most important part in this file is the initialization of the F-PC system.  F-PC is saved as an EXE file under DOS.  It contains the code dictionary, the head dictionary, and the list dictionary.  These dictionaries must be moved to their appropriate segments and then the F-PC can be booted.  Many system and user variables must also be initialized to proper values for F-PC to operate.

 

Many loose ends left over by the meta compiler will also have to be tied together.  Forward references must be resolved.  Deferred words must be vectored to executable words.  Lastly, the target core image must be saved in an EXE file so that the kernel can be booted and executed later.

 

There are also a number of utility words included in this file.  Some of them are provided for debugging purposes.  The decompiler and a fully featured debugger will be loaded on top of the kernel later as tools.  However, some minimal debugging facility is handy in case there are problems with the kernel and higher level utilities cannot be loaded successfully.

 

 

5.1.   USER VOCABULARY

 

 

Forth has always been a multi-tasking, multi-user system from its beginning.  There are two very important concepts which make it very easy for Forth to support multi-tasking: re-entrancy of Forth code and the user area.  All the resources and information specific to a user or task are isolated and put into the user area.  Forth words in the dictionary are fully re-entrant so that the same set of words can be used by all tasks or users.  Thus each task can operate independent of each other while sharing all the tools and utilities from a centralized dictionary.  A multi-tasking Forth system does not require huge amounts of memory and can switch among the tasks at very high speed.

 

The user area contains the following resources: a data stack, a return stack, optional dictionary extend memory, input and output buffers, and a set of user variables.  The user variable area can also hold user deferred words.  The same user deferred word can be vectored to different words in different tasks.  F-PC uses the same names VARIABLE and DEFER to define user variables and user deferred words.  They are redefined and collected in the USER vocabulary so that they can be used to define user variables and user deferred words.  This section describes all the words defined in the USER vocabulary.

 

#USER  Count of how many user variables are defined in the current system.  It is incremented when a new user variable is defined.  F-PC leaves space for 10 more user variables to be added by user.

 

VARIABLE #USER

 

USER   Vocabulary that holds versions of defining words which define new user variables and user deferred words.  They have the same names as those in the FORTH vocabulary, but may have different functions in different tasks.

 

VOCABULARY USER         \ Create USER vocabulary

USER DEFINITIONS            \ The following words are compiled into the USER vocabulary

 

ALLOT   Allocate some space in the user area for a task.  When used with CREATE, you can define arrays this way.  However, be aware that F-PC gives you only 20 bytes in the user area.  It can be enlarged by adding more memory space in the system user variable area at the end of KERNEL4.SEQ and modifying the words which define tasks in MULTASK.SEQ.

 

: ALLOT ( n -- )

    #USER +!            \ Add n to #USER

    ;

 

CREATE  Define a word that returns the address of the next available memory location in the user area.

 

' CREATE                \ Get the address of the regular CREATE for ,-X in this

: CREATE    ( -- )          \    CREATE to avoid recursion.

    [ ,-X ]             \ Compile addr of the regular CREATE

    #USER @ ,           \ Compile the user area pointer

    ;USES 

    DOUSER-VARIABLE ,-X \ Install DOUSER-VARIABLE as its inner interpreter

 

VARIABLE    Define a user variable.  Allocate two bytes in the user area.  When the user variable is executed, the address of that location in the user area is returned.

 

: VARIABLE  ( -- )

    CREATE          \ New user CREATE just defined

    2 ALLOT   ;         \ User ALLOT

 

DEFER   Define an execution vector that is local to every task.  The same user deferred word can be vectored to different words in different tasks.

 

: DEFER ( -- )

    VARIABLE            \ Define it as a user variable

    ;USES

    DOUSER-DEFER ,-X        \ Install the user defer inner interpreter

 

 

5.2.   IS AND SELECT

 

 

These two words are not related to each other and to the words before and after them.  It would probably be a good idea to move these words to Section 5.6 as miscellaneous utility words.  However, in order not to disturb the loading sequence of words in the F-PC kernel, a little section is opened here for them.

 

IS is used to assign an actual function to a deferred word.  It is built so that it can be used interactively or in a colon definition.  It is very convenient to the user but not quite along the thinking of Forth-83, which demanded the separation of  interpretive behavior and compiling behavior into separate words like ' and ['] .  Since IS is not a Forth-83 standard word, it is exempted from this restriction.

 

SELECT is used to define words to select different drives in the DOS system.

  

>IS     Map a code field into a parameter field.  If the word is in the USER class of words, then the parameter field address must be calculated relative to the current user pointer.  Otherwise it just returns the parameter field address.

 

FORTH DEFINITIONS           \ Return from USER to compile FORTH

META IN-META            \   words to the target system

 

: >IS       ( cfa -- pfa )

    DUP 1+ @            \ Fetch the relative jump address

    OVER >BODY +        \ Compute the absolute jump address

    DUP [  [ASSEMBLER] DOUSER-VARIABLE META ] LITERAL = SWAP

                    \ Is it a user variable?

    DUP [  [ASSEMBLER] DOUSER-DEFER    META ] LITERAL = SWAP

    DROP OR         \ Or perhaps a user deferred word?

    IF   >BODY @ UP @ +     \ Either way, find the actual address in the user area

    ELSE    >BODY       \ Otherwise, move to parameter field

    THEN   ;

 

(IS)        The code compiled by IS.  Set the execution address of the following DEFERred word to the address on the data stack.

 

: (IS)      ( cfa --- )

    2R@  @L         \ Fetch cfa of next word in list

    >IS !               \ Store cfa in its parameter field

    R> 2+ >R   ;            \ Bump IP, which passes the next word

 

IS      Depending on STATE, either set the following DEFERred word immediately or compile the setting for later resolution.

 

: IS        ( cfa --- )

    STATE @         \ If compiling,

    IF  COMPILE (IS)        \   compile (IS) which will resolve next word at run-time.

    ELSE  ' >IS !           \ Else, resolve it now.

    THEN ; IMMEDIATE

 

SELECT  Select drive n as the current disk drive to use as the DEFAULT drive when no drive is specified.  N ranges from 0 which is drive A:, to a legal value up to 255.

 

: SELECT    ( n -- )

    14 bdos drop        \ Select drive

    SEQHANDLE >hndle @ -2 = \ If Handle field in current file is -2,

    if -1 SEQUANDLE >hndle !    \   change it to -1.

    then    ;

 

: A:                ( --- )             0 SELECT ;

: B:           ( --- )             1 SELECT ;

: C:                ( --- )             2 SELECT ;

: D:                ( --- )             3 SELECT ;

 

Select drive A:, B:, C:, or D: as the default drive.

 

 

5.3.   F-PC BOOT SYSTEM

 

 

The operating system of F-PC is the Text Interpreter INTERPRET, which accepts user commands from a keyboard and executes them in an input-execute infinite loop.  The Boot System is the part of the code which takes the object image in a DOS .EXE file, loads it into memory, and sets up things so that the F-PC Text Interpreter can be brought up alive.  The Head and List Segments must be moved to their appropriate locations in the DOS memory map.  All registers, variables, and vectored words must be initialized with their proper values.  All these activities must be performed at the machine code level until the Forth word COLD is executed, which brings up the Text Interpreter.  This section contains all the high level words taking F-PC from COLD to INTERPRET.  In the next section we will see all the low level code needed to boot F-PC up to COLD.

 

Another important task at boot time is to set up the interrupt system so that DOS and F-PC can pass control from one to the other smoothly.  F-PC thus has to save the Control Break and Divide by 0 interrupt vectors and install its own interrupt handlers.  The DOS interrupt handlers must be restored before passing control back to DOS.  These things if handled improperly will prevent an application from being smoothly integrated into the DOS environment.  F-PC is very careful in this respect.  The boot-up code is thus worthy of studying to learn how to do this DOS integration.

 

QUIT        The main loop in Forth.  Get more input from the terminal and interpret it.  Respond with 'ok' if all input commands are executed successfully.  This is often called the Forth Text Interpreter Loop, where user gives commands via the terminal keyboard.  The Text Interpreter carries out these commands and comes back for more.  Forth is running this loop until the power is turned off or it is forced to execute a BYE command to go back to DOS.

 

: QUIT      ( -- )

    SP0 @ 'TIB !            \ Select terminal input buffer

    [COMPILE] [         \ Start interpreting

    BEGIN               \ Outer loop

        BEGIN           \ Inner loop

            RP0 @ RP!   \ Initialize the return stack

            STATUS  \ Display system status

            QUERY   \ Wait for a line of commands

            RUN     \ Execute them

            STATE @ NOT \ If still interpreting,

        UNTIL           \   exit to the outer loop.

                    \   Remain in inner loop to do compiling.

        ."  ok"         \ Display 'ok' message and

    AGAIN  ;            \   loop back again.

 

BOOT      A high level word executed during cold start.  User may install functions into BOOT that he wants done when F-PC is loaded.

 

DEFER BOOT              \ Vectored to START in Sec. 5.7.

 

INITSTUFF   A deferred word chain, used by many system utilities that need to specify a function to be performed at cold start time.

 

DEFER INITSTUFF   ' SEQINIT IS INITSTUFF    \ See Sec. 6.5 for SEQINIT.

 

SEGSET  A deferred word that contains the current function used to set up the segment registers at cold start time.  It typically contains SETYSEG.

 

DEFER SEGSET      ' SETYSEG IS SEGSET

 

WARMSTRT    The default function to be performed on a WARM start.  This word is plugged into the deferred word WARMFUNC, to specify what is done when the CONTROL BREAK key is pressed.  See also WARMFUNC and WARM below.

 

: WARMSTRT  ( -- )

    FORTH           \ Select FORTH as the context vocabulary

    TRUE ABORT" Warm Start" \ Abort

    ;

 

WARMFUNC    A deferred word that is invoked when a warm start occurs.  This function is also called whenever the CONTROL BREAK key is pressed.

 

DEFER WARMFUNC  ' WARMSTRT IS WARMFUNC

 

WARM    The WARM entry point for Forth.  It simply calls the deferred word WARMFUNC.  A warm start is invoked whenever the CONTROL BREAK key is pressed.

 

: WARM  ( -- )

    [ LABEL WARMBODY ]  \ Reference point for warm start for assembly code

    WARMFUNC ;          \ Do all the warm start functions

 

COLD        The high level cold start code.  To activate Forth, BOOT should initialize the virtual Forth Machine and pass control to QUIT.

 

: COLD      ( -- )

    [ LABEL COLDBODY ]      \ Reference point of cold start for assembly code

    1STCODE         \ Only do this stuff once on cold start

    IF  SEGSET      \ Initialize the segments.  If heads and lists are not moved

                    \   to proper locations, move them.

        VMODE.SET       \ Select the CRT display mode

        INITSTUFF       \ Do other initiation functions

    THEN

    %OFF> 1STCOLD       \ Turn value in 1STCOLD off

    BOOT                \ Initialize Forth registers and user initiation work

    QUIT   ;            \ Fall into Text Interpreter

 

 

5.4.   F-PC INITIALIZATION

 

 

The initialization process consists of all the code from the JMP CORIG at the very beginning of the F-PC code to the high level word COLD.  This process in F-PC is more complicated than other PC Forth systems because of the segregation of lists and heads from the code and data.  The code also provides much insight into how F-PC is constructed and some of its unique characteristics.

 

START   Initialize the user variables needed by the Text Interpreter.  BOOT is vectored to START.  (See Sec. 5.7).

 

: START ( -- )

    SP0 @ 'TIB !            \ Terminal Input Buffer is placed above the data stack.

    >IN OFF         \ Clear interpreter pointer

    SPAN OFF            \ Clear input character count

    #TIB OFF            \ Clear input buffer length

    LOADING OFF         \ Clear file loading flag

    DEFAULT         \ Handle command line input from DOS

    INTERPRET ;             \ Execute user commands

 

RESTORE_VECTORS Restore the CONTROL BREAK and DIVIDE by 0 DOS interrupt vectors to their original value as when Forth was first entered.  The CONTROL BREAK and DIVIDE by 0 vectors are saved by the assembly language cold start routines before Forth is entered.

 

HEX

VARIABLE BIOSBKSAVE  0 ,-T      \ Save DOS control break vector

VARIABLE DIV0SAVE    0 ,-T      \ Save DOS divide by 0 vector

 

CODE RESTORE_VECTORS    ( --- ) \ Restores the saved vectors to their saved values. 

                    \ This word is called just prior to returning to DOS.

    MOV AX, CS          \ Make DS=CS

    MOV DS, AX

    MOV DX, CS: BIOSBKSAVE  \ Get CS part of saved vector

    MOV DS, CS: BIOSBKSAVE 2+ \ Get the PC part of saved vector

    MOV AX, # 251B      \ Ask DOS to restore the control

    INT 21              \   break interrupt vector

    MOV AX, CS          \ Re-initialize DS to CS

    MOV DS, AX

    MOV DX, CS: DIV0SAVE    \ Get saved CS

    MOV DS, CS: DIV0SAVE 2+ \ Get saved PC

    MOV AX, # 2500      \ Ask DOS to restore divide by 0

    INT 21              \   interrupt

    MOV AX, CS          \ Restore DS again

    MOV DS, AX

    NEXT

    END-CODE

 

DIV0STRT    The default function to perform when a DIVIDE BY 0 trap occurs.  This routine does an ABORT.  A divide by 0 trap calls DIV0FUNC, which is vectored to this routine.

 

: DIV0STRT  ( -- )

    TRUE ABORT" Divide OVERFLOW error" ;

 

DIV0FUNC    Divide by 0 error causes a trap to the interrupt vector 0, which calls this deferred word.  You can change the contents of this deferred word to handle divide by 0 errors in your own program.

 

DEFER DIV0FUNC  ' DIV0STRT IS DIV0FUNC

 

BYEFUNC A deferred word which normally contains NOOP, provided a mechanism for you to specify functions to be performed before leaving F-PC back to DOS.

 

DEFER BYEFUNC   ' NOOP IS BYEFUNC

 

BYE     Return control to DOS.  Perform the deferred word BYEFUNC and restore the control break and divide by 0 interrupt vectors before actually leaving.

 

: BYE       ( -- )

    RESTORE_VECTORS

    BYEFUNC         \ Bye task chain

    ." Leaving.." CR

    0 0 BDOS  ;         \ Exit to DOS

 

DIVIDE0 The actual entry point of the divide by 0 trap.   This word just calls the deferred word DIV0FUNC.  Normally the registers on the stack are simply discarded, but you can install your own routine into DIV0FUNC to handle the divide by 0 error.

 

: DIVIDE0   ( STATUS_reg, CS, IP, AX, BX, CX, DX, SI, BP --- )

    [ LABEL DIV0BODY ]

    DIV0FUNC            \ Abort to QUIT as default

    BYE ;               \ This word is generally not seen by F-PC, unless you

                    \   re-vectored DIV0FUNC.

 

LABEL DIV0BK            \ Handle a Divide by 0 interrupt

    STI             \ Set flag to enable interrupts

    PUSH AX         \ Push all relevant registers

    PUSH BX         \   on the data stack

    PUSH CX

    PUSH DX

    PUSH SI

    PUSH DI

    PUSH BP

    MOV AX, # DIV0BODY 5 -  \ Jump to DIVIDE0 above the F-PC way.

    JMP AX             

    END-CODE

 

TRUE VALUE RESTNEXT     \ A flag to determine if we want the next code restored.

 

LABEL SETBRK            \ Set control break to do warm start

    PUSH ES         \ Save ES.  Need it for list addressing

    MOV AX, CS          \ DS=CS

    MOV DS, AX

    CMP ' RESTNEXT >BODY # 0 WORD   \ If RESTNEXT is NOT = 0

    0<> IF  MOV AX, # AD26  \ LODSW ES: in >NEXT

        MOV >NEXT AX    \ Restore it

        MOV AX, # E0FF  \ JMP AX    in >NEXT + 2

        MOV >NEXT 2+ AX \ Restore it

    THEN

    MOV DX, # BIOSBK

    MOV AX, # 251B      \ Install BIOS Break 1B

    INT 21

    MOV DX, # DOSBK

    MOV AX, # 2523      \ Install DOS Break 23

    INT 21

    MOV DX, # 1

    MOV AX, # 3301      \ Enable DOS Break

    INT 21

    MOV DX, # DIV0BK

    MOV AX, # 2500      \ Install DIV by 0 Break 0

    INT 21

    POP ES          \ Restore ES

    RET                 \ Done

    END-CODE

 

LABEL SAVEVECTORS       \ Save Divide by 0 & Ctrl Brk vectors for now.

    PUSH ES

    MOV AX, # 351B      \ Get the interrupt vector for

    INT 21              \   BIOS control break vector

    MOV BIOSBKSAVE BX       \ Save PC vector

    MOV BIOSBKSAVE 2+ ES    \ Save CS vector

    MOV AX, # 3500      \ Get the interrupt vector for

    INT 21              \   DIVIDE by 0

    MOV DIV0SAVE BX     \ Save PC vector

    MOV DIV0SAVE 2+ ES      \ Save CS vector

    POP ES

    MOV AX, # $3300     \ Control BREAK flag status

    NT $21

    SUB DH, DH

    MOV CTRLBKSAVE DX   \ Save it away for later restoration

    RET

    END-CODE

 

SET_VECTORS Set the CONTROL-BREAK and DIVIDE-BY-0 traps to point to the functions provided by F-PC, so we can handle them smoothly.

 

DECIMAL

CODE SET_VECTORS    ( --- )

    CALL SETBRK         \ Define as a subroutine

    NEXT

    END-CODE

 

CODE @REL>ABS   ( a1 --- a2 )   \ Convert JMP address in a1+1 to an absolute memory address

    POP BX

    ADD BX, 1 [BX]

    ADD BX, # 3

    PUSH BX

    NEXT

    END-CODE

 

WORIG   The warm start routine which is entered when the user pushes the Control Break key on the keyboard.  This generally allows F-PC to recover if it is trapped in an infinite loop or doing some very time-consuming task.  The warm start can recover only if the F-PC system is intact.  If the List Segment or the Code Segment were written over, F-PC would not be able to recover.  If the Head Segment was written over, F-PC will still respond to carriage-returns, but it will not be able to find words in the dictionary.  Under these circumstances, using Alt-Ctrl-Del or hitting the power switch are the only alternatives.

 

[FORTH] ASSEMBLER

LABEL WORIG

    HERE ORIGIN 6 + -       \ Patch ORIGIN with warm start

    ORIGIN 4 + !-T          \   address

    MOV AX, # WARMBODY 5 -  \ Jump to WARMBODY

    JMP AX

    END-CODE

 

CORIG   The cold start routine which builds the F-PC from the loaded target core image.  The Head dictionary is moved to the Head Segment and the List dictionary is moved to the List Segment.  All Forth registers and pertinent user and system variables are initialized.  Finally, COLD is executed and the Forth Text Interpreter is invoked to take commands from the user.

 

LABEL CORIG             \ Cold start routine

    HERE ORIGIN 3 + -       \ Patch ORIGIN with cold start

    ORIGIN 1+ !-T           \   address

    MOV AX, CS          \ Initialize DS and SS segment registers to CS

    MOV DS, AX

    MOV SS, AX

    MOV BX, YSTART      \ Read YSTART the relocate flag

    OR BX, BX           \ If not reset, then move head stuff

    0<> IF

        ADD AX, ' #CODESEGS >BODY   \ Add Code segments and

        ADD AX, ' #LISTSEGS >BODY       \   List segments to get to head space.

        MOV ES, AX      \ Move Head segment to ES

        MOV CX, YDP     \ Bytes in head dictionary

        MOV DI, # 0     \ Clear DI

        MOV SI, YSTART  \ Move YSTART to SI

        OR CX, CX 0<>   \ If YDP was not zero (0)

        IF  CLD

            REPZ

            MOVSB   \ Move heads to Head Space

            CLD

        THEN

        MOV YSEG ES     \ Initialize YSEG to base of Head Space

    THEN

    MOV BX, XMOVED      \ Has LIST been moved?

    OR BX, BX           \ If not, then move List Segments.

    0= IF

        MOV AX, DS      \ Copy DS (CS) to AX

        ADD AX, ' #CODESEGS >BODY   \ Add Code Segments

        MOV ES, AX      \ Copy Head Segment base to ES

        MOV CX, XSEGLEN \ Segments of list dictionary

        SHL CX, # 1     \ Multiply by 16 decimal

        SHL CX, # 1

        SHL CX, # 1

        SHL CX, # 1

        MOV DI, # 0     \ Clear DI

        MOV SI, DPSTART \ MOV source offset to SI

        OR CX, CX       \ if head length was not zero (0)

        0< IF   CLD     \ Forward move

            REPZ

            MOVSB   \ move list to List Space

            CLD

        THEN

        MOV XSEG ES     \ set XSEG base of List Segment

    THEN

\ The following few instructions patch two ADD instructions in KERNEL1, so

\ we can do an ADD IMMEDIATE rather than an ADD MEMORY in NEST and DODOES.

    MOV ES, XSEG        \ Initialize ES in case we haven't??

    MOV NESTPATCH 1+ ES \ Patch ADD instruction in NEXT

    MOV DOESPATCH 1+ ES \ Patch ADD instruction in DODES

    CALL SAVEVECTORS        \ Save existing vectors

    MOV ' RESTNEXT >BODY # TRUE WORD    \ We want NEXT restored

    CALL SETBRK         \ Install F-PC Break vectors and restore NEXT

    MOV AX, ' #CODESEGS >BODY   \ Length of code dictionary

    SUB AX, # 1         \ One less than max

    SHL AX, # 1         \ * 16 to length in bytes

    SHL AX, # 1

    SHL AX, # 1

    SHL AX, # 1

    MOV ' LIMIT 3 + AX      \ Initialize LIMIT

    SUB AX, # 10

    MOV ' FIRST 3 + AX      \ FIRST = LIMIT - 10h

    SUB AX, # 10

    MOV RP, AX          \ RP = FIRST - 10h

    MOV BX, # RP0

    ADD BX, UP          \ Add user area

    MOV 0 [BX], RP      \ RP0 = RP

    SUB AX, # 200

    MOV 'TIB AX         \ TIB = RP - 250 decimal

    MOV BX, # SP0       \ Stack pointer

    ADD BX, UP

    MOV 0 [BX], AX      \ SP0 = TIB

    MOV SP, AX          \ SP = TIB

    MOV ' 1STCOLD >BODY # TRUE WORD     \ Make COLD to do its initialization

    MOV AX, COLDBODY 2- \ Cold start routine

    ADD AX, XSEG        \ Add List Segment base

    MOV ES, AX          \ Execute COLDBODY as a colon word

    MOV IP, # 0

    NEXT

    END-CODE

5.6.   DEBUGGING WORDS

 

 

Here is a small set of tools which allows you to exercise the F-PC kernel system if you modified the kernel and have trouble in loading the full F-PC system with all the sophisticated debugging tools.  You can look at memory contents, display word names, examine the data stack, etc.  They are better than nothing when you have problems, and are generally powerful enough to solve most problems.

 

DEPTH   Return the number of items on the data stack not including itself.

 

: DEPTH ( -- n )

    SP@                 \ Current stack pointer

    SP0 @               \ Bottom of data stack

    SWAP - 2/   ;           \ Difference in cells

 

VARIABLE MAX.S  Maximum items on the stack to be displayed by .S .  Initialized to 4.

 

.S      Display the contents of the data stack non- destructively.  Very useful when debugging.

 

: .S        ( -- )

    DEPTH 0<            \ Abort if stack underflow

    ABORT" Stack UNDERFLOW !! "

    DEPTH ?DUP          \ If stack is not empty,

    MAX.S @ 1 <         \ If MAX.S is less than 1,

    IF 4 MAX.S ! THEN       \   initialize it to 4.

    IF  DUP ."  ["      \   display stack depth,

        1 .R ." ]"

        0 SWAP 1-

        MAX.S @ 1- MIN  \   and up to MAX.S items

        DO I PICK 7 U.R    \   on the top of the data

            SPACE   \   stack.

        -1 +LOOP

    ELSE    ."  Stack Empty. "      \ Else, say so.

    THEN ;

 

.ID     A deferred word.  Display the variable length name whose name field address is on the stack.  If the name is shorter than its count, it is padded with underscores.  Only valid ASCII character is typed.

 

: %.ID      ( nfa -- )

    DUP 1+          \ nfa nfa+1 --

    DUP YC@             \ Get first character of name

    ROT YC@             \ Get the count byte

    31 AND 0            \ Mask off irrelevant bits

    ?DO DUP 127 AND FEMIT   \ Display one character

        128 AND     \ Is it the last character in name?

        IF  ASCII _ 128 OR  \ Yes.  Leave pad character _ .

        ELSE    1+ DUP YC@  \ No.  Get the next character.

        THEN

    LOOP                \ Display as many as count.

    2DROP SPACE ;       \ trailing blank

 

DEFER .ID   ' %.ID  IS  ID      \ Deferred to allow for colorizer to display names in color.

 

DUMP    A primitive little dump routine to help you debug after you have changed the system source and nothing works any more.  A more elaborate DUMP is defined in DUMP.SEQ.

 

: DUMP  ( addr len -- )

    0               \ Do len times

    DO  CR DUP 6 .R SPACE   \ Display address

        16 0            \ Dump 16 bytes to a line

        DO  DUP C@ 3 .R 1+  \ Display bytes

        LOOP

    16 +LOOP   DROP   ;     \ Next line

 

RECURSE Force the compilation of the word under construction.  We prefer that you will use RECURSIVE rather than RECURSE. ( See RECURSIVE )

 

: RECURSE   ( -- )

    LAST @          \ Get the name field address from LAST.

    NAME> X,            \ Compile its cfa into list

    ;  IMMEDIATE            \ Must be executed during compilation

 

H.      Display the unsigned number in hex, with trailing blank.  It does not change the number base.

 

: H.        ( n -- )

    BASE @ >R           \ Save BASE

    HEX U.          \ Display n in hex

    R> BASE ! ;        \ Restore base

 

LMARGIN The left margin setting used by ?LINE and ?CR. When a line-wrap occurs, LMARGIN specifies how many spaces are printed on the following line.  Default value is 0.

 

VARIABLE LMARGIN    0 LMARGIN !-T

 

RMARGIN Control the right margin, used by ?LINE and ?CR. It specifies where to wrap the line.  Default value is 70.

 

VARIABLE RMARGIN   70 RMARGIN !-T

 

TABSIZE Control the TAB increment for TAB.  Default is 8.

 

VARIABLE TABSIZE    8 TABSIZE !-T

 

?LINE       Break the line at the cursor if there are less than n characters till RMARGIN is encountered.

 

: ?LINE ( n -- )

    #OUT @ +            \ Add n to output character counter

    RMARGIN @ >     \ If it exceeds RMARGIN,

    IF CR          \   do carriage-return and

        LMARGIN @ SPACES    \   skip to left margin.

    THEN ;

 

?CR     Break the line at the cursor, if we have reached the right margin as specified by RMARGIN.

 

: ?CR       ( -- )  0 ?LINE  ;

 

TAB     Print spaces to get to the next TAB increment as specified by TABSIZE.

 

: TAB       ( --- )

    #OUT @          \ Output character count

    TABSIZE @ MOD       \ Characters printed after TAB

    TABSIZE @

    SWAP - SPACES ;     \ Pad spaces till next tab.

 

\       Comment till the end of this line.

      

: \     ( --- )

    SPAN @          \ Move interpreter point >IN to

    >IN !               \   end of input buffer, and

    ; IMMEDIATE         \   ignoring all characters in between.

 

CODE SET-CURSOR ( n1 --- )      \ Set the cursor shape to value n1

    POP CX

    MOV AH, # 1

    PUSH SI

    PUSH BP

    INT $10         \ Call DOS to deposit the color code

    POP BP

    POP SI

    NEXT C;

 

: GET-CURSOR    ( --- n1 )              \ return n1 the shape of the cursor.

5.7.   RESOLVING FORWARD REFERENCES AND DEFERRED WORDS

 

 

Here is the list of all the forward references and deferred words which were not already resolved or vectored to executable words.  This list usually does not need your attention unless you made substantial modifications to the F-PC kernel.  The word is in this list are also the most difficult ones to understand.  Most of them are inner interpreters to classes of words generated by defining words.  The defining words are very difficult to handle in meta compilation.  Each defining word must be hand coded.  When you are developing an application and intend it to be meta compiled, it is best to avoid using defining words if you can help it.  If you have to use them, then study the F-PC meta compiler and this kernel carefully.  Try to mimic the way F-PC handles these defining words.

 

:RESOLVES resolves forward references in the List space, while  RESOLVES resolves forward reverences in the Code space.  It does not matter whether the word you are resolving is a CODE word or a colon definitions, what matters is where it is being resolved, typically in the List space but not the Code space.  All this is to say you should normally use :RESOLVES rather than RESOLVES to resolve forward reverences.

 

' (.")      :RESOLVES <(.")>

' (")       :RESOLVES <(")>

' (;CODE)   :RESOLVES <(;CODE)>

' (;USES)   :RESOLVES <(;USES)>

' (IS)          :RESOLVES <(IS)>

' (ABORT") :RESOLVES <(ABORT")>

 

 [ASSEMBLER]    >NEXT    META               RESOLVES <VARIABLE>

 [ASSEMBLER]    DOUSER-DEFER META       RESOLVES <USER-DEFER>

 [ASSEMBLER]    DOUSER-VARIABLE META    RESOLVES <USER-VARIABLE>

5.8.   SAVING F-PC KERNEL

 

 

Following is a list of words executed after the meta compilation is completed.  They display a set of system parameters and other information relevant to the meta compilation and to the target Forth system, like the sizes of various segments.  After that, the object image of the resulting Forth kernel is saved in a file KERNEL.EXE.  This is a minimally useful F-PC system, which serves as a basis to build useful applications.  One of the very useful application is the full F-PC system, which can be constructed by type EXTEND under the DOS prompt.  EXTEND compiles a set of utility files on top of the F-PC kernel system to give the user a complete Forth programming environment in which very large application can be coded and debugged.
