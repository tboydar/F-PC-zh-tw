7.6.   DUMP

 

 

Memory dumping is more complicated in F-PC than in F83 because it has to address the entire memory space in the AT/PC.  The regular DUMP in F83 is retained to dump memory in the Code Segment.  Special words XDUMP and YDUMP are defined to dump memory in the List Segment and the Head Segment.  All these variations are derived from the generic dump utility word LDUMP which uses a seg:addr pair to specify the memory area to be dumped.  A variable DUMPSEG is used to define the dump segment to facilitate accessing the extended memory range.

 

The dump utility gives you a formatted hex dump, 16 bytes to a line, with the ASCII text corresponding to the bytes on the right hand side of the screen.  DUMPSEG is set accordingly.

 

VARIABLE DUMPSEG    Store the segment address from where memory contents are shown.

 

DUMPC@  Fetch a byte from the dump segment, given the offset address on the stack.

 

: %DUMPC@   ( addr -- b )

    DUMPSEG @           \ Get the dump segment address

    SWAP                \ Move offset address to top

    C@L ;               \ Fetch a byte with long fetch

 

DEFER DUMPC@    ' %DUMPC@ IS DUMPC@

 

.2W     Print n in two digits followed by a space.

 

: .2W       ( n -- )

    0 <# # # #>         \ Convert two digits only

    TYPE SPACE   ;      \ Type them with a trailing space

 

D.2W        Dump the contents of an array of n bytes from addr, in two digit pairs.

 

: D.2W      ( addr ln -- )

    BOUNDS          \ Scan the range of memory

    ?DO I DUMPC@        \ Fetch byte from dump segment

        .2W         \ Display one byte at a time

    LOOP   ;

 

EMIT.   Emit an ASCII character char.  If the char is not printable then print a ".".

 

: EMIT. ( char -- )

    127 AND             \ Eliminate most significant bit

    DUP BL 126 BETWEEN \ Is it a control character?

    NOT IF

        DROP ASCII .        \ Yes.  Substitute with a period

    THEN EMIT ;         \ Print it

 

DLN     Dump a line, consisting of 16 bytes of hex data followed by 16 bytes of ASCII string data.

 

: DLN       ( addr -- )

    CR   ."  |"         \ New line

    DUMPSEG @ 0         \ First display dump segment

    <# ASCII : HOLD         \   Starting with segment:

        # # # # #> TYPE

    DUP 0               \ Follow by starting address

    <# # # # # #> TYPE

    ."  | " 8 2DUP D.2W     \ Dump 8 bytes with a separator

    OVER + 8 D.2W ." |"         \ Next 8 bytes with separator

    16 BOUNDS ?DO           \ Dump contents in ASCII form

        I DUMPC@ EMIT.  

    LOOP  ." |" ;           \ Field terminator

 

.HEAD   Print the header line for DUMP.

 

: .HEAD ( addr len -- addr' len' )

    OVER 15 AND

    CR ." -----------"

    49 0 DO ." -" LOOP ." ? 16 0 DO ." -" LOOP ." ?

    CR ." - SEG:OFF - "

    16 0 DO DUP I + 15 AND 2 .R SPACE LOOP ." -"

    16 0 DO DUP I + 15 AND 1 .R LOOP DROP  ." -"

    CR ." ----------"

    49 0 DO ." -" LOOP ." -" 16 0 DO ." ? LOOP ." -" ;

 

: .FOOT ( --- )

    CR ." ----------"

    49 0 DO ." -" LOOP ." -" 16 0 DO ." ? LOOP ." -" CR ;

 

LDUMP   The generic dump word.  Dump len bytes of a memory area starting from seg:addr.  The dump segment is also stored in DUMPSEG, so that you can continue dumping using DU.  The dumped object code is enclosed in a nicely formed box with dividing lines, very pretty on the screen.

 

: LDUMP ( seg addr len -- )

    ROT DUMPSEG !       \ Save dump segment in DUMPSEG

    BASE @ -ROT             \ Save current base

    HEX .HEAD BOUNDS        \ Display head in hex

    DO  I DLN  KEY? ?LEAVE  \ Dump one line at a time

    16 +LOOP            \ Until completion or a key

    BASE !  CR ;            \ Restore BASE

 

DUMP    Dump the contents of a memory array from address addr for length len in the Code Segment.  This is the most commonly used dump word because most data and buffers are in the Code Segment, and it is compatible with the DUMP in F83.

 

: DUMP  ( addr len -- )

    ?CS:                \ Make CS the dump segment

    -ROT LDUMP ;            \ Dump Code Segment memory

 

YDUMP   Dump an area of n bytes in the Head Segment.

 

: YDUMP ( addr n -- )

    YSEG @          \ Make Head Segment the dump segment

    -ROT LDUMP ;            \ Then dump

 

XDUMP   Dump an area of n bytes in the List Segment.  The segment address is relative to the base segment address XSEG pointing to the beginning of the List Segment.

 

: XDUMP ( seg-offset n -- )

    SWAP XSEG @ +       \ Get the absolute segment address for the dump segment

    0 ROT LDUMP ;       \ Dump

 

DU      Dump 64 bytes from the dump segment starting at an offset address addr.  Return the address of next line so that DU can be executed again.

 

: DU                ( addr -- addr+64 )

    DUP 64 DUMPSEG @        \ addr 64 seg --

    -ROT LDUMP          \ Dump 64 bytes

    64 +   ;                \ Address of next line

 

 

7.7.   CASE

 

 

This case structure was originally reported by Charles Eaker in Forth Dimensions, Vol. 2, No. 3, Sep/Oct 1980.  It was adapted to F-PC by Bob Smith.  The most critical part (OF) is coded in assembly and moved into the F-PC Kernel.  It is repeated here for completeness.

 

A case structure is a control structure which allows multiple branches selected by a value.  It must be defined inside a colon definition.  A case statement must be constructed as follows:

 

    CASE ( value -- )

        value1 OF  func1   ENDOF

        value2 OF  func2   ENDOF

        value3 OF  func3   ENDOF  

            ...

        otherwise-func DROP

    ENDCASE

 

CASE and ENDCASE enclose the case statement.  OF and ENDOF enclose a branch.  Value is passed into the case structure on the data stack.  OF compares value with the number before it.  If the two numbers are equal, the function after OF is executed until ENDOF, and the case terminated with value removed from the stack.  If the numbers are not equal, value is passed to the next OF for comparison.  The otherwise-func can still make use of value if none of the branches was executed.  If it does not use value, DROP discard the value and the case structure is terminated.

 

CASE is extremely powerful for multiple tests and multiple branches which are difficult to code with the IF-ELSE-THEN structure.  F-PC uses it extensively in the system.  However, if values for comparison are sequential, the EXEC: word is much faster, and more efficient in memory.  See EXEC:

 

(OF)        Primitive case comparison word, compiled by OF. Performs a comparison between n1 and n2.

 

CODE (OF)   ( n1 n2 -- n1 ) or ( n1 n1 -- )

    POP AX          \ Pop n2

    MOV DI, SP

    CMP AX, 0 [DI]      \ Compare n2 and n1

    0<> IF              \ Not equal,

        MOV ES: IP, 0 [IP]  \   jump to the next case.

        NEXT

    THEN                \ n1=n2

    ADD SP, # 2         \ Drop n1 from the data stack

    ADD IP, # 2         \ Execute the OF clause

    NEXT

    END-CODE

 

CASE        Start a multiple branch control structure which allows an arbitrary value to specify a function to be performed. 

 

: CASE  ( n --  n )

    COMPILE DOCASE

    <MARK           \ Simply put a place mark here

    0               \ Mark the data stack as the bottom of address list for

    ; IMMEDIATE         \   ENDCASE to resolve

 

OF      Start a conditional branch phrase in a case structure.

 

: OF        ( -- )

    COMPILE (OF)        \ Compile run-time code (OF)

    >MARK ;             \ Compile a dummy forward branch address and leave its

                    \   address on stack for ENDOF to resolve

    IMMEDIATE           \ Must execute immediately

 

ENDOF   Close a conditional branch phrase in the a case structure.

 

: ENDOF ( -- )

    COMPILE DOENDOF         \ Compile an unconditional forward branch to ENDCASE

    >MARK           \ Leave address for ENDCASE

    SWAP >RESOLVE       \ Resolve branch address after OF

    ;   IMMEDIATE       \ Do it now

 

NRESOLVE    Primitive used by ENDCASE to resolve the previous case references.

 

: NRESOLVE  ( 0 n1 n2 ... n -- )

    BEGIN               \ Place current IP in all locations on stack till the 0 marker

        DUP         \ Is it a valid address?

        IF  >RESOLVE 0  \ Yes.  Resolve forward branch

        ELSE    -1          \ No.  End of list.  Terminate.

        THEN

    UNTIL   DROP ;      \ Clean up the stack

 

ENDCASE Resolve all branches in a case structure and close the structure.

 

: ENDCASE   ( -- )

    NRESOLVE            \ Resolve all forward branches

    DROP ;          \ Discard marker left by CASE

    IMMEDIATE

 

 

7.8.   SET DIRECTORY PATH

 

 

PATHSET.SEQ has a word set to select and set the directory path to files.  PATHSET checks the file contained in a handle.  It it does not contain a path, then apply the current drive and path to the handle.  It allows F-PC to use the full path/file name in DOS to specify files to be accessed.

 

flhndl  A value that returns the address of the handle we are currently working on.

 

0 value flhndl              \ Will be plugged later

 

?drive.extract  Given a handle, return drive-value of the drive specified in handle.  Return the current drive if no drive was specified in handle.

 

: ?drive.extract        ( handle --- drive-value )

    dup >nam 1+ c@      \ Get the second character

    ascii : =           \ Is it a : ?

    if  dup>r >nam c@       \ Get the drive character

        bl or 96 -      \ Convert to drive number, A: is 1

        r@ count 2- >r      \ Length less drive specification

        dup 2+ swap     \ name+3 name+1

        r> cmove        \ Copy name over the drive spec

        r@ c@ 2- r@ c!      \ Reduce name length by 2

        r> count + off      \ NULL fill the end

    else                    \ No drive specified

        drop 0 25 bdos 1+   \ Ask system the current drive

    then    ;

 

?drive.prepend  Given a drive-value and a handle, prepend the drive-value into handle, as a letter followed by ":".

 

: ?drive.prepend    ( drive-value handle --- )

    over 0=             \ Drive number =0 ?

    if  2drop           \ Yes.  Use default drive.

    else                \ A drive is specified.

        dup>r count >r      \ Name address

        dup 2+ r> cmove>    \ Move name down by 2 characters

        64 + r@ >nam c!     \ Insert drive name

        ascii :

        r@ >nam 1+ c!       \   with a colon

        r@ c@ 2+ r> c!      \ Adjust character count

    then    ;

 

HANDLE pathhndl     \ A handle that contains the default drive path.

 

prepend.path    Prepend the default drive and path to a handle, and return a Boolean flag that tells if we were successful.

: prepend.path  ( handle --- f1 )

    pathhndl clr-hcb

    dup =: flhndl ?drive.extract >r

    flhndl >nam c@ '\' <> dup                       \ leave if got path

    if      drop

        '\' pathhndl 1+ c! 64 pathhndl c!

        pathhndl 2+ r@ pdos dup 0=

        if      drop

            pathhndl 1+ 64 0            \ determine path length

            do      dup i + c@ 0= if i pathhndl c! leave then

            loop    drop pathhndl c@ 1 >

            if      '\' pathhndl count + c!

                pathhndl c@ 1+ pathhndl c!

            then    flhndl c@ pathhndl c@ + 62 > dup 0=

            if      drop

                flhndl 1+ pathhndl c@ over + flhndl c@ cmove>

                pathhndl count flhndl 1+ swap cmove

                pathhndl c@ flhndl c@ + flhndl c!

                false

            then

        then

    then   

    r> flhndl ?drive.prepend 0 flhndl count + c! ;

 

' PREPEND.PATH IS PATHSET

 

 

7.9.   STRING SEARCH

 

 

SEARCH.SEQ was contributed to F-PC by Roger Bird.  It is 20% faster than our earlier version and 140 bytes smaller.  It may be removed in a turnkey application, but it is used by WORDS.SEQ, and ENVIRON.SEQ, which is itself used by EXEC.SEQ.  It must be loaded for an interactive Forth system.

 

The string manipulation primitives include string comparison and searching.  The string search implemented here is used in the editor to find desired strings.  The only unusual thing about it is the presence of a variable called CAPS, which determines whether or not to ignore the case of the subject and pattern strings.  If case is ignored then A-Z = a-z.  The default is to ignore case.

 

Much thanks to Roger Bird for this improved implementation of SEARCH.  It is about 20% faster than the previous improved version in F-PC, and is 10 times faster in the case where the string being searched for starts with a space.  It is also 140 bytes smaller than the old implementation.

 

SEARCH  Search for a source string (saddr,slen) contained in the destination string (daddr,dlen).  Return a true flag if found, and an address equal to the offset into the destination string where saddr,slen was found.

 

CODE SEARCH     ( saddr slen daddr dlen -- offset found? )

    pop cx              \ dlen

    pop di              \ daddr

    pop bx              \ slen

    pop ax              \ saddr

    cmp bx, # 0                 \ if search length "slen" is 0 then return true

    0= if   push bx

        mov ax, # true

        1push

    then

    push di             \ Save daddr

    push es             \ Save ES

    mov es, sseg            \ ES points to string segment

    push si             \ Save IP

    push bp         \ Save RP

    mov si, ax          \ Source address saddr

    dec bx              \ Source count-1

    dec cx              \ Destination count-1

    mov dx, bx          \ Save a copy in DX

    cmp caps # 0            \ Case sensitive?

    0= if               \ Yes.  Clear mask.

        mov bp, # 0

    else                \ Case insensitive.

        mov bp, # $2020 \ Set mask to two blanks

    then

    begin               \ Search loop

        cmp bx, cx      \ Source-len > dest-len ?

    <= while            \ No.  Must do search.

        begin               \ Compare strings

            mov al, 0 [si+bx]   \ Get a byte from source

            mov ah, es: 0 [di+bx]   \ Get a byte from dest

            or ax, bp       \ Mask case bit

            cmp ah, al      \ Are they the same?

        0= while            \ Yes.

            dec bx              \ Decrement source count

            0< if           \ Source string exhausted?

                pop bp      \ Yes.  Match is found.

                pop si      \ Restore IP

                pop es      \ Restore List pointer

                pop dx      \ Destination string addr

                sub di, dx  \ Addr of found string

                push di     \ Push on stack

                mov ax, # $FFFF \ True flag

                1push       \ Push on stack

            then            \ Not yet done

        repeat              \ Compare next byte

        inc di          \ Move on the next source byte

        dec cx          \ Decrement destination count

        mov bx, dx      \ Restore source count

    repeat              \ Fail to find a match

    pop bp              \ Restore RP

    pop si              \ Restore IP

    pop es              \ Restore ES

    pop dx              \ Get dest address

    sub di, dx          \ Move to original daddr

    push di             \ Push on stack

    sub ax, ax          \ Make false flag

    1push               \   and push on stack

    end-code

 

 

7.10.   WORDS

 

 

WORDS is used in F83 to display the names of words in the context vocabulary.  This is a very important utility in Forth to allow the user to inspect the words currently available to be used for execution or compilation.  F-PC greatly enhances the usefulness of WORDS by allowing it to take a string argument to trigger some very interesting functions.  If WORDS is followed by an arbitrary string, all the words in all vocabularies containing that string pattern will be reported.  This is very useful to identify a group of words whose spelling is not known for sure.

 

If the string argument is *.* , then all words in all vocabularies are displayed.  CODE.* allows only code words to be searched and reported.  :.* allows only colon words.  Other patterns allowed are VARIABLE.* , CONSTANT.* , UVARIAVLE.* , DEFER.* , and UDEFER.*  for obvious purposes.  TOTAL.* causes only the word count to be reported.

 

Since F-PC has a very large dictionary, these conditional searching words are more important here than in other smaller Forth systems.  If you are using a color monitor, F-PC can display different types of words in different color.  The colorization can be turn on or off, by executing the word COLORIZEON or COLORIZEOFF.

 

Here is a list of variables used in displaying word lists:

 

VYET                \ Did we print this vocabulary yet?

VADDR               \ Vocabulary name address

TOTALWORDS              \ Accumulator for the total number of names.

 

.VYET   Print the name of a vocabulary if we have not printed it yet.

 

: .VYET ( -- )

    VYET @ IF EXIT THEN \ If VYET is true, this vocabulary was printed already.  Exit.

    VADDR @ CR          \ Otherwise, print the vocabulary

    ." --[ " .ID ."  ]--"       \   name first.

    VYET ON         \ Make sure doing it only once

    CR LMARGIN @ SPACES  ;  \ New line with left margin

 

 

DEFER W.ID ' .ID IS W.ID        \ .ID is deferred to accommodate the colorizer.

CREATE W$ 64 ALLOT      \ Word name is store here temporarily to match substrings.

    W$ 64 ERASE

 

?INNAME A substring pattern is stored in the word buffer at HERE.  Search the word name at nfa for this substring.  Return a true if the substring is contained in the word name.

 

: ?INNAME   ( nfa -- f )

    @> YSEG SWAP        \ seg:addr of the name field of this word

    ?CS: HERE 31 CMOVEL \ Copy word name to HERE

    $C0 HERE CRESET                     \ mask to real count only

    $80 HERE COUNT + DUP OFF    \ clear end of name to NULL

    1- CRESET           \ mast high bit of last char

    W$  COUNT           \ First pattern to be searched.

    HERE COUNT SEARCH NIP

    W$ 32 + COUNT       \ Second pattern to be searched

    HERE COUNT SEARCH NIP

    AND ;               \ Return true if word name contains both sub-strings

 

?CODENAME   Return true if the word at nfa is a code definition.

 

: ?CODENAME ( nfa -- f )

    NAME>           \ Get cfa

    C@ DUP 232 <>       \ If it does not contain a CALL

    SWAP 233 <> AND ;       \   nor a JMP, then it must be a code word

 

0 VALUE WORDTYPE        \ Address of inner interpreter for type identification

 

?WORDTYPE   Return true if the word at nfa is of the same type as shown in WORDTYPE.

 

: ?WORDTYPE ( nfa -- f )

    NAME>           \ Get cfa

    @REL>ABS            \ Get absolute address of the inner interpreter of this word

    WORDTYPE = ;        \ Compare with WORDTYPE

 

?TOTALWORD  Increment the total word count.  Replace nfa with a false flag.

 

: ?TOTALWORDS   ( nfa -- false )

    DROP FALSE

    TOTALWORDS INCR ;

 

?W.NAME This is a critical word in the WORDS utility in F-PC.  It is a deferred word.  It takes a nfa and returns a flag.  If the flag is true, the name of this word should be printed.  Otherwise, the word will be ignored.  Depending on the search string following WORDS, ?W.NAME will be vectored to a words which selects the specific type of words and sets the proper flag.  See the following words for its usage and behavior.

 

DEFER ?W.NAME   ( nfa -- flag )

 

W.NAME  Print the name of a word at nfa filtered by the string at HERE.  Test to see if conditions are correct, like CODE, or ALL, or WITHIN, and then print the name.

 

: <W.NAME>  ( nfa -- )

    DUP ?W.NAME     \ Call ?W.NAME to decide  whether name should be printed.

    IF  .VYET 17 ?LINE W.ID     \ Yes.  Print vocabulary and word name.

        #OUT @ COLS 16 - < \ Tab if needed

        IF TAB THEN

        TOTALWORDS INCR \ Bump word count

    ELSE    DROP            \ Do not print name

    THEN    ;

 

DEFER W.NAME    ' <W.NAME>  IS  W.NAME

 

.VOCWORDS   Display all the matching words, i.e., words selected by ?W.NAME, in a vocabulary.

 

 

code largest    ( a1 n1 --- a2 n2 ) \ Return the largest element of an array of words

    pop cx                      \ count of array to search

    pop bx                      \ starting address of array

    mov ax, # 0                 \ starting highest value = 0

    mov dx, bx                  \ highest value addr = start address

here    cmp 0 [bx], ax

    u> if   mov dx, bx

        mov ax, 0 [bx]

    then

    add bx, # 2                 \ bump to next element

    loopnz

    2push           end-code

 

: .VOCWORDS ( voc-addr -- )

    DUP HERE 500 +      \ Copy vocabulary threads

    #THREADS 2* CMOVE       \   to Code Segment

    BODY> >NAME VADDR ! \ Store address of vocabulary

    VYET OFF            \   in VADDR

    BEGIN  

        HERE 500 +      \ Thread table

        #THREADS

        LARGEST DUP \ Find highest name on  threads

        ?KEYPAUSE

    WHILE  

        DUP L>NAME      \ Go from lfa to nfa

        W.NAME      \ Print out name

        Y@ SWAP !       \ Replace thread with next lfa

    REPEAT  2DROP ;     \ Repeat for the vocabulary

 

DEFER ?W.TEST           \ A template to provide DODEFER

' NOOP IS ?W.TEST           \   to ?DEFER.* later

 

The following set of words ?xxxxx.* vector execution words into ?W.NAME so that ?W.NAME will be able to select a specific class of words to be printed.  They test the string in the word buffer at HERE and change the behavior of ?W.NAME accordingly.

 

: ?*.*      ( -- )

    W$ 1+           \ Word buffer

    " *.*" COMP 0=      \ Is the string *.* ?

    IF  ['] NOOP        \ Yes.  Store NOOP in ?W.NAME

        IS ?W.NAME      \   allow all words to be matched

    THEN    ;

 

: ?CODE.*   ( -- )

    W$ 1+           \ Is the string CODE.* ?

    " CODE.*" CAPS-COMP 0=

    IF  ['] ?CODENAME   \ If so, search only code words

        IS ?W.NAME      \   by vectoring ?W.NAME to

    THEN    ;           \   ?CODENAME

 

: ?:.*      ( -- )

    W$ 1+           \ If the string in word buffer is

    " :.*" CAPS-COMP 0=     \   :.* ,

    IF  ['] ?*.* @REL>ABS   \   let WORDTYPE points to NEST

        =: WORDTYPE

        ['] ?WORDTYPE   \   and ?W.NAME is vectored to

        IS ?W.NAME      \   ?WORDTYPE to print colon words

    THEN    ;

 

: ?VARIABLE.*   ( -- )

    W$ 1+               \ For variables

    " VARIABLE.*" CAPS-COMP 0=

    IF  ['] TOTALWORDS @REL>ABS     \ WORDTYPE points to >NEXT

        =: WORDTYPE

        ['] ?WORDTYPE IS ?W.NAME    \ ?WORDTYPE is execution

    THEN    ;               \   routine in ?W.NAME

 

: ?UVARIABLE.*  ( -- )

    W$ 1+               \ For user variables

    " UVARIABLE.*" CAPS-COMP 0=

    IF  ['] BASE @REL>ABS       \ WORDTYPE points to

        =: WORDTYPE         \   DOUSER-VARIABLE

        ['] ?WORDTYPE

        IS ?W.NAME

    THEN    ;

 

: ?CONSTANT.*   ( -- )

    W$ 1+               \ For constants

    " CONSTANT.*" CAPS-COMP 0=

    IF  ['] WORDTYPE @REL>ABS   \ WORDTYPE points to

        =: WORDTYPE         \   DOCONSTANT

        ['] ?WORDTYPE

        IS ?W.NAME

    THEN    ;

 

: ?VALUE.*      ( --- )

    W$ 1+ " VALUE.*" CAPS-COMP 0=

    IF      ['] WORDTYPE @REL>ABS =: WORDTYPE

        ['] ?WORDTYPE IS ?W.NAME

    THEN    ;

 

: ?DEFER.*  ( -- )

    W$ 1+               \ For deferred words

    " DEFER.*" CAPS-COMP 0=

    IF  ['] ?W.TEST @REL>ABS    \ WORDTYPE points to

        =: WORDTYPE         \   DODEFER

        ['] ?WORDTYPE

        IS ?W.NAME

    THEN    ;

 

: ?UDEFER.* ( -- )

    W$ 1+               \ For user deferred words

    " UDEFER.*" CAPS-COMP 0=

    IF  ['] EMIT @REL>ABS       \ Point WORDTYPE to

        =: WORDTYPE         \   DOUSER-DEFER

        ['] ?WORDTYPE

        IS ?W.NAME

    THEN    ;

 

: ?TOTAL.*  ( -- )

    W$ 1+               \ For counting words

    " TOTAL.*" CAPS-COMP 0=

    IF  CR ." Not displaying, just counting the TOTAL "

        ['] ?TOTALWORDS         \ Vector ?W.NAME to word

        IS ?W.NAME          \   just incrementing count

    THEN    ;

7.11.   CURSOR CONTROL WORDS

 

 

IBMCURSR.SEQ contains words which position the cursor on the display screen.  F-PC supports IBM color card and monochrome card, and also Hercules high resolution card.  It is smart enough to be able to select the appropriate word set to handle the screen display automatically.

 

IBM-AT  Move the cursor on the IBM display screen to the column and row specified.  This is done using a BIOS level interrupt.  This word is normally the deferred function of AT, you should use AT for portability.

 

CODE IBM-AT ( col row -- )

    POP AX

    POP DX

    MOV DH, AL

    XOR BH, BH

    MOV AH, # 2

    PUSH SI PUSH BP

    INT $10         \ BIOS service 16, function 2

    POP BP  POP SI

    NEXT   C;

 

IBM-AT? Return the col and row of the current cursor location on the screen.

 

CODE IBM-AT?    ( -- col row )

    XOR BH, BH

    MOV AH, # 3

    PUSH SI PUSH BP

    INT $10         \ BIOS service 16, function 3

    POP BP  POP SI

    SUB AX, AX

    MOV AL, DH

    MOV DH, AH

    2PUSH   END-CODE

 

IBM-DARK    Clear the screen and place the cursor in the upper left hand corner.  This is the deferred function of DARK.  Use DARK for portability.

 

CODE IBM-DARK   ( -- )

    MOV AX, # 2

    PUSH SI PUSH BP

    INT $10

    SUB AH, AH

    INT $10         \ Clear the screen

    POP BP  POP SI

    NEXT   END-CODE

 

LFILLW  Similar to LFILL, except filling the memory area with a 16 bit word pattern.

 

CODE LFILLW     (  seg start-addr byte-count word-pattern -- )

    CLD            

    POP AX

    POP CX

    SHR CX, # 1

    POP DI

    POP BX

    MOV DX, ES

    MOV ES, BX

    REPNZ           STOSW       \ Repeat Store-Words

    MOV ES, DX

    NEXT

    END-CODE

 

NORM-DARK   If >DOSIO is true, use IBM-DARK to blank the screen.  Otherwise, clear the screen by filling the screen buffer with proper word pattern.  This is necessary to deal with non-IBM video cards.

 

: norm-dark     ( --- )

    ?dosio

    if          ibm-dark

    else    blank.color

        VIDEO-SEG @ 0 ROWS COLS 2* *

        attrib c@ flip $20 or LFILLW

        show.color

    then    0 0 at ;

 

IBM--LINE   Delete the current line on the IBM display.  It causes all lines lower on the screen to scroll up.  This is the deferred function of -LINE.  Use -LINE for portability.

 

CODE IBM--LINE  ( -- )

    PUSH SI PUSH BP

    XOR BH, BH

    MOV AH, # 3

    INT   $10           \ Read Cursor Position

    MOV CH, DH

    XOR CL, CL          \ Upper left corner

    MOV DX, # ' ROWS >BODY 

    DEC DH

    MOV DL, ' COLS >BODY

    DEC CL 

    MOV BH, # 7

    MOV AH, # 6             \ Scroll up

    MOV AL, # 1         \ Lines to scroll  

    INT 16

    POP BP  POP SI

    NEXT   END-CODE

7.14.   SAVE SCREENS

 

 

Source File: SAVESCR.SEQ

 

 

F-PC manages many screens of useful information to help the user while running the editor, the debugger, and many on-line help utilities.  A common need is to save the current screen display, replace it with some other help screens, and later restore the original screen to continue normal work.  This save screen utility provides a memory area to save up to three screenful of data.  The saving process is nestable to three level deep.

 

0 value svseg           \ screen save segment

4 value svmax                       \ maximum number of screens to save

4000 value svsize                       \ size of each screen

0 value svtotal                     \ total of saved screens

 

svinit  Cold start initialization word that allocates 64K bytes of space for the screen save segment.

 

: svinit    ( -- )              \ Screen save initialization

    defers initstuff

    off> svseg

    rows cols 2* * =: svsize            \ set save size per screen

    65535. svsize um/mod nip            \ maximum number of screens

    1- svmax min =: svmax               \ limit svsize to < 64k

    svsize svmax * =: svtotal           \ adjust total arraysize

    svmax 1+ svsize * paragraph

    alloc 8 =               \ allocate the space

    if 2drop cr

        ." Could not allocate memory for Screen save routine."

    else    nip =: svseg

    then    ;

' svinit is initstuff

 

savescr Save the current contents of the CRT screen to an external segment save area.  Nestable up to four (SAVMAX) times.

 

: savescr   (-- )

    svseg 0

    2dup svsize + svtotal cmovel>       \ Make a hole in buf

    blank.color

    video-seg @ 0

    svseg 0 svsize cmovel           \ & save screen in it.

    show.color ;

 

restscr Restore a saved screen from the external screen save segment.  Un-nestable up to three levels.

 

: restscr   ( -- )

    svseg 0= ?exit

    blank.color

    svseg 0

    video-seg @ 0 svsize cmovel     \ Restore screen &

    show.color

    svseg svsize

    over 0 svtotal cmovel ;    \ compress buffer.

 

RECOVERSCR  Make a copy of the last saved screen and then restore it.

 

: recoverscr    ( -- )

    svseg 0= ?exit                  \ last saved screen

    blank.color

    svseg 0

    video-seg @ 0 svsize cmovel         \ Restore screen

    show.color ;

 

RECOVERLINE Get a copy of line n1 from the last saved screen.

 

: recoverline   ( n1 --- )                 

    svseg 0= if drop exit then         

    dup 0 rows 1- between

    if          cols 2* * >r

                blank.color     \ Restore line n1

                svseg r@

        video-seg @ r> cols 2* cmovel

                show.color

    else        drop

    then    ;

 

 

7.15.    TIMER WORDS

 

 

Words in TIMER.SEQ and TIMESTUFF.SEQ deal with time.  As we envision that many user will use F-PC for real-time applications, a complete set of time and date manipulation words has been included.  They call appropriate DOS service functions to provide the requested services.  The words for getting and setting the date and time are discussed in this section.          

 

Time delay words use the DOS time function to obtain very accurate time delays.  Background processing continues, as pause is called in the wait loop.  Another deferred word, PAUSE-FUNC, is also in the loop, which can be re-assigned to perform any function you may want done while the delay is occurring.

 

GETDATE Return d1 the 32 bit binary date from the operating system.  Bytes in d1 are arranged in the order of year/month/day/day-of-week.

 

: GETDATE   ( -- d1 )

    0 0 42 OS2          \ DOS service 42

    DROP ;

 

SETDATE Given the binary date d1, set the system clock to that date.

 

: SETDATE   ( d1 -- )

    SWAP 43 OS2             \ Update date

    NIP NIP 255 =           \ d1 might be invalid

    IF  CR

        ." Invalid DATE "

    THEN ;

 

GETTIME Return d1 with bytes arranged in the order hr/min/sec/100th-sec from the operating system.

 

: <GETTIME> ( -- d1 )

    0 0 44 OS2

    DROP ;

 

DEFER GETTIME  ' <GETTIME> IS GETTIME

 

SETTIME Given the binary time d1, set the system clock to that time.

 

: SETTIME   ( d1 -- )

    SWAP 45 OS2

    NIP NIP 255 =

    IF  CR

        ." Invalid TIME "

    THEN ;

 

CREATE DTBUF 16 ALLOT       \ A buffer to store date or time string for output

 

##+     Convert the two lowest digits in n1 and add the digits to DTBUF.

 

: ##+       ( n1 -- )

    0 <# # # #>             \ Convert two digits of n1

    TUCK DTBUF COUNT + \ End of string in DTBUF

    SWAP CMOVE          \ Append two digits

    DTBUF C+! ;         \ Update string count

 

"+      Append a string at addr of n bytes to the string in DTBUF.

 

: "+        ( addr n -- )

    TUCK DTBUF COUNT + \ See comments above

    SWAP CMOVE

    DTBUF C+! ;

 

BUILD-HM    Append the hour:minute string converted from n1 into DTBUF.

 

: BUILD-HM  ( n1 -- )

    SPLIT               \ Separate minute from hour

    ##+                 \ Convert hour

    " :" "+                 \ Insert a :

    ##+ ;               \ Convert minute

 

BUILD-SH    Append the second.tick string converted from n1 to the string in DTBUF.

 

: BUILD-SH  ( n1 -- )

    " :" "+                 \ Add separator

    SPLIT ##+           \ Convert seconds

    " ." "+                 \ Insert separator

    ##+ ;               \ Convert ticks

 

BUILD-TIME      Add the hour:minute:second.tick string to the string in DTBUF.  The time is represented by d1 on the stack.

 

: BUILD-TIME    ( d1 -- )

    SWAP                \ Make it Sh and HM

    BUILD-HM            \ Convert hour:minute

    BUILD-SH ;          \ Convert second.tick

 

FORM-TIME       Build up a time string in DTBUF from the time spec d1 on the stack.  Return the address of DTBUF.

 

: FORM-TIME ( d1 -- addr )

    BASE @ >R DECIMAL       \ Have to used decimal base

    DTBUF OFF           \ Init null string in DTBUF

    BUILD-TIME          \ Add time string

    R> BASE !           \ Restore base

    DTBUF ;         \ Push address of DTBUF

 

.TIME   Print the current time to the screen, in the format HH:MM:SS.HR, where HH is in hours, MM in minutes, SS in seconds, and HR in hundredths of a second.

 

: .TIME ( -- )

    GETTIME             \ What time is it?

    FORM-TIME           \ Convert to a time string

    COUNT TYPE ;        \ Print it

 

The time string format is fairly universal as HH:MM:SS.HR.  However, the representation of month and day shows many variations.  Here F-PC gives you three choices, which are quite obvious from their names:

 

: <M/D/Y>   ( d1 -- )

    SPLIT               \ Split day byte from month byte

    ##+                 \ Convert month

    " /" "+                 \ Add separator

    ##+                 \ Convert day

    " /" "+                 \ Add separator

    ##+ ;               \ Convert year

 

: <Y-M-D>   ( d1 -- )

    SPLIT ROT           \ day month year --

    ##+ " -" "+             \ Convert year and add /

    ##+ " -" "+             \ Convert month and add /

    ##+ ;               \ Convert day

 

: <D.M.Y>   ( d1 -- )

    SPLIT SWAP          \ day month year --

    ##+ " ." "+             \ Convert day

    ##+ " ." "+             \ Convert month

    ##+ ;               \ Convert year

 

We are sure that these choice will not be the one you will want to use.  Thus BUILD-DATE is defined as a deferred word so that you can make the correct choice and vector BUILD-DATE to it.

 

DEFER BUILD-DATE  

' <M/D/Y> IS BUILD-DATE     \ Our default choice

 

: M/D/Y ( -- )  ['] <M/D/Y> IS BUILD-DATE ;

 

: Y-M-D ( -- )  ['] <Y-M-D> IS BUILD-DATE ;

 

: D.M.Y ( -- )  ['] <D.M.Y> IS BUILD-DATE ;

 

DORM-DATE   Convert the date spec d1 into a date string in DTBUF.  Return the address of DTBUF.

 

: FORM-DATE ( d1 -- addr )

    BASE @ >R DECIMAL       \ Must use decimal base

    DTBUF OFF           \ Start with a null string

    BUILD-DATE          \ Add date string

    R> BASE !           \ Restore base

    DTBUF ;         \ Return with DTBUF address

 

.DATE   Print the current date to the screen, in the format MM/DD/YY, where MM is month, DD is day, and YY is year.

 

: .DATE ( -- )

    GETDATE             \ Ask Ms. DOS what day it is.

    FORM-DATE           \ Build the date string in DTBUF

    COUNT TYPE ;        \ Print it

 

A special word set is defined in F-PC to measure elapsed time for real time experiments and for characterization of program performance.

 

VARIABLE STIME 0 ,          \ Starting time

VARIABLE TTIME 0 ,          \ Buffer to store a time spec

 

T>B     Convert a DOS time spec d1 to a double integer in the units of 100th of a second, or a tick.  This binary representation is used to compute time difference.

 

: T>B       ( d1 -- d2 )

    SPLIT 100 * +           \ tick+100*second

    SWAP 0 SWAP         \ ticks 0 hh:mm --

    SPLIT >R 6000 *D        \ Convert minutes

    D+ R> 1000 *            \ Convert hour

    360 *D D+ ;         \ Add then altogether

 

B>T     Inverse of T>B.  Convert a double integer ticks back into the DOS time specification stored in TTIME.

 

: B>T       ( d1 -- )

    0 100 UM/MOD >R         \ Extract ticks

    100 UM/MOD          \ Extract seconds

    SWAP TTIME C!       \ Store ticks

    R> 60 UM/MOD        \ Extract minutes

    SWAP TTIME 1+ C!        \ Store seconds

    60 /MOD         \ Extract hours

    TTIME 3 + C!            \ Store hours

    TTIME 2+ C! ;           \ Store minutes

 

TIME-RESET  Reset the accumulated time value in the double variable STIME to zero, in effect resetting the current elapsed time to zero.  This word is used at the beginning of a sequence of operations you want to time.  The word .ELAPSED is used at the end of the operations to print the elapsed time since the last TIME-RESET.

 

: TIME-RESET    ( -- )

    GETTIME T>B             \ Get time in binary form

    STIME 2! ;              \   and store in STIME

 

TIME-ELAPSED    Get current time and find the difference from the time in STIME in units of ticks, 100th of a second.

 

: TIME-ELAPSED  ( -- d1 )

    GETTIME T>B             \ Get current time in ticks

    STIME 2@            \ Last ticks

    D- ;                \ Difference in ticks

 

B>SEC   Convert the double integer ticks to seconds.  Overflow occurs at about 18 hours.

 

: B>SEC ( d1 -- n1)

    0 100 UM/MOD DROP       \ Discard overflow

    100 UM/MOD NIP ;        \ Retain only seconds

 

.ELAPSED    Print the elapsed time since the last TIME-RESET was performed.

 

<.ELAPSED>  ( -- )

    TIME-ELAPSED        \ Get elapsed ticks

    B>T                 \ Convert ticks to DOS time

    TTIME 2@ FORM-TIME \ Convert to HH:MM:SS:HR spec

    COUNT TYPE ;        \ Print the time string

 

: .ELAPSED  ( -- )

    CR ." Elapsed time   =  "

    <.ELAPSED> ;

 

TIMER   Perform the Forth words following on the same command line, and when they finish execution, print the elapsed time used for their execution.

 

: TIMER ( words -- )

    TIME-RESET          \ Reset timer

    INTERPRET           \ Execute following words

    .ELAPSED ;          \ Display elapsed time

 

SEC-ELAPSED Return n1 the seconds that have elapsed since TIME-RESET.

 

: SEC-ELAPSED       ( -- n1 )  

    TIME-ELAPSED        \ Elapsed ticks

    B>SEC ;         \ Seconds within 18 hours

 

10TH-ELAPSED    Return n1 the tenths of a second that have elapsed since the last TIME-RESET was performed.

 

: 10TH-ELAPSED  ( -- n1 )

    TIME-ELAPSED        \ Elapsed ticks

    0 100 UM/MOD DROP

    10 UM/MOD NIP ;     \ Retain 10th of seconds

 

PAUSE-FUNC  A deferred word set to a function that is to be performed while waiting for timing to complete.

 

DEFER PAUSE-FUNC        ' NOOP IS PAUSE-FUNC

 

SECONDS Wait n1 seconds.

 

: SECONDS   ( n1 -- )

    STIME 2@ 2>R >R         \ Save starting time

    TIME-RESET          \ Clear STIME for counting

    BEGIN

        PAUSE  PAUSE-FUNC   \ Pause for task switching

        R@ SEC-ELAPSED > 0= \ Elapsed seconds > n1 ?

    UNTIL   R>DROP      \ If so, exit.

    2R> STIME 2! ;      \ Restore STIME

 

TENTHS  Wait n1 tenths of a second.

 

: TENTHS    ( n1 -- )

    STIME 2@ 2>R >R         \ Similar to SECONDS

    TIME-RESET

    BEGIN   PAUSE 

        PAUSE-FUNC

        R@ 10TH-ELAPSED     \ Except count 10th of seconds

        > 0=

    UNTIL   R>DROP

    2R> STIME 2! ;

 

MINUTES Wait n1 minutes.

 

: MINUTES   ( n1 -- )

    0 MAX   0  

    ?DO   60 SECONDS        \ Let SECONDS do the work

    LOOP ;

: HOURS ( n1 -- )

    0 MAX   0

    ?DO 60 MINUTES      \ Let MINUTES do it

    LOOP ;

7.16.   COMMENTS

 

 

Source code is in COMMENT.SEQ.  All comment words in F83, like (, .(, \, \S are preserved and they behave similarly in F-PC.  However, a file in F-PC is similar to a block in F83 and \S stops the compilation of the rest of the file.  To accommodate documentation which spans over many lines, additional comment words are defined in F-PC.  Multiple line comment in F-PC starts with COMMENT: and terminates at COMMENT; .  It looks like:

    COMMENT:   

    <text>

    <more text>

    ...

    <even more text>

    COMMENT;

 

To print multiple line comments during compiling,

    .COMMENT:      

    ...

    COMMENT;

 

.COMMENT; starts a group of lines that are to be printed to the terminal, until a terminating "COMMENT;" is found.

 

Plenty of documentation tools are provided in F-PC.  There is no excuse not using them to beautify your program.

 

' <run> value crunsave

7.17.   CONDITONAL COMPILATION

 

 

Conditional compilation words are also defined in the COMMENT.SEQ file.  Their function is to allow part of the source file to be loaded depending upon the condition exists at the loading time.  For example, if a floating point word exists in the dictionary, the entire floating point package must have been loaded.  Consequently, the floating point package needs not be reloaded.  The condition can be tested during loading, and the loading sequence does not have to be specified precisely before you start loading files.

 

<#if>       A primitive used by #IF.  Ignore lines until #ELSE or #ENDIF.

 

: <#if>     ( -- )

    loading @ 0=

    if crunsave is run

        true abort" #IF missing a #THEN while loading"

    then

    begin   bl word dup c@ 0= >r 1+

        dup " #endif" caps-comp 0= over

                " #then"  caps-comp 0= or swap

                " #else"  caps-comp 0= or dup

        if crunsave is run

            >r crunsave execute r>

         then   r> or

    until   ;

 

#ELSE   Start a false multi-line structure.

 

: #else     ( -- )

    ?loading                    \ you must be loading

    ?exec                       \ but NOT compiling

    @> run !> crunsave                  \ Save previous value of RUN.

    ['] <#if> is run\ Ignore following lines

    <#if> ;        immediate            \   and rest of this line.

 

 

#if     Starts a multi-line compiler directive. If the Boolean flag passed to #IF is true, then the lines following #IF will be executed.  If the flag is false, then the lines following #IF up to the #ENDIF or #ELSE, will be ignored.  Here is an example of how #IF works:

    TRUE    ( -- f1 )

    #IF     True flag passed, this comment needs no preceeding \

        cr .( This is printed due to TRUE before #IF.)

    #ENDIF

 

    FALSE   ( -- f1 )

    #IF

        .( This is NOT printed due to FALSE flag in #IF.)

    #ENDIF

 

: #if       ( f -- )

    ?loading

    ?exec

    0=

    if @> run !> crunsave  \ Save previous value of RUN.

        ['] <#if> is run        \ Ignore following lines

        <#if>           \   and rest of this line.

    then    ;       immediate

 

#endif  Just a noop for the #if TRUE case.  Ends a multi-line Compiler directive.  See #IF.

 

: #endif    ( -- )  ?loading  ; immediate

 

: #then     ( -- )  ?loading  ; immediate

 

Here is an example of how the interpreted compiler directives work.

    key bl or 116 =         \ wait for a key

    #if .( TRUE)

    #else .( FALSE) 

    #then .(  always )
