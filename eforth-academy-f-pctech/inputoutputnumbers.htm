CHAPTER 3.   INPUT, OUTPUT AND NUMBERS

 

 

 

 

 

KERNEL2.SEQ contains words which handle functions needed by the text interpreter and the colon compiler in F-PC.  It includes system variables, user variables, terminal input and output words, tools and mechanisms to get strings from the user or from a file, converting the strings to a form usable by the system, and also words converting numbers between the external ASCII form and the internal binary form.  Similar functions in F83 were all written in high level.  Most of them are reduced to assembly code words in F-PC to improve execution speed.

 

Many code words in F-PC 2.25 had shared code fragments to save memory space.  They are changed in F-PC 3.5 such that every code word is defined independently and are self-sufficient.  Code words can now be compiled independently and moved around freely, making it easier for target compilation.

 

 

3.1.   USER VARIABLES AND USER DEFERRED WORDS

 

 

Forth as originally developed by Charles Moore has always been a multi-user/multi-tasking system which can support many foreground tasks, and many background tasks.  A foreground task interacts with the user through a terminal, and background tasks are used to control peripherals and instruments.  Forth, Inc. still holds the multitasker, among other things in polyForth, as proprietary information.  Respecting the pioneering efforts by Charles Moore and his associates at Forth, Inc., implementers of public domain Forth systems like figForth deliberately crippled their systems by deleting this important feature of Forth.  However, over the years the round-robin task scheduling technique became public knowledge, and F83 included enough of the multi-task facility to implement a printer spooler.  However, the multi-tasker in F83 is still incomplete and cannot support more than one foreground terminal task.  F-PC has restored the full multi-tasker so that it is possible to run more than one terminal task.

 

The secret of multi-tasking in Forth is hidden in the user area, which is a data structure allocated in memory for every task declared in the system.  The user area preserves the entire environment of a task so that the task can give up the CPU to another task, and continue its execution when the CPU is passed back to it.  The environment includes a data stack, a return stack, a set of user variables, and some memory space for dictionary extension.  Since each task has its own user area with all the system information to run the task, very few CPU registers need to be saved during task switching.  Therefore a Forth multi-tasker runs very fast.  Typical task switching time is about 20 microseconds, which is incomprehensible in other languages and operating systems.  IBM discovered that it could do multitasking only on AT's, while Forth, Inc. had it more than ten years ago on the 8080 class of microcomputers.

 

The user variables defined in F-PC are listed as follows, with some user deferred words.  They are listed in the order of their sequence in the user area.  The user variables are initialized during F-PC boot-up.  See Section 5.5.

 

TOS     Top of the data stack saved before passing CPU control to the next task.  When a task PAUSEs, it pushes the return stack pointer RP, the instruction pointer IP, and the list segment ES on the data stack.  It then saves the data stack pointer in TOS and jumps to the next task whose ENTRY address is in LINK.

 

ENTRY   Contains the machine code to grab the CPU or pass it to the next task.  If the task is awake, it contains E9CD which causes a software interrupt INT E9 to grab hold of the CPU.  If the task is asleep, it contains E990 which is a jump instruction.  The address to be jumped to is in the next cell of LINK, which points to the ENTRY cell in the user area of the next task.

 

F83 used 80CD or INT 80 as the wake-up code in ENTRY.  This is a very obscure bug discovered by Mike Yantil.  It crashes the system if an interrupt occurred when the byte 80 or E9 is written to ENTRY.  The probability of this thing happening is very small if you are not doing a lot of interrupts, but when it happens the system will crash.  Replacing INT 80 by INT E9 solves the problem cleanly.  (This is the only serious bug in F83 discovered since 1983.)

 

LINK        Point to the ENTRY field of next task in the round-robin chain of tasks.

ES0     The base address of the List Segment.

SP0     Base of the data stack for this task.  It is used to initialize the data stack of this task.

RP0     Base of the return stack for this task.  Used to initialize the return stack of this task.

DP      Next available location of dictionary for this task.

OFFSET  This is a user variable left over from F83.  It is used to specify the block offset to be added to blocks accessed by this task.  Not used in F-PC.

BASE        The current numeric base for number input/output conversions.  Each task can do its own number conversion.

HLD     Point to the last converted character in the number string during conversion of a number to an ASCII string.

PRINTING    Indicate whether the printer is enabled.

 

To support foreground terminal tasks, each task needs to handle its own terminal through the terminal I/O words like KEY and EMIT.  Each task has a unique copy of these words to address the terminal assigned to it.  In F83, only EMIT was defined as a user deferred word.  Consequently, it can only support a printer task.  In F-PC all the basic keyboard I/O words are defined as user deferred words.  Hence it is able to support several terminals for a multi-terminal, multi-user system.  However, a multi-user system requires other supporting utilities so that each terminal can allow its user to edit files, interpret commands, and compile new words.  These utilities in F-PC are defined for one user only.  There is a lot more work still to be done to make it truly a multi-user system.

 

A user deferred word is defined like a user variable and compiled into the user area.  Its body contains an address pointing to a piece of executable code.  This address can be changed at run-time so that the deferred word may have different execution behavior.  Each task has a unique copy of the user deferred word so that the word can be referred to by the same name but different code is executed in different tasks.

 

EMIT        ( char -- ) Send a character to the output device assigned to a task.

KEY?        ( -- f )        Usually deferred to (KEY?), to sense keyboard status. It returns a true flag if a key is depressed on the keyboard.

KEY     ( -- char ) Usually deferred to (KEY) to get a character from the terminal keyboard.

TYPE        ( addr count -- )   Display the given string on the terminal.  Initialized to (TYPE).

TYPEL   ( seg addr count -- )   Similar to TYPE except the address is a segment:address pair.

Send a string to the terminal from any segment in memory.  Initialized to (TYPEL).

SSEG        Search and scan segment used by SED editor.

SEQHANDLE   Pointer to the handle of the current sequential file.

LOADLINE    Line number of the line in the current file we are presently loading or interpreting.

CAPS        If true, then convert names to upper case.

3.3.  STRING WORDS

 

 

This set of memory words deals with arrays and strings.  Many of them address memory locations outside of the Code Segment which is where normal Forth memory words operate.  A few words which deal with List Segment memory are also included in this section.

 

Strings are sequences of bytes.  In Forth, there are three different ways to represent strings.  The first is to use an address and a byte count; the address points to the first byte of the string.  The second representation is called a 'counted string':  the address of a counted string points to an address one byte ahead of the string.  The extra byte is the count byte.  Thus a counted string may have 0 to 255 characters in it.  The third representation is called a 'long string.'  Its address points two bytes ahead of the actual string.  The two extra bytes is combined to a 16 bit length count, thus allowing a long string with up to 65355 characters.  The long string is very useful in manipulating large text files.  COUNT converts a counted string to the address/count representation.  LENGTH converts a long string to the address/count representation.

 

Forth has to manipulate lots of texts, not the least of which are parsing of words from user input and comparing words with names in its dictionary.  Most text and string words are coded in assembly to increase the compilation speed of F-PC.

 

FILL        Fill the string starting at start-addr for count bytes with the character char.  Both BLANK and ERASE are special cases of FILL.

 

CODE FILL       (  start-addr count char -- )

    CLD             \ Set forward direction flag

    MOV BX, DS          \ Save DS

    POP AX          \ Character to fill

    POP CX          \ Count

    POP DI          \ Starting address

    PUSH ES             \ Save ES

    MOV ES, BX          \ ES:DI address the string

    REPNZ           \ Repeat next instruction

    STOSB               \   and fill the memory

    POP ES          \ Restore ES

    NEXT                \ Done

    END-CODE

 

LFILL   Fill a string with a character.  It is like FILL, but the string is located in a segment seg other than the Code Segment.

 

CODE LFILL      (  seg start-addr count char -- )

    CLD                 \ Set direction

    POP AX          \ Character

    POP CX          \ Count

    POP DI          \ Destination offset address

    POP BX          \ Destination segment

    PUSH ES         \ Save ES

    MOV ES, BX          \ Move in dest segment

    REPNZ           \ Repeat

    STOSB               \   filling the character in AL

    POP ES          \ Restore ES

    NEXT

    END-CODE

 

ERASE   Fill a string with zeros.

 

: ERASE ( addr len -- )

    0 FILL   ;

 

BLANK   Fill a string with blanks.

 

: BLANK ( addr len -- )

    BL FILL   ;

 

COUNT   Given the address addr of a counted string on the stack, return the address of the string and its character count.  Useful before words such as TYPE and CMOVE, which need a starting address of the text and a count as inputs.

 

CODE COUNT  ( addr -- addr+1 len )

    POP BX          \ Get address

    SUB AX, AX          \ Clear AH

    MOV AL, 0 [BX]      \ Get the count byte

    INC BX          \ Address+1

    PUSH BX         \ Push address

    1PUSH               \ Push count

    END-CODE

 

LENGTH  Given the address of a long string on the stack, return the address of the string and its length.  A long string is a string preceded by two bytes of length and  may have up to 65355 characters.

 

CODE LENGTH ( addr -- addr+2 len )

    POP BX          \ Get address

    MOV AX, 0 [BX]      \ Get the length

    ADD BX, # 2         \ Real address of data

    PUSH BX         \ Push it

    1PUSH           \   with length

    END-CODE

 

COUNTL  Like COUNT, but works with a long  seg:offset  address.

 

CODE COUNTL     ( seg addr -- seg addr+1 len )

    POP BX

    POP DS

    XOR AX, AX

    MOV AL, 0 [BX]

    INC BX

    PUSH DS

    PUSH BX

    MOV DX, CS

    MOV DS, DX

    1PUSH

    END-CODE

 

MOVE    Move the specified bytes from source to destination without overlapping.

 

: MOVE  ( source-addr dest-addr len -- )

    -ROT                \ Hide length

    2DUP U<             \ If source < dest

    IF   ROT CMOVE>     \   move from the end

    ELSE   ROT CMOVE        \ Else from the beginning

    THEN ;

UPC     Convert a character to upper case by looking up the code in the table ATBL.  Compare this code with that in F83 which subtracts 32 if the character is between a and z.

 

CODE UPC    ( char -- char' )

    POP AX          \ Get original character

    MOV BX, # ATBL      \ Put table base address in BX

    XLAT                \ Viola!  The character is converted.

    1PUSH               \ Push translated character

    END-CODE

 

UPPER   Take a string at the specified address and convert it to upper case.  It converts the string in place, so be sure to make a copy of the original if you need to use it later.

 

CODE UPPER  ( addr len -- )

    POP CX                          \ Get length

    POP DI                          \   and starting address

    PUSH SI                         \ Save IP

    MOV DX, ES                  \   and List Segment pointer

    MOV BX, DS

    MOV ES, BX                      \ Set ES to DS for source

    MOV SI, DI                      \ Set SI to DI

    MOV BX, # ATBL              \ Load BX with table base

    CLD                             \ Clear direction flag

    CX<>0 IF            \ Skip if CX=0

        HERE                 \ Leave address for LOOPNZ

            LODSB  \ Get a character

            XLAT        \ Convert to upper case

            STOSB       \ Store it back

        LOOPNZ              \   until all chars are done

    THEN

    MOV ES, DX                      \ Restore ES=List pointer

    POP SI                          \   and SI=IP

    NEXT

    END-CODE

        MOV DX, ES                  \   and List Segment pointer

        MOV BX, DS

        MOV ES, BX                      \ Set ES to DS for source

        MOV SI, DI                      \ Set SI to DI

        MOV BX, # ATBL              \ Load BX with table base

        CLD                             \ Clear direction flag

        CX<>0 IF            \ Skip if CX=0

            HERE                 \ Leave address for LOOPNZ

                LODSB  \ Get a character

                XLAT        \ Convert to upper case

                STOSB       \ Store it back

            LOOPNZ              \   until all chars are done

    THEN

-TRAILING   Return the address and length of a given string, ignoring trailing blanks.

 

CODE -TRAILING  ( addr len -- addr len1 )

    POP CX          \ original count

    POP DI          \ Get addr while put it back on the stack

    PUSH DI

    CX<>0 IF

        MOV AX, DS

        PUSH ES

        STD         \ Search backward

        MOV ES, AX

        ADD DI, CX

        DEC DI      \ Point to th e  last character

        MOV AL, # $20

        REPE SCASB      \ Repeat till a non-blank character

        0<> IF      INC CX  \ Correct the new count

        THEN

        CLD         \ restore forward searching direction

        POP ES      \ Restore ES used for scanning

    THEN

    PUSH CX         \ New count pushed back.

    NEXT

    END-CODE

 

COMP    This performs a string compare.  If the two strings are   equal, then COMP returns 0.  If the two strings differ, then COMP returns -1 or +1.  -1 is returned if string1 is less than string2.  +1 is returned if string1 is greater than string2.  All comparisons are relative to the ASCII order.

 

CODE COMP   ( addr1 addr2 len -- -1 | 0 | 1 )

    MOV DX, SI              \ Save IP

    POP CX              \ Length

    POP DI              \ Destination

    POP SI                  \ Source

    CX<>0 IF                \ Length is not zero?

        PUSH ES         \ Save ES

        MOV ES, SSEG        \ Source string in SSEG segment

        REPZ

        CMPSB           \ Compare two strings

        0<> IF              \ If strings are not equal

            0< IF

                MOV CX, # -1    \ Return 1 if string1>string2

            ELSE   

                MOV CX, # 1     \ Return -1 if string1<string2

            THEN

        THEN                \ CX=0 if string1=string2

    THEN

    MOV SI, DX              \ Restore IP

    POP ES              \ Restore ES

    PUSH CX             \ Push results

    NEXT

    END-CODE

 

CAPS-COMP   This code handles the string comparison where case is not significant.  Each character is converted to upper case before the comparison is made.  Thus, lower case a and upper case A are considered identical.

 

CODE CAPS-COMP  ( addr1 addr2 len -- -1 | 0 | 1 )

    MOV DX, SI          \ Save IP

    POP CX          \ Length

    POP DI          \ Destination

    POP SI              \ Source

    PUSH ES         \ Save ES

    MOV ES, SSEG        \ Source segment SSEG

    BEGIN

        JCXZ  0 $       \ Exit if the string is exhausted.

        MOV     AH, 0 [SI] \ Get a character from string1

        INC SI

        MOV ES: AL, 0 [DI]  \ Get a character from string2.

        INC DI

        OR AX, # $02020 \ Make both characters lower case before comparing.

        CMP AH, AL

        JNE 1 $     \ Exit if a character is not equal

        DEC CX

    AGAIN

1 $: 0< IF              \ Unequal exit

        MOV CX, # -1        \ string1 < string2

    ELSE

        MOV CX, # 1     \ string1 > string2

    THEN

0 $:    MOV SI, DX          \ Equal exit

    POP ES

    PUSH CX

    NEXT

    END-CODE

 

COMPARE Performs a string compare.  If CAPS is true, characters from both strings are converted to upper case before comparing.

 

: COMPARE   ( addr1 addr2 len -- -1 | 0 | 1 )

    CAPS @

    IF   CAPS-COMP  

    ELSE   COMP 

    THEN   ;

 

 

3.4.   DOS WORDS

 

 

OSF     A variable to indicate that an operating system call is in progress.  This flag is provided so that interrupt routines can test it to avoid clashing against DOS services.

 

FCDOS   A subroutine called by other assembler code to do INT 21H (DOS service call).  BP and SI are the critical FORTH registers which must be saved and restored.  OSF is set during the DOS call, and it can be tested by interrupt routines which call non-reentrant DOS functions.

 

LABEL FCDOS    

    PUSH SI         \ IP must be saved

    PUSH BP         \ BP is the return stack pointer

    INC CS: OSF WORD        \ Set OSF flag

    INT 33              \ DOS system service interrupt

    DEC CS: OSF WORD        \ Reset OSF flag

    POP BP          \ Restore BP and SI

    POP SI

    RET

    END-CODE

 

XFDOS   Call INT 21H with almost all possible register combinations.  This is the most general form of DOS service call in F-PC.

 

CODE XFDOS  ( DX CX BX AX ES DS -- CX BX AX CY)

    POP DI          \ Get all the input data

    POP DS

    POP AX

    POP BX

    POP CX

    POP DX

    PUSH ES         \ Save ES

    PUSH DS             \ Make ES=DS

    POP ES

    PUSH CS         \ Save a copy of CS for DS later

    MOV DS, DI          \ Real DS popped from the stack

    CALL FCDOS          \ Do the DOS 33 call

    POP DS          \ DS=CS

    POP ES          \ Restore ES

    MOV DX, # -1            \ Initialize DX to false

    U>= IF              \ Test the flag left by DOS call

        XOR DX, DX      \ If no error, clear the error flag

    THEN

    PUSH CX         \ Push the output data on stack

    PUSH BX

    PUSH AX

    PUSH DX

    NEXT                \   and exit

    END-CODE

 

BDOS        Load DOS function into AH and a parameter into DX, and then do a DOS service call.  Return the result placed in the AL register on the stack.  The BDOS calls were inherited from CP/M.  It is defined as a deferred word and vectored to <BDOS> to make it more flexible.

 

CODE <BDOS> ( n fun -- m )

    POP AX          \ Function spec

    MOV AH, AL

    POP DX          \ Parameter

    INT 33

The KEY and KEY? words in F-PC were designed to do much more than simply looking at the keyboard and returning a character or a flag.  They call the DOS keyboard service and do some preliminary work on the character before giving it back to the user.  A key filter is built-in so that the user can install special processes responding to different key strokes.  A background task chain is also built in KEY.  You can insert functions into this chain to be executed when a key is pressed.

 

Following are the words supporting the key filter and the key task chain.

CODE BIOSKEY?   ( --- f )

    BEGIN

        MOV AH, # 1     \ Question the keyboard

        PUSH SI     \ Save important Forth registers

        PUSH BP

        POP BP

        POP SI

        POP BP

        POP SI

    MOV AX, # -1            \ A key was pressed

    1PUSH               \   return with a true flag

    END-CODE

        PUSH SI

        PUSH BP

        POP BP

        POP SI

        CMP AX, # 0     \ Ignore Control BREAK, 00 Hex.

    1PUSH               \   and push it on the stack

    END-CODE

3.5.   LONG MEMORY WORDS

 

 

F-PC uses only a few 64K segments of the memory in a PC, but it allows you to use the entire memory space available to a PC.  To address memory locations outside of the Code Segment, two 16 bit words are needed for the address specification.  The first word in the address pair specifies the segment and the second specifies the address offset in that segment.  Memory words for addressing extended or 'long' memory space have the letter 'L' prefixed or appended to the corresponding name of a regular memory word.  To facilitate accessing the memory locations in the List Segment and Head segment, the memory words are prefixed with X for List Segment or Y for Head Segment.

 

?CS:        Push the CS register on the data stack.  It is the base segment address of the Code Segment.

 

CODE ?CS:   ( -- CS )

    PUSH CS         \ Push CS register

    NEXT                \ That's all

    END-CODE

 

?ES:        Push the ES register on the data stack stack.  It is the current segment register pointing to the beginning of a colon word list.

 

CODE ?ES:   ( -- ES )

    PUSH ES

    NEXT

    END-CODE

 

@L      Fetch a 16 bit value from extended memory.

 

CODE @L ( seg addr --- n )

    POP BX          \ Get address offset

    POP DS          \ Pop segment address into DS

    MOV AX, 0 [BX]      \ Fetch data at DS:BX

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    1PUSH           \ Push results on stack

    END-CODE

 

C@L     Similar to @L except returning only a byte value.

 

CODE C@L    ( seg addr --- byte )

    POP BX

    POP DS

    MOV AL, 0 [BX]      \ Fetch a byte here

    XOR AH, AH

    MOV BX, CS

    MOV DS, BX

    1PUSH

    END-CODE

 

C!L     Store a byte into the extended memory space.

 

CODE C!L    ( byte seg addr -- )

    POP BX          \ Pop offset

    POP DS          \ Pop segment

    POP AX          \ Pop byte value

    MOV 0 [BX], AL      \ Store to DS:BX

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

!L      Store a 16 bit value into a location specified by the seg:addr address pair.

 

CODE !L ( n seg addr -- )

    POP BX          \ Pop all parameters

    POP DS

    POP AX

    MOV 0 [BX], AX          \ Store 16 bit value

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

CMOVEL  Move a block of bytes from one extended memory location to another.

 

CODE CMOVEL ( sseg saddr dseg daddr count -- )

    CLD             \ Move forward

    MOV BX, SI          \ Save IP

    POP CX          \ Pop count

    POP DI          \ Pop destination offset

    POP AX          \ Pop destination segment

    POP SI              \ Pop source offset

    POP DS              \ Pop source segment

    PUSH ES         \ Save ES

    MOV ES, AX          \ Copy daddr to ES

    OR CX, CX           \ If count is zero, exit.

    0<> IF

        REPNZ       \ Otherwise, block move.

        MOVSB

    THEN

    POP ES          \ Restore ES to saved value

    MOV AX, CS          \ Restore DS

    MOV DS, AX

    MOV SI, BX          \ Restore IP

    NEXT                \ Done

    END-CODE

 

CMOVEL> Similar to CMOVEL except that the last byte is moved first to avoid overwriting moved data.

 

CODE CMOVEL>    ( sseg saddr dseg daddr count -- )

    STD             \ Reverse move direction

    MOV BX, SI          \ Save IP

    POP CX          \ Pop all data

    POP DI

    POP AX

    POP SI

    POP DS

    PUSH ES

    MOV ES, AX          \ Destination segment

    OR CX, CX           \ Skip if count=0

    0<> IF

        DEC CX

        ADD DI, CX      \ Offset to last destination byte

        ADD SI, CX      \ Offset to last source byte

        INC CX      \ Restore count

        REPNZ       \ Move from end to head

        MOVSB

    THEN

    POP ES          \ Restore registers

    MOV AX, CS

    MOV DS, AX

    MOV SI, BX

    CLD             \ Restore direction flag

    NEXT

    END-CODE

 

 

3.6.   MEMORY ALLOCATION WORDS

 

 

F-PC allocates and uses its memory according to the rules laid down by MS-DOS so that it can take advantages of all the services that MS-DOS provides.  This set of words is used by the system to arrange the various segments needed for F-PC to operate.  The user can also use this word set to request additional memory for his own application.  Memory not needed can be de-allocated and given back to DOS.

 

HEX

1000 CONSTANT #CODESEGS     \ Number of segments needed for Code Segments. 

1000 CONSTANT #LISTSEGS     \ Number of segments needed for definitions.

1000 CONSTANT #HEADSEGS     \ Number of segments needed for Heads. 64K bytes each.

: MEMCHK    ( f -- )

    IF                      \ If memory error

        ." Insufficient Memory"

        0 0 BDOS        \ Cold start

    THEN ;

 

DEALLOC De-allocate a block of memory previously allocated by  DOS.  The block number n must be that returned by ALLOC.  The flag returned is 0 if de-allocation is successful.

 

CODE DEALLOC    ( n -- f )

    MOV AH, # 49            \ De-allocation service number

    POP DX          \ Block number

    PUSH ES         \ We need ES to pass block number

    MOV ES, DX

    INT 21              \ Call DOS service

    u< if

        sub ah, ah      \ Not successful.  Error code.

    else

        mov ax, # 0     \ Success.  Clear error code.

    then

    POP ES          \ Restore ES

    1PUSH               \ Push flag.

    END-CODE

 

ALLOC   Request n 16- byte pages of memory from DOS.  If memory is successfully allocated, f will be 0, n2 is the pages allocated, and n1 is the base segment address of the allocated block of memory.  If f is 8, memory is not sufficient.  N2 is the pages actually available and n1 is garbage.

 

CODE ALLOC  ( n -- n1 n2 f )

    MOV AH, # 48        \ Allocation function number         

    POP BX          \ Request segments

    INT 21              \ Please?

    PUSH BX         \ Segment base address

    PUSH AX         \ Allocated segments

    u< if

        sub ah, ah      \ Not successful.  Error code

    else

        mov ax, # 0     \ Successful.

    then

    1PUSH               \ Push error flag

    END-CODE

 

SETBLOCK    Re-adjust the size of a memory block.  Memory block starts a 'seg' with a new size 'size'  in 16 byte pages.  f is the error flag.  If DOS failed to allocate, the error code will be 7, 8 or 9.  

 

CODE SETBLOCK   ( seg size -- f1 )

    POP BX                          \ get new size

    MOV AH, # $4A               \ setblock call

    POP DX

    PUSH ES

    MOV ES, DX

    INT $21

    U< IF   SUB AH, AH      \ Error occurred, keep error code in AL.

    ELSE    MOV AX, # 0     \ No error, clear AX.

    THEN

    POP ES

    1PUSH

    END-CODE

 

DOSVER  Get DOS version number.

 

: DOSVER    ( -- n )

    0 30 BDOS           \ Ask DOS for its

    0FF AND ;           \   version number

 

DEFER CURSORSET         \ Initialize the cursor characteristics.

CODE +XSEG      ( n1 -- n2 )

    POP AX

    ADD AX, XSEG                \ Add XSEG to n1, returning n2.

    1PUSH

    END-CODE

: SETYSEG   ( --- )             \ Set Head Segment + more space

    [ LABEL 'SETYSEG ]      \ Define a label here for bootstrape process.

        0 0 BDOS        \ Abort if DOS version too low

    CURSORSET ;         \ Initialize the cursor

 

 

3.7.   HEAD AND LIST SEGMENT WORDS

 

 

Here are all the words that manipulate memory in the Head Segment.  This segment is also called the Y Space in F-PC, and the prefix 'Y' is used to identify this set of words.  The base segment address of the Head Segment is stored in variable YSEG.  All addresses are offset from this segment address.  The dictionary in F-PC is broken into three parts: the code dictionary in the Code Segment, the head dictionary in the Head Segment, and the colon list dictionary in the List Segment.  The regular Forth memory words operate on memory in the Code Segment.  Similar memory words are defined for both the Head Segment and the List Segment.  These segment-implicit words are convenient to use in building the head and the colon list dictionaries.

 

YHERE   Return the address of the next available location above the head dictionary.

 

CODE YHERE  ( -- addr )

    PUSH YDP            \ Head dictionary pointer

    NEXT

    END-CODE

 

YS:     Tuck the base segment address of Head Segment under the address on top of the stack.

 

CODE YS:    ( n -- YSEG n )

    POP AX          \ Retain n

    PUSH YSEG           \ Tuck YSEG

    1PUSH               \ Push n on top

    END-CODE

 

Y@      Fetch an integer in the Head Segment.

 

CODE Y@ ( addr -- n )

    POP BX          \ Pop addr into BX for relative addressing

    MOV DS, YSEG        \ DS must point to YSEG

    PUSH 0 [BX]         \ Fetch and push

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

Y!      Store an integer in the Head Segment.

 

CODE Y! ( n addr -- )

    POP BX          \ Pop address

    MOV DS, YSEG        \ Use right segment in DS

    POP 0 [BX]          \ Pop n and store it

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

YC@     Fetch a byte in the Head Segment.

 

CODE YC@    ( addr -- char )

    POP BX

    SUB AX, AX          \ Clear the throat

    MOV DS, YSEG

    MOV AL, 0 [BX]      \ Get the byte

    MOV BX, CS

    MOV DS, BX

    1PUSH           \ Push on stack

    END-CODE

 

YC!     Store a byte in the Head Segment.

 

CODE YC!    ( char addr -- )

    POP BX

    POP AX

    MOV DS, YSEG

    MOV 0 [BX], AL      \ Store one byte

    MOV BX, CS

    MOV DS, BX

    NEXT

    END-CODE

 

Y,      Compile an integer on the top of the head dictionary.

 

CODE Y, ( n -- )

    MOV BX, YDP         \ Top of head dictionary

    ADD YDP # 2 WORD        \ Increment head pointer

    POP CX          \ Integer to be compiled

    MOV DS, YSEG        \ DS must point to YSEG

    MOV 0 [BX], CX      \ Write n to dictionary

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

YCSET   Set bits in a memory location in the Head Segment according to the bits set in byte.

 

CODE YCSET  ( byte addr -- )

    POP BX          \ Get address

    POP AX          \ Get bit pattern

    MOV DS, YSEG        \ DS points to YSEG

    OR 0 [BX], AL           \ Set bits

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    NEXT

    END-CODE

 

YHASH   Given a string and a vocabulary, return the address which holds the last link field address in a thread.  The hashing algorithm is:   2*( char1*2 + char2 ) + length .  This special hashing method distributes word definitions evenly among all the threads so that the least amount of time will be spent on searching for a word.

 

CODE YHASH  ( ystr vocaddr -- thread )

    POP DX          \ Address of vocabulary code

    POP BX          \ Address of string

    MOV DS, YSEG        \ Point DS to Head Segment

    MOV AX, 1 [BX]      \ Get first and second chars

    SHL AL, # 1         \ 2*char1

    MOV CL, 0 [BX]      \ Get count

    AND CX, # 31            \ Retain only word length

    DEC CX          \ Length=1?

    CX<>0  IF               \ If length>1,

        ADD AL, AH      \   add char2.

    ELSE    MOV AH, # 32        \ Else, add 32.

        ADD AL, AH

    THEN SHL AX, # 1        \ Multiply sum by 2

    ADD AL, 0 [BX]      \ Plus count byte

    AND AX, # #THREADS 1-   \ Limit it by # of threads

    SHL AX, # 1         \ Address offset

        ADD AX, DX          \   into thread table

    MOV CX, CS          \ Restore DS

    MOV DS, CX

    1PUSH               \ Push address of thread

    END-CODE

 

The List Segment is called X space in F-PC.  Memory words directed into this segment are prefixed with 'X'.  This words set is similar to that for the Head Segment.

 

The starting (base) segment address of the List Segment is stored in the variable XSEG.  The word list of a colon definition is addressed by its segment offset from this base segment address.  The code field address list in this definition is addressed by an address offset.  Thus we need both a segment address and an address offset to locate memory in the List Segment.  This method allows F-PC to use more than 64K bytes for the List Space.

 

XHERE   Return the current segment pointer and the address offset pointing to the top of list dictionary.

 

CODE XHERE  ( -- seg addr )

    PUSH XDPSEG     \ Current segment pointer

    PUSH XDP            \ Current offset address in the current segment

    NEXT

    END-CODE

 

X,      Compile an integer to the top of list dictionary.

 

CODE X, ( n -- )                \ XHERE !L  2 XDP +!

    POP AX          \ n

    MOV BX, XDP         \ Address offset

    MOV DS, XDPSEG      \ Current segment

    MOV 0 [BX], AX      \ Store value

    MOV BX, CS          \ Restore DS

    MOV DS, BX

    ADD XDP # 2 WORD        \ Increment address offset

    NEXT

    END-CODE

 

XC,     Compile a byte to end of the list dictionary.

 

CODE XC,    ( n -- )                \ XHERE C!L 1 XDP +!

    POP AX

    MOV BX, XDP

    MOV DS, XDPSEG

    MOV 0 [BX], AL      \ store byte

    MOV BX, CS

    MOV DS, BX

    INC XDP WORD

    NEXT

    END-CODE

 

 

3.8.   TERMINAL OUTPUT WORDS

3.9.   EXPECT WORDS

 

 

EXPECT is the word by which F-PC gets a line of command from the user.  As it is waiting for the user to complete entering the line, a limited amount of editing is also allowed.  In addition, F-PC maintains a table for all the control characters, which can cause specific actions immediately when a control character is entered.  Thus an application can use the control character table to design very powerful user interfaces like menu help system, hot keys, etc.  The words in this section show how this control character table is constructed and the implementation of several commonly used control characters like carriage-return, back-space and delete.

 

BS-IN       Backspace.  Beep if at the beginning of a line; otherwise, back up 1.  The second item on data stack, the character count in a line, must be decrmented by 1 until it becomes zero.  The top item is usually a character which is not used but preserved.

 

: BS-IN     ( n char -- 0 char | n-1 char )

    >R  DUP         \ Preserve char

    IF          1- BS EMIT      \ n>0, backspace

        #OUT @ 2- 0MAX 

        #OUT !          \ Adjust #OUT

    ELSE    BEEP            \ n=0, ring the bell

    THEN   R> ;         \ Restore char

 

DEL-IN  Delete a character.  Beep if at beginning of a line; otherwise, back up and erase the previous character.  DEL-IN is a deferred word, usually vectored to (DEL-IN).

 

: (DEL-IN)  ( n char -- 0 | n-1 )

    >R DUP

    IF      1-  BS EMIT         \ Back up

        SPACE BS EMIT   \ Erase previous character

        #OUT @ 4 -

        0MAX    #OUT !      \ Save current #OUT

    ELSE    BEEP

    THEN    R> ;

 

DEFER DEL-IN    ' (DEL-IN) IS DEL-IN

: BACK-UP   ( n c -- 0 c )

    >R

    DUP BACKSPACES      \ Back up a line 

    DUP SPACES          \ Erase the line

    BACKSPACES          \ Back up again

    0  R> ;

: RESET-IN  ( c -- )

    FORTH           \ Restore FORTH vocabulary  

    TRUE ABORT" Reset"  ;   \ Abort

    PRINTING !  ;           \ Store back

: (ESC-IN)  ( addr count c -- addr count+1 c )

    >R

    2DUP + @ EMIT       \ Print a character in string

    1+              \ Bump count

    R> ;

 

DEFER ESC-IN    ' (ESC-IN) IS ESC-IN

 

CR-IN   Finish input and remember the number of characters in SPAN.

 

: CR-IN ( m a n c -- m a m C )

    >R SPAN !           \ Store n in SPAN  

    OVER            \ Replace n by m

    BL EMIT R>  ;           \ Print a space

 

CHAR    Process an ordinary character by appending it to the input buffer.  A string of n bytes is already in the buffer at addr.  It is deferred to (CHAR).

 

: (CHAR)    ( addr n char -- a n+1 char )

    dup>r           \ Copy char to return stack

    3DUP EMIT           \ Emit char to screen

    + C!                \ Store char to input buffer

    1+                  \ Bump buffer count

    R> ;                \ Recall char

 

DEFER CHAR      ' (CHAR) IS CHAR

DEFER ^CHAR     ' CHAR   IS ^CHAR

 

KEYTABLE    Similar to a case structure; it processes the 32  control characters received from keyboard.  It is deferred to NORM-KEYTABLE.  This case structure can be changed to respond to control characters selected by plugging in appropriate words in the table.  Later features, especially the key commands in the editor, replace the KEYTABLE functions.

 

: NORM-KEYTABLE

    EXEC:

   ^CHAR   ^CHAR  ^CHAR  RES-IN ^CHAR  ^CHAR   ^CHAR  ^CHAR

    DEL-IN  ^CHAR  ^CHAR  ^CHAR  ^CHAR  CR-IN   ^CHAR  ^CHAR

    P-IN    ^CHAR  ^CHAR  ^CHAR  ^CHAR  BACK-UP ^CHAR  ^CHAR

    BACK-UP ^CHAR  ^CHAR  ESC-IN ^CHAR  ^CHAR   ^CHAR  ^CHAR ;

 

DEFER KEYTABLE  ' NORM-KEYTABLE IS KEYTABLE

 

EXPECT  Get a string from the terminal and place it in the buffer provided.  Perform a limited amount of line editing.  Save the number of input characters in the variable SPAN.  It uses NEXPECT which can accept a string into the middle of the input buffer.

 

: NEXPECT   ( addr len start -- )

    dup>r               \ Save the starting count

    IF OVER R@ TYPE THEN    \ If not zero, type prior string

    DUP SPAN !              \ Save len in SPAN, maximum characters expected

    SWAP R>         \ len addr start --

    BEGIN       2 PICK OVER -  \ len addr #so-far #left --

    WHILE       2>R >R KEY  \ Accept one character

            SWAP 2R> ROT    \  Silly way to ensure stack is clean in doing

                    \ a task switch.

            DUP BL <    \ A control character?

        IF      DUP KEYTABLE    \ Yes. Process it.

            DROP

        ELSE    DUP 127 =   \ Is it a DEL?

            IF   DEL-IN \ Yes.  Delete previous character

            ELSE   CHAR \ Put it into the input buffer

            THEN  DROP

        THEN

    REPEAT  3DROP ;     \ Repeat for next character

 

: (EXPECT)  ( addr len -- ) 0   NEXPECT  ;        

 

DEFER EXPECT   ' (EXPECT) IS EXPECT

 

TIB     Leave the address of the text input buffer on the data stack.

 

CODE TIB    ( --- addr )

    PUSH 'TIB           \ Address is in a user variable

    NEXT

    END-CODE

 

MORE?   Return a true flag if there are still characters un-interpreted in the input buffer.

 

CODE MORE?      ( -- flag )                 \ Is words left in input stream?

    MOV AX, >IN

    SUB AX, #TIB

    SBB AX, AX

    1PUSH  

    END-CODE

 

QUERY   Get a line of input from the user and place it in the terminal input buffer at TIB.

 

: QUERY ( -- )

    TIB COLS EXPECT         \ Wait for a line from keyboard

    SPAN @ #TIB !       \ Store line length in #TIB also

    >IN OFF  ;          \ Clear interpreter character pointer

 

VARIABLE DISK-ERROR     \ Leftover from F83.  Not used in F-PC.

-2 CONSTANT LIMIT           \ Last addressable word in Code Space

LIMIT 10 - CONSTANT FIRST       \ Another leftover pointer from F83

3.10.   NUMBER CONVERSION WORDS

 

 

All data are stored as binary integers in F-PC.  Numbers input from the keyboard and output to console have to be represented in ASCII strings for the user's benefit.  This set of words converts binary numbers to ASCII strings and also converts ASCII number strings to binary numbers.  It also gives the user tools to control the formats of the input/output ASCII number strings.

 

The user variable BASE contains the current number base which is used in converting numbers between the internal binary form and the external ASCII form.  It gives the Forth user great power in choosing the best way to present numbers in the most convenient form.

 

 

HEX     All subsequent numeric conversions  will be done in hexadecimal.

 

: HEX       ( -- )      16 BASE !  ;

 

DECIMAL All subsequent numeric conversions will be done in decimal.

 

: DECIMAL   ( -- )      10 BASE !  ;

 

OCTAL   All subsequent numeric conversions will be done in octal.

 

: OCTAL ( -- )      8 BASE !  ;

 

DEFER DEFAULT   Command tail processor which executes words given after F-PC in a DOS command line.  The first word in the command tail is a file name.  DEFAULT opens this file when F-PC is invoked.

 

DIGIT       Return a flag indicating whether or not a character is a valid digit in the given base.  If so, return converted value and true; otherwise, return the original char and false.

 

CODE DIGIT  ( char base -- n f )

    POP DX          \ base

    POP AX          \ char

    PUSH AX         \ Save a copy of char

    SUB AL, # ASCII 0       \ Less than 0?

    JB 0 $              \ Yes.  Return false.

    CMP AL, # 9         \ Greater than 9?

    > IF

        CMP AL, # 17        \ Less than 'A'?

        JB 0 $          \ Fail again

        SUB AL, # 7     \ Adjust for 'A' and above

    THEN

    CMP AL, DL          \ Greater than base?

    JAE 0 $             \ Yes.  Fail.

    MOV DL, AL          \ Converted value

    POP AX          \ Discard char

    MOV AX, # TRUE      \ Get true flag

    2PUSH               \ Push them on stack

0 $:    SUB AX, AX          \ Common failure exit.

    1PUSH

    END-CODE

 

DOUBLE? Returns true if a period was encountered in the input number string.

 

: DOUBLE?   ( -- f )

    DPL @ 1+            \ DPL was initialized to -1

    0<> ;               \ True if anything else

 

CONVERT Starting with an unsigned double number ud1 and a counted string at addr1, convert the string to a number in the current base and add it to ud1.  Leave results and the address of the unconvertable digit on stack.

 

: CONVERT   ( ud1 addr1 -- ud2 addr2 )

    BEGIN   1+  dup>r       \ Skip count

        C@  BASE @  DIGIT   \ Convert one digit

    WHILE   SWAP        \ Exit if not a digit

        BASE @ UM*  DROP    \ Multiply d1 with base

        ROT  BASE @ UM*  D+     \ Add digit*base

        DOUBLE?         \ Increment DPL if digit is

        IF  DPL INCR THEN  \   after decimal point

        R>          \ Restore incremented addr1

    REPEAT  DROP  R>  ;     \ d2 is the converted double integer.  Addr2 points to

                    \   the non-digit.

 

(NUMBER?)   Given a string containing at least one digit, convert it to a double integer.  The string must be terminated with an ASCII space.

 

: (NUMBER?) ( addr -- d flag )

    0 0  ROT            \ Place 0.0 under addr

    DUP 1+ C@           \ Get first character in string

    ASCII -  =              \ Is it a '-' sign?

    DUP  >R  -              \ Save the sign on return stack and back up if not a - sign.

    DPL -1!         \ Initialize DPL to -1

    BEGIN   CONVERT         \ Convert to a double integer

        DUP C@          \ Is non-digit a decimal point

        ASCII , ASCII /     \   or something like it,

        BETWEEN     \   between , and / ?

    WHILE   DPL 0!      \ Yes.  Mark it in DPL.

    REPEAT              \ Convert the part after decimal point.

    -ROT  R>            \ Conversion done. Retrieve sign.

    IF  DNEGATE  THEN           \ Negate if sign was -.

    ROT C@ BL =  ;      \ Make sure that the string is delimited by Blank.

 

NUMBER? Convert a counted string at addr to a double integer.  It takes into account a leading minus sign, and stores a pointer to the last delimiter in DPL.   The string must end with a blank.  Leave a true flag if successful.

 

: NUMBER?   ( addr -- d flag )

    FALSE           \ Push a false flag for testing

    OVER COUNT BOUNDS   \ Scan characters in the string

    ?DO     I C@            \ Get one character

        BASE @ DIGIT NIP    \ Is it a digit?

        IF DROP TRUE LEAVE \ Yes.  Leave the loop with a true

        THEN

    LOOP                \ addr f --

    IF  (NUMBER?)       \ If valid number, convert.

    ELSE  DROP  0 0 FALSE  \ Else leave 0.0 and false

    THEN  ;

 

NUMBER  Convert a counted string at a1 into a double number d1.  It will be nice if we can specify hex numbers without changing BASE.  A simple method used in F-PC is to make the interpreter to  accept numbers prefixed with $ as hex numbers, ASCII code with a ' (tick) prefix, and control code with a ^ prefix.

 

: %$NUM         ( a1 -- d1 f1 )             \ process as a hex number $A123

    dup>r DUP COUNT 1- 0MAX >R

    DUP 1+ SWAP R> CMOVE        \ Extract the $.

    DUP C@ 1- OVER C!           \ Shorten count by 1.

    BL OVER COUNT + C!          \ Append a blank to string.

    BASE @ >R                       \ Save the base for later restoration.

    HEX NUMBER?                 \ Try to convert the number in HEX

    R> BASE !                  \ Restore the BASE.

    DUP 0=                          \ If its not a number, restore the $.

    IF      R@ COUNT >R DUP 1+ R> CMOVE>

    R@ C@ 1+ R@ C!

    ASCII $ R@ 1+ C!

    THEN    r>drop ;

 

: %'NUM         ( a1 -- d1 f1 )             \ process as an ascii char 'A'

    STATE @

    IF          DROP

        TIB >IN @ 3 - + C@ 0

    ELSE    2+ C@ 0

    THEN    TRUE DPL ON ;

 

: %^NUM         ( a1 -- d1 f1 )         \ process as a control char ^A

    2+ C@ $1F AND 0 TRUE DPL ON ;

 

DEFER $NUM      ' %$NUM   IS $NUM

DEFER 'NUM      ' %'NUM   IS 'NUM

DEFER ^NUM      ' %^NUM   IS ^NUM

DEFER #NUM      ' NUMBER? IS #NUM

 

CODE %NUMBER    ( a1 -- d1 f1 ) \ Call colon words inside a code word. 

\ Convert count delimited string at a1 into double number.  Special prefixes allowed.

    MOV DI, SP

    MOV BX, 0 [DI]

    MOV AL, 1 [BX]

    CMP AL, # ASCII $           \ test for leading $

    0= IF   JMP ' $NUM          \ process as HEX

    THEN

    MOV AL, 1 [BX]

    MOV AH, 3 [BX]

    CMP AX, # ASCII '  dup flip +   \ test for lead & trail '

    0= IF   JMP ' 'NUM      \ process as ascii char

    THEN

    MOV AX, 0 [BX]

    CMP AX, # ASCII ^ flip $02 +    \ test for lead ^ & count = 2

    0= IF   JMP ' ^NUM      \ process as control char

    THEN   

    JMP ' #NUM          \ else process as a number

    END-CODE

 

: (NUMBER)      ( a1 -- d1 )        \ Convert count delimited string at a1 into a double number.

    %NUMBER NOT ?MISSING ;

 

DEFER NUMBER    ' (NUMBER) IS NUMBER

 

When we convert a binary number to an ASCII number string, the number string is constructed starting at PAD.  New digits converted are added to PAD buffer towards the low memory.  The least significant digit is placed at PAD, the next digit at PAD minus 1, and so forth.  The pointer pointing to the last converted digit is stored in the system variable HLD.  When the conversion is completed, the number string between (HLD) and PAD can be sent to the output device.

 

HOLD        Save char in the numeric output string under construction.

 

: HOLD      ( char -- )

    HLD DECR            \ Move number string pointer

    HLD @ C!   ;            \ Add char to number string

 

<#      Start numeric conversion.  Set up the output number string below PAD.

 

: <#        ( -- ) 

    PAD  HLD  !  ;          \ Init number string pointer

 

#>      Terminate numeric conversion.  Return addr and count of the number string constructed.

 

: #>        ( d -- addr len )

    2DROP           \ Discard d.  Conversion completed.

    HLD  @          \ First digit of number string

    PAD  OVER  -  ;     \ Character count

 

SIGN        If n is negative, insert a minus sign into the string.

 

: SIGN      ( n -- )

    0<

    IF  ASCII - HOLD  THEN  ;   \ Add '-' to number string

 

#       Convert a single digit in the current base and add the digit to the number string under construction.

 

: #    ( -- )

    BASE @ MU/MOD       \ Convert a digit

    ROT 9 OVER <            \ Adjust for alphabetic character

    IF  7 + THEN

    ASCII 0  +  HOLD  ;     \ Add digit to number string

 

#S      Convert a double integer d1 until it is finished, or reduced to 0.

 

: #S        ( d1 -- 0 0 )

    BEGIN 

        #           \ Convert a digit

        2DUP  OR        \   until d1 is reduced to 0

    0=  UNTIL  ;

 

(U.)        Convert an unsigned 16 bit integer to a string.

 

: (U.)      ( u -- addr len )   

    0    <# #S #>   ;

 

U.      Output u as an unsigned single integer with a trailing space.

 

: U.        ( u -- )      

    (U.)   TYPE SPACE   ;

 

U.R     Output u as an unsigned single integer right justified in a field of l columns.

 

: U.R       ( u l -- )     

    >R   (U.)               \ Convert unsigned integer

    R> OVER - SPACES        \ Pad with enough spaces

    TYPE   ;            \   so that number is right justified

 

(.)     Convert a signed 16 bit integer to a string.

 

: (.)       ( n -- addr len )   

    DUP ABS 0  

    <# #S   ROT SIGN   #>   ;

 

.       Output n as a signed single integer with a trailing space.  Free-format output.

 

: .     ( n -- )       

    (.)   TYPE SPACE   ;

 

.R      Output n as a signed single integer right justified in a field of l columns.  Formatted output.

 

: .R        ( n l -- )     

    >R   (.)  

    R> OVER - SPACES  

    TYPE   ;

 

(UD.)       Convert an unsigned double integer ud to a string.

 

: (UD.)     ( ud -- addr len )  

    <# #S #>   ;

 

UD.     Output ud as an unsigned double integer with a trailing space.

 

: UD.       ( ud -- )      

    (UD.)   TYPE SPACE   ;

 

UD.R        Output ud as an unsigned double integer right justified in a field of l columns.

 

: UD.R     ( ud l -- )    

    >R   (UD.)  

    R> OVER - SPACES   TYPE  ;

: (D.)     ( d -- addr len )   

    TUCK DABS   <# #S   ROT SIGN  #>   ;

3.11.   THE PARSING WORDS

 

 

Parsers are very profound subjects in computer science.  You must go to a graduate school in computer science to learn about them.  They are complicated because they are tools to decompose source code in a high level programming language to some form that a computer can do things about.  On the contrary, the parser in Forth is very simple because the language syntax in Forth is very simple.  All the F-PC parser does is to extract a word, which is a string delimited by blank characters or some other characters you specified, and place it in the Word Buffer just above the code dictionary.  The text interpreter will then search the dictionary for this word so that it will be executed or compiled.  If the word is a number string, the text interpreter will convert it to a number and either push it on the data stack or compile it as a literal.  This set of words supports the F-PC parser, which is a standard Forth word WORD.

 

In F-PC 3.5, WORD is defined completely in assembly.  SKIP, SCAN, /STRING, and PARSE are not used to build WORD.  They are preserved for F83 compatibility, and for some applications where specialized parsers have to be handcrafted.

 

SKIP        Given the address and length of a string, and a character to look for, run through the string while we continue to find the character.  Leave the address of the first mismatch and the length of the remaining string.

 

CODE SKIP   ( addr1 len1 char -- addr2 len2 )

    POP AX          \ Pop char

    POP CX          \ Pop len1

    JCXZ 0 $            \ Done if len=0

    POP DI          \ Pop addr1

    PUSH ES             \ Save ES

    MOV ES, SSEG        \ Use Scan/Search Segment

    REPZ                \ Repeat if character=char

    SCASB           \ Skip over char's

    POP ES          \ Restore ES

    0<> IF              \ If string is not yet exhausted

        INC CX          \   Back up len of string

        DEC DI      \   and addr to the character

    THEN                \   different from char

    PUSH DI         \ Push addr2

    PUSH CX         \ Push len2

    NEXT

0 $:    PUSH CX         \ len=0 case

    NEXT

    END-CODE

 

SCAN        Given the address and length of a string, and a character to look for, run through the string until we find the character.  Leave the address of the match and the length of the remaining string.

 

CODE SCAN   ( addr len char -- addr' len' )

    POP AX

    POP CX

    JCXZ 0 $

    POP DI

    PUSH ES

    MOV ES, SSEG

    MOV BX, CX

    REPNZ           \ Same as SKIP except test for

    SCASB           \   not equal.

    POP ES

    0= IF

        INC CX

        DEC DI

    THEN

    PUSH DI

    PUSH CX

    NEXT

0 $:    PUSH CX

    NEXT

    END-CODE

 

/STRING Index into the string by n.  Return addr+n and   len-n.

 

CODE /STRING    ( addr len n -- addr' len' )

    POP AX          \ n

    POP BX          \ len

    PUSH BX         \ Save len in case of return

    CMP BX, AX          \ n > len ?

    U<= IF              \ If so select the smaller one

        XCHG BX, AX         \ AX =smaller of AX and BX

    THEN

    POP BX

    POP DX

    ADD DX, AX          \ addr'

    PUSH DX

    SUB BX, AX          \ len'

    PUSH BX

    NEXT

    END-CODE

 

SOURCE  Return the address and length of the string to be scanned from the input stream which is stored at TIB.  It is not used by F-PC but kept here for F83 compatibility.

 

CODE SOURCE ( -- addr len ) \ TIB #TIB @

    MOV DX, 'TIB

    MOV AX, #TIB

    2PUSH

    END-CODE

 

PARSE   Scan the input stream until a delimiting char is encountered.  Update >IN pointer.   Leave the address and length of the enclosed string on the stack.  It function is now absorbed into SOURCE-PARSE-WRD, but kept here to be compatible with F83.

 

: PARSE ( char -- addr len )

    >R   SOURCE             \ Source address and buffer length

    >IN @ /STRING       \ Start searching from >IN

    OVER SWAP R> SCAN   \ Scan for char

    >R OVER -           \ Leave addr and len

    DUP R> 

    0<> -  >IN +!  ;            \ Update >IN to end of found string

 

WORD    Parse the input stream for a string delimited by char and return a counted string at HERE.  In F-PC 2.25, the word buffer was defined in a deferred word 'WORD.  However, since 'WORD was initialized to HERE and never got changed, it is deleted in F-PC 3.5 and HERE is used in its place.   Note there is always a blank following the string.  Scan the input stream until char is encountered.  Skip over leading char's.  Update >IN pointer, and leave address and length of the enclosed string.  This is an all-code realization of WORD to speed up the F-PC 3.5 interpreter/compiler.  Earlier versions of WORD in F-PC 2.25 and F83 were colon definitions and were much slower.  By defining WORD in code, many intermediate words are also eliminated, making F-PC 3.5 simpler.

 

CODE WORD   ( char -- addr )

    MOV DI, 'TIB            \ Terminal input buffer

    MOV CX, #TIB            \ Length of TIB

    POP BX          \ char to match

    PUSH ES         \ Save ES for later restoration

    MOV DX, DS

    MOV ES, DX          \ ES=DS from now to the end

    MOV AX, >IN         \ Current character pointer

    CMP CX, AX          \ Select smaller of len and >IN

    U<= IF

        MOV AX, CX      \ AX = smaller of AX and CX

    THEN

    ADD DI, AX          \ Starting address

    SUB CX, AX          \ Remaining string length

    MOV AX, BX          \ Char for searching

    CX<>0 IF            \ Search only if string is not null

        REPZ            \ Skip over leading char's

        SCASB

        0<> IF   

            INC CX  \ Remaining count

            DEC DI  \ First character of parsed string

        THEN

    THEN

    MOV DX, DI

    MOV AX, BX

    CX<>0 IF            \ Some more characters left?

        REPNZ       \ Yes.  Scan to terminating char

        SCASB

        0= IF           \ If char is found

            INC CX  \   backup pointer and count

            DEC DI

        THEN

    THEN

    SUB DI, DX          \ Update string length

    MOV BX, #TIB

    MOV AX, DX

    CX<>0 IF            \ If TIB is not yet exhausted

        DEC CX      \   count must be adjusted

    THEN

    SUB BX, CX          \ >IN must be adjusted also

    MOV >IN BX          \ Update >IN to end of found string

    MOV BX, UP

    MOV DX, DP [BX]     \ Get HERE, address of the word buffer on top of code dictionary

    MOV CX, DI

    MOV DI, DX

    MOV 0 [DI], CL      \ Copy count byte

    INC DI         

    MOV BX, IP          \ Save SI, which we need to move string

    MOV IP, AX          \ Address of source string

    REPNZ                       \ Copy string from input buffer to word buffer

    MOVSB

    MOV AL, # 32            \ Append a space to end of parsed string

    STOSB

    MOV IP, BX          \ Restore SI

    POP ES                              \ Restore ES

    PUSH DX

    NEXT

    END-CODE
