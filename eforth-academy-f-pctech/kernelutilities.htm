CHAPTER 6.   KERNEL UTILITIES

 

 

 

 

 

Kernel Utilities are words loaded into the F-PC Kernel with the KERNEL1-4.SEQ files.  They provide I/O and file words needed by the Kernel but generally not considered as part of the Kernel because they are specific to the host computer and the underlying operating system.  Since they are loaded from a separate set of files, it is convenient to group them in one place.

 

The loading sequence of these files in building the F-PC Kernel is shown at the end of the META86.SEQ file:

    FLOAD KERNEL1.SEQ

    FLOAD VIDEO.SEQ

    FLOAD KERNEL2.SEQ

    FLOAD VIDEO2.SEQ

    FLOAD KERNEL3.SEQ

    FLOAD EQUCOLON.SEQ

    FLOAD SAVEREST.SEQ

    FLOAD HANDLES.SEQ

    FLOAD SEQREAD.SEQ

    FLOAD FPATH.SEQ

    FLOAD DEFAULT.SEQ

    FLOAD KERNEL4.SEQ

 

The discussion in this Chapter follows the above loading order except the KERNEL files, which were discussed in the previous two Chapters.

 

 

6.1.   VIDEO OUTPUT WORDS

 

 

VIDEO1.SEQ and VIDEO2.SEQ contain the word set which allow F-PC to access the video displays in an PC or its clones.  One of the problems is that there are so many different video display cards for PC.  F-PC tries its best to identify the video card used in the system and to deal with it appropriately.

 

VIDEO-SEG   A variable that holds the segment address of the source from where text is sent to the output devices.  It is normally set to the value of ?CS: to display text stored in the Code Segment, but the editor changes it to display text from an external edit buffer segment.  It is defined here with other variables and values controlling various attributes of the video display:

 

VARIABLE ATTRIB   7 ATTRIB !-T              \ display attribute value

VARIABLE VIDEO-SEG                          \ Segment of display

VARIABLE VMODE-VAR                  \ Video mode save variable

VARIABLE BLANKING           \ Are we blanking during screen drawing?

0 VALUE COLS                \ Screen columns

0 VALUE ROWS                    \ Screen rows

0 VALUE CROWS              \ Cursor DOT rows

 

?VMODE  Read the current video mode from the BIOS.  A value of 7 is normal for monochrome card, and a value of 2 is for a CGA card.

 

CODE ?VMODE ( -- n )            \ Get the video mode from DOS

    MOV AH, # $0F

    INT $10

    SUB AH, AH

    MOV VMODE-VAR AX                \ Save video mode in VMODE-VAR

    PUSH AX

    MOV AX, # $40                       \ absolute segment $40:00

    MOV DS, AX                          \ goes into DS

    MOV BL, $4A                         \ get the # of COLS from    $40:$4A

    MOV CL, $84                         \ get the # of ROWS FROM    $40:$84

    MOV BH, $60                         \ get the Cursor bottom row $40:$60

    MOV AX, CS                          \ restore DS from CS

    MOV DS, AX

    MOV ' CROWS >BODY BH

    MOV ' COLS  >BODY BL

    CMP CL, # 24

    < IF    MOV CL, # 25            \ At least 25 rows

    ELSE    INC CL

    THEN

    MOV ' ROWS >BODY CL

    NEXT

    END-CODE

 

INITMONO    A deferred word used to initialize the monochrome display attribute by setting the >ATTRIBn words.  See the file MONOCROM.SEQ.

 

INITCOLOR   A deferred used to initialize the color display attribute by setting the >ATTRIBn words.  See the file MONOCROM.SEQ, and COLOR.SEQ.

 

DEFER INITMONO      ' NOOP IS INITMONO

DEFER INITCOLOR     ' NOOP IS INITCOLOR   

 

VMODE.SET   Set the VIDEO-SEG variable after testing the current video mode, and perform any needed initialization required by executing the INITMONO, or INITCOLOR as needed.

 

HEX

: VMODE.SET ( -- )

    ?VMODE 7

    IF  0B000   INITMONO        \ Monochrome text buffer

    ELSE    0B800   INITCOLOR       \ Color card text buffer

    THEN    VIDEO-SEG ! ;

DECIMAL

 

CGA video cards were the oldest video card available on IBM-PC's.   It is extremely dumb and needs lots of software attentions.  You have to wait for vertical retrace interval to write characters into the video memory buffer.  Otherwise, you will cause snow noise to appear on the screen.  Other more advanced video displays do not have this problem.  BLANK.COLOR will write to CGA only during vertical retrace.

 

CODE BLANK.COLOR    ( -- )                  \ Blanks screen if in COLOR mode

    MOV BX, # 1                             \ Bit mask for retrace

    MOV AX, VMODE-VAR

    CMP AX, # 7                             \ If video mode <> 7 (mono)

    0<> IF  MOV AX, BLANKING

        OR AX, AX

        0<> IF  MOV DX, # 986   \ CGA status port

            BEGIN   IN AL, DX   \ Wait for retrace

                TEST AL, BX

            0<> UNTIL

            MOV DL, # 216       \ Address control reg

            MOV AL, # 37        \ Disable the CRT

            OUT DX, AL

        THEN

    THEN

    next

    end-code

 

CODE SHOW.COLOR     ( -- )                 \ Re-enable the display

    MOV AX, VMODE-VAR

    CMP AX, # 7

    0<> IF  MOV AX, BLANKING

        OR AX, AX

        0<> IF  MOV DX, # 984           \ CGA mode control reg

            MOV AL, # $2D           \ Enable byte for mode 3

            OUT DX, AL

        THEN

    THEN

    NEXT

    END-CODE

6.2.   VALUES: CONSTANTS AS VARIABLES

 

 

Source File is EQUCOLON.SEQ.  There are two advantages in treating a constant like a variable:  the first is that a constant is faster in getting the data because you don't have to first get the address and then fetch it; and the second is that program becomes cleaner and easier to understand by eliminating @'s.  Variables are more often fetched than stored.  Defining a variable as a constant will thus improve the execution speed, with a small improvement on program size.

 

However, the Forth-83 Standard clearly dictates that the location where constants are stored is not known to the user, and he should not attempt to modify constants after they are defined.  If you like to maintain your program according to Forth-83, skip this section.  If you want to really squeeze out all the loose cycles from your PC, you will enjoy reading it and make some good use of this word set.

 

Many people evaluating F-PC system objected to the practice in changing the values of constants.  Tom Zimmer compromised by calling these variable constants VALUEs.  VALUE is simply an alias of CONSTANT.  All words operating on a VALUE will operate on a CONSTANT identically.  This is not is new practice.  European Forth users have been using it for years, but they call it the 'TO' concept.  VALUE was defined in Sec. 4.8.

 

Following are code words which manipulate data stored in the parameter field of the following word in a colon definition.  They are very fast because the code field address of the following word can be obtained by a LODSW ES:  machine instruction.  The data stored in the parameter field can then be accessed by a BX relative mode instruction.

 

%@>     It must be compiled into a colon definition.  At run-time, it pushes the value in the parameter field of the following definition onto the data stack.

 

CODE %@>    ( --  n )

    LODSW ES:           \ 12 + 2 cycles. Get cfa of next word.

    MOV BX, AX          \  2     cycles.

    PUSH 3 [BX]         \ 17 + 9 cycles. Fetch data in pfa.

    NEXT

    END-CODE

 

%!>     Primitive used by the following definitions.  It is compiled into a colon definition, and stores value on the stack into the parameter field of the following definition, which must be a constant, a variable, or a VALUE.  Only to be used in a colon definition.

 

CODE %!>    ( n -- )

    LODSW ES:           \ 12 + 2 cycles. Get cfa of next word.

    MOV BX, AX          \  2     cycles.

    POP 3 [BX]          \ 17 + 9 cycles. Store n to its pfa.

    NEXT

    END-CODE

 

CODE    %U@>    ( -- n1 )       \ Fetch the DATA field of a USER definition in user space.

    LODSW ES:

    MOV BX, AX

    MOV BX, 3 [BX]

    ADD BX, UP

    PUSH 0 [BX]

    NEXT

    END-CODE

   

CODE    %U!>    ( n1 -- )       \ Store into the DATA field of a USER definition in user space.

    LODSW ES:

    MOV BX, AX

    MOV BX, 3 [BX]

    ADD BX, UP

    POP 0 [BX]

    NEXT

    END-CODE

 

%+!>        Increment the value stored in the parameter field of the following word by the amount n on the data stack.  Used in colon definitions only.

 

CODE %+!>   ( n -- )

    POP CX          \ Increment value

    LODSW ES:

    MOB BX, AX          \ Get pfa of the next word

    ADD 3 [BX] WORD     \   and increment it by n.

    NEXT

    END-CODE

 

I%NCR>  Increment contents in the parameter field of the following word by one.  It is used to modify the following value, constant or variable.  Used in colon definitions only.

 

CODE %INCR> ( -- )

    LODSW ES:           \ Get cfa

    MOV BX, AX

    INC 3 [BX] WORD     \ Increment parameter

    NEXT

    END-CODE

 

%DECR>  Decrement contents in the parameter field of the following word by one.  It is used to modify the following value, constant or variable in a colon definition.  Used only in a colon definition.

 

CODE %DECR> ( -- )

    LODSW ES:

    MOV BX, AX

    DEC 3 [BX] WORD     \ Decrement parameter field

    NEXT

    END-CODE

 

%OFF>   Zero the following value/constant/variable.  Somewhat faster than OFF.  Store 0 into the parameter field of following definition.  Only to be used in a colon definition.

 

CODE %OFF>  ( -- )     

    LODSW ES:           \ Get cfa of next word

    MOV BX, AX          \ Move to BX for relative addressing

    MOV 3 [BX], # 0  WORD   \ Store 0 into parameter field

    NEXT

    END-CODE

 

%ON>    Turn on the following value/constant/variable.  Somewhat faster than <name> ON.  Store -1 into the parameter field of the following definition.  Only used in a colon definition.

 

CODE %ON>   ( -- )     

    LODSW ES:

    MOV BX, AX

    MOV 3 [BX], # -1 WORD

    NEXT

    END-CODE

 

CODE   %&>  ( -- a1 )       \ Return the BODY a1 address of the following word in a definition.

    LODSW ES:

    ADD AX, # 3

    1PUSH

    END-CODE

 

Following are high level words operating on VALUEs.  They can be used in colon definitions and can also be executed interactively.  Used inside a colon definition, they compile low level words shown above.  These words can be omitted in a stand-alone application.  F-PC 3.5 allows you to set values in user variables as well.  To support user variables, %U@>,%U!>, ?USER, and ?NOUSER are added.

 

: ?NOUSER   ( a1 -- a1 )        \ Test a1 to verify it is not a USER definition, if it is, abort.

    DUP >IS OVER >BODY <>

    ABORT" Won't work on USER words." ;

   

: ?USER ( a1 -- a1 f1 )     \ test a1, is it a user word, return TRUE if it is else FALSE.

    DUP >IS OVER >BODY <> ;

 

@>      Fetch the contents from the parameter field of the next word to the stack.  May be used outside of a colon definition.

 

: @>  <name>        ( -- n )

    STATE @

    IF      ' ?USER

        IF      COMPILE %U@>

        ELSE    COMPILE %@>

        THEN    X,

    ELSE    ' >IS @

    THEN    ; IMMEDIATE

 

!>      Store the value n on the stack into the parameter field of the following value, constant or variable.  Identical to =: .  May be used outside of a colon definition.

 

: !>  <name>        ( n -- )

    STATE @

    IF      ' ?USER

        IF      COMPILE %U!>

        ELSE    COMPILE %!>

        THEN    X,

    ELSE    ' >IS !

    THEN    ; IMMEDIATE

 

+!>     Increment the value of the following word by n.

 

: +!>  <name>       ( n -- )

    ?NOUSER

    STAT @

    IF  COMPILE %+!>

    ELSE    ' >BODY +!

    THEN    ; IMMEDIATE

 

INCR>   Increment the following value by 1.

 

: INCR>  <name> (  -- )

    ?NOUSER

    STATE @

    IF COMPILE %INCR>

    ELSE    ' BODY INCR

    THEN    ; IMMEDIATE

 

DECR>   Decrement the following value by 1.

 

: DECR>  <name> ( -- )

    ?NOUSER

    STATE @

    IF  COMPILE %DECR>

    ELSE    ' BODY DECR

    THEN    ; IMMEDIATE

 

OFF>        Clear the following value to 0.

 

: OFF>  <name>  ( -- )

    ?NOUSER

    STATE @

    IF COMPILE %OFF>

    ELSE    ' BODY OFF

    THEN    ; IMMEDIATE

 

ON>     Set the following value to TRUE or -1.

 

: ON>  <name>       ( -- )

    ?NOUSER

    STATE @

    IF  COMPILE %ON>

    ELSE    ' BODY ON

    THEN    ; IMMEDIATE

 

: &>  <name>            ( t1 -- a1 )    \ Return the BODY address a1 of word t1, a VALUE of VARIABLE.

    ' ?NOUSER

    STATE @

    IF      COMPILE %&> X,

    ELSE    >IS

    THEN    ; IMMEDIATE

 

 

6.3.    SAVE AND RESTORE VARIABLES AND VALUES

 

 

The words defined in SAVEREST.SEQ allow you to quickly save the contents of a variable of value on the return stack, and set it to some other value temporarily with SAVE!>.  The previous contents may then be restored with RESTORE>.  These utility words are used extensively in F-PC 3.5, when file parameters or screen parameters have to be saved, new environment established for many operations, and then the original environment must be restored to continue on temporarily interrupted operations.

 

Here is an example of how to use SAVE!> and RESTORE>:

 

    : DEF   ( --- )

        32 SAVE!> MYSTUFF

         ... Do something with the new MYSTUFF ...

        RESTORE> MYSTUFF ;

 

%SAVE!> Save the BODY contents of the following definition on the return stack and set its BODY to n1.

 

CODE %SAVE!>    ( n1 --- )

    LODSW ES:           \ Get code field address of next word.

    MOV BX, AX          \ Save it to BX.

    ADD BX, # 3         \ Move it to the body field.

    SUB RP, # 2         \ Prepare to push on to the return stack.

    MOV AX, 0 [BX]      \ Extract contents in the body field.

    MOV 0 [RP], AX      \ Copy it to the return stack.

    POP 0 [BX]          \ Store n1 into the body field, changing its value.

    NEXT           

    END-CODE

 

%SAVE>  Save the BODY contents of the following definition on the return stack.

 

CODE %SAVE>     ( --- )

    LODSW ES:           \ See comments above.

    MOV BX, AX

    SUB RP, # 2

    MOV AX, 3 [BX]

    MOV 0 [RP], AX

    NEXT           

    END-CODE

 

%RESTORE>   Restore the BODY of the following definition from the return stack.

 

CODE %RESTORE>  ( --- )     \ Reverse of above.

    XCHG RP, SP

    POP DX

    XCHG RP, SP

    LODSW ES:

    MOV BX, AX

    MOV 3 [BX], DX

    NEXT           

    END-CODE

 

%USAVE!>    Save the USER data area for the following definition on the return stack and set it to n1.

 

CODE %USAVE!>   ( n1 --- )

    LODSW ES:

    MOV BX, AX

    MOV BX, 3 [BX]                  \ get body contents

    ADD BX, UP                      \ add to USER table

    SUB RP, # 2

    MOV AX, 0 [BX]                  \ save contents in AX

    MOV 0 [RP], AX                  \ move AX to return stack

    POP 0 [BX]                      \ pop data stack into USER table

    NEXT           

    END-CODE

 

%USAVE> Save the USER data area for the following definition on the return stack.

 

CODE %USAVE>    ( --- )

    LODSW ES:

    MOV BX, AX

    SUB RP, # 2

    MOV BX, 3 [BX]                  \ get body contents

    ADD BX, UP                      \ add to USER table

    MOV AX, 0 [BX]                  \ get USER table contents

    MOV 0 [RP], AX

    NEXT           

    END-CODE

 

%URESTORE   Restore the USER data area of the following definition from the return stack.

 

CODE %URESTORE> ( --- )

    XCHG RP, SP

    POP DX

    XCHG RP, SP

    LODSW ES:

    MOV BX, AX

    MOV BX, 3 [BX]                  \ get body contents

    ADD BX, UP                      \ add to USER table

    MOV 0 [BX], DX

    NEXT           

    END-CODE

 

SAVE!>  Leaves value in <name> on return stack and sets body of <name> to n1, the equivalent of "VARIABLE-NAME DUP @ >R !".

 

: ?COMP         ( --- )         \ Abort if we are not in compiling.

    STATE @ 0= ABORT" Use only while compiling" ;

 

: SAVE!>        ( n1 | <name> --- )

    ?COMP

    ' DUP @REL>ABS DUP

    [  [ASSEMBLER] DOUSER-VARIABLE META ] LITERAL = SWAP

    [  [ASSEMBLER] DOUSER-DEFER    META ] LITERAL = OR

    IF          COMPILE %USAVE!>

    ELSE    COMPILE %SAVE!>

    THEN

    X, ; IMMEDIATE

 

SAVE>   Saves value in <name> body on the return stack.  Equivalent to "VARIABLE-NAME @ >R".

 

: SAVE>         ( | <name> --- )

    ?COMP

    ' DUP @REL>ABS DUP

    [  [ASSEMBLER] DOUSER-VARIABLE META ] LITERAL = SWAP

    [  [ASSEMBLER] DOUSER-DEFER    META ] LITERAL = OR

    IF          COMPILE %USAVE>

    ELSE    COMPILE %SAVE>

    THEN    X, ; IMMEDIATE

 

RESORE> Restore body of <name> from the return stack.  Equivalent to "R> VARIABLE-NAME !".

 

: RESTORE>      ( | <name> --- )

    ?COMP

    ' DUP @REL>ABS DUP

    [  [ASSEMBLER] DOUSER-VARIABLE META ] LITERAL = SWAP

    [  [ASSEMBLER] DOUSER-DEFER    META ] LITERAL = OR

    IF          COMPILE %URESTORE>

    ELSE    COMPILE %RESTORE>

    THEN    X, ; IMMEDIATE

 

 

6.4.   HANDLES

 

 

HANDLES.SEQ contains the code to talk to a file using the DOS 2.00+ file handle service routines.  Handle is a better device than File Control Block to interface to the DOS file system.  The very long file name field permits complete pathnames to be specified.  File handles can be created, deleted, copies, and referenced through the DOS 21H service interrupts.  This section describes all the F-PC words related to file handles.

 

The DOS definition of a handle is "a 16 bit number returned by the operating system when a file is opened or created".  In F-PC, on the other hand, the DOS handle is called the 'Handle number', and the word HANDLE refers to a data array of 70 bytes.  The address of this array is given by executing the handle name.  The zero'th byte is a count. Bytes 1 to 65 are used to store path, file name, and extension as a long counted string.  The name string is terminated by a NUL character.   The count and name fields are structured like a Forth counted string, and many F-PC string words can be used to manipulate the name in a handle.  Bytes 66 and 67 are for the file attributes and bytes 68 and 69 hold the handle number.  After a file handle is established, the file is referenced in DOS by its handle number.  F-PC refers to a handle by the address of the first byte in the handle array.

 

70 CONSTANT B/HCB       \ Bytes in a handle

68 CONSTANT HNDLOFFSET  \ Offset to >HNDL field

VARIABLE RWERR          \ Flag for read/write error

 

>attrib Step to the attribute field of the handle.  Attribute is normally  zero (0) for Read/Write.  It may be set to one (1) for a write-only file, and to two (2) for read-only.

 

: >ATTRIB   ( h-addr -- attrib-addr )   66 + ;

 

>HANDLE Step to the handle storage field in the handle array.

6.5.   CONSOLE AND PRINTER WORDS

 

 

The words handling the console and printer input/output were in the HANDLES.SEQ in F-PC 2.25.  They are moved into SEQREAD.SEQ file in F-PC 3.5.  A major improvement in these words from 2.25 to 3.5 is that the basic I/O words can take characters from any segment in the memory, like CONSOLEL, PRINTL, AND (TYPEL).  The words working on the Code segments are derived from the more powerful long memory words.

 

DOS defines two special handles for the console display and the printer.  The DOS devices CON: and PRN: are derived from these handles.  Output characters and strings using these handles are not particularly fast.  DOS is not known for its speed anyway.  F-PC uses optimized output routines to raise its performance.  However, if you have to move F-PC to compatible machines or clones, the hardware may prevent you from using those optimized routines.  You can re-vector the output routines to this set of handle output I/O words, which should be usable under any MS-DOS systems Version 2.0 and later.

 

CREATE CONHNDL B/HCB  ALLOT \ Handle for console CON device

    1 CONHNDL >HNDLE !-T

CREATE PRNHNDL B/HCB  ALLOT \ Handle for printer PRN device

    4 PRNHNDL >HNDLE !-T

 

(CONSOLE)   Output a character to the console through the CON handle.  This word is used where DOS compatibility is the major concern.

 

: CONSOLEL  ( seg char -- )

    OUTPAUSE            \ Pause for task switching

    SWAP >R         \ Save segment to avoid deep ROLL

    SP@ 1 CONHNDL >R        \ Gather parameters for an

    EXHWRITE 2DROP      \   extended file write

    #OUT INCR ;         \ Characters in a line

 

: (CONSOLE)     ( char -- )     \ Use CONSOLEL to send character in Code segment.

    ?CS:  SWAP  CONSOLEL ;

 

(PRINT) Output a character to the printer.  Use the printer handle to send out the character.

    OUTPAUSE            \ Similar to (CONSOLE)

    SWAP >R

    SP@ 1 PRNHNDL >R        \   except using printer handle

    EXHWRITE 2DROP

    #OUT INCR ;

 

: (PRINT)   ( char -- )

    ?CS:  SWAP  PRINTL ;

 

(TYPE)  Output a string at addr to the console device through the CON handle.  String length is len.  The string may be sent to the printer if PRINTING is ON.

 

: PRNTYPEL      ( seg addr length -- )

    OUTPAUSE

    0MAX ROT

    PRNHNDL SWAP EXHWRITE

    #OUT +! ;

    OUTPAUSE

    0MAX ROT

6.6.   SEQUENTIAL FILES

 

 

Source file is SEQREAD.SEQ.  F-PC uses sequential files for source code and documentation.  The most important task in using text in a sequential file is to read the text in lines terminated by carriage-return and line-feed character-pairs.  The compiler will also have to be able to compile source code line by line.  The editor will have to read lines, write lines and modify lines.  These functions are provided in the file SEQREAD.SEQ.

 

To allow a file to load other files, F-PC uses a handle stack to nest the files for loading.  The handle stack has space for 7 handles.  Thus you can nest file loading to 7 levels deep.  This is more than enough for most applications.

 

In SEQREAD.SEQ, many variables are re-defined as values for speed and cleanness of code.  This is good place to make use of the very powerful VALUE technique.

                    \   files.

0 VALUE INLENGTH            \ Length of input text

6.8.   COMMAND TAIL

 

 

It is often convenient to pass information into F-PC directly on the DOS command line, after the command to execute F-PC.  F83 allows the user to specify a file name to be opened under F83 after F83 is loaded.  This capability is retained in F-PC.  Moreover, F-PC allows you to attach a whole line of Forth commands after the file name.  These Forth commands will be executed after the file is opened.  This command tail gives us the capability to build rather sophisticated batch files to do a large amount of work under DOS.

 

In F-PC 3.5, a configuration file is used to load system configuration information.  The .CFG file is loaded before the command tail is processed.  HDEFAULT is modified accordingly.  The name of the .CFG file is store in CFGHNDL.
